Follow-ups earlier reviews assigned to T0.3 (as passed on by the orchestrator; they are
requirements or checks, not designs):
1. **Privacy of the DB path.**
   - `.gitignore` anchors `/data/` and `/*.db` to the repo root.
   - `just dev` and `just migrate` run from `services/api`. A relative DB URL such as
     `data/typist.db` would therefore create `services/api/data/typist.db`, which is NOT ignored.
   - The DB path must resolve to the root `data/`, unless the owner approves another ignore rule.
2. **Migration entry point.** `just migrate` calls `uv run alembic upgrade head` directly. Design
   doc 14.1 defines `typist db migrate`. One entry point has to be chosen, along with whether the
   CLI is in T0.3's scope at all.
3. **D22 obligations.**
   - Add bandit and pip-audit as dev dependencies, pinned in `services/api/uv.lock`.
   - Add a local bandit pre-commit hook that runs through `uv run` from `services/api`, the same
     pattern as the ruff hook.
   - Replace the body of `security-py`.
4. **`just dev` signal handling.** This was only tested with stubs for the API. With the real
   `uv run uvicorn --reload` (which runs a reloader parent and a server child), Ctrl-C must stop
   everything and leave nothing on port 8000.
5. **Sandbox (from T0.2 experience).** The sandbox blocks:
   - network access for uv and pnpm (TLS through the proxy);
   - package-manager store and cache locks;
   - local port binding;
   - writes under `.claude/`.

   The owner runs those steps manually. This is a constraint (see section 6), not a design.

## 2. Why it matters

What T0.3 enables later:
- Every backend task builds on this scaffold:
  - T1.1 (first tables and the first real migration);
  - T1.6 (idempotent events endpoint);
  - T1.7 (`attribution.py`, "the most correctness-sensitive part");
  - T1.9 (`typist stats recompute`);
  - T2.x (assignment, generators, worker);
  - T3.x (MLXRuntime);
  - T4.1 (analysis).
- It defines where the SQLite file lives. From T1.1 on, participant keystroke data is written there.
  Section 4.2 promises that data is stored in "one SQLite file on your laptop", and CLAUDE.md says
  "Never commit anything under `data/`".
- It makes `just check` (D21) check real Python for the first time: ruff check,
  `ruff format --check`, pyright and pytest.
- It turns `just security` (D22) from a placeholder into a real Python scan (`security-py`).
- T0.4 (CI) needs a Python project that installs from a committed `uv.lock` on Linux without
  mlx-lm. `main`'s ruleset requires a status check named exactly `api`.
- M0 done-when ("just dev runs web, API and worker") needs the API line of `just dev` to work.
  The line is already written:
  `uv run uvicorn --factory typist.main:create_app --host 127.0.0.1 --port 8000 --reload`.
- The web dev server already proxies `/api` to `http://127.0.0.1:8000` (`apps/web/vite.config.ts`),
  and the web code already builds `/api/v1/health` (`apiPath("/health")`). T0.3 is the first time
  that proxy has a target.
- `/health` is the endpoint T2.5 extends: "heartbeat visible on /health".
- T0.5 (model smoke test) and T3.2 (MLXRuntime) depend on how the mlx optional group is set up in
  `pyproject.toml`.
- T1.2, T1.3 and T1.7 depend on `services/api/tests/fixtures/` existing at the path CLAUDE.md names.
  The golden fixture is shared by TS and Python.

What breaks if it is wrong:
- **DB path resolves inside `services/api/`.** Participant data can then be committed and pushed
  to GitHub (follow-up 1). That is a privacy failure, not a hygiene issue.
- **The justfile contracts are not met** (`pyproject.toml` with ruff, pyright and pytest in the
  dev group; `typist.main:create_app`; `alembic.ini` in `services/api`). Then `just lint`,
  `format-check`, `types`, `test`, `check`, `dev` and `migrate` fail for every later task.
- **mlx-lm becomes a mandatory dependency, or its marker is wrong.** Then `uv sync` fails on
  Linux (cloud sessions, T0.4 CI).
- **The API process imports the model runtime.** Section 6.1 forbids this: Services "Must not ...
  Import the model runtime". The API would also stop starting on Linux.
- **pyright strictness for `src/` is weaker than section 17.1 requires.** Tightening it later
  touches every file, and the attribution code (T1.7) gets written without those checks.
- **SQLite pragmas are missing or set only once instead of on every connection.** Foreign keys go
  unenforced (verify: `foreign_keys` is per connection), and the concurrent API and worker access
  that WAL is chosen for (5.2) is not in place when T2.5 arrives.
- **`just dev` leaves uvicorn running after Ctrl-C.** The next `just dev` then fails to bind port
  8000, and the Vite proxy may keep talking to a stale server.

`security` (D22) classifies each sub-recipe's result like this, verbatim from the recipe comment:
"Every skip message contains "skipping"; that is how a skip is told apart from a pass." It then
applies `case "$out" in *skipping*)`:
- exit 0 with "skipping" in the output means skipped;
- exit 0 without it means passed;
- any non-zero exit means FAILED.

The D22 plan (risk 6) states: "T0.3 must keep it when it replaces `security-py`." Registry probes
in the existing recipes look like this:
`curl --silent --head --output /dev/null --connect-timeout 5 --max-time 10 <url>`. There is no
`--fail`, so any HTTP response counts as reachable.

## 7. Edge cases

1. **DB path resolves relative to the working directory (follow-up 1).** SQLAlchemy resolves a
   relative SQLite URL such as `sqlite:///data/typist.db` against the process's working directory
   (verify).
   - Every entry point runs from `services/api`: `just dev`, `just migrate`, `uv run pytest` in
     `just test`, and the pre-commit hooks. The file then lands at
     `services/api/data/typist.db`.
   - `git check-ignore` does not match that path: `/data/` and `/*.db` are anchored to the root.
   - Its `-wal`/`-shm` siblings ARE ignored (unanchored `*.db-wal`, `*.db-shm`). So only the main
     DB file shows as untracked, which is easy to miss.
   - `.semgrepignore`'s unanchored `data/` would hide the same directory from semgrep, so the
     security scan would not notice it either.
   - The same applies to `alembic.ini`'s `sqlalchemy.url`, which is resolved from wherever
     `alembic` runs.
2. **`data/` does not exist on a fresh clone.** SQLite cannot create a file in a missing directory.
   Example: the first `just dev` followed by `curl /api/v1/health` with a DB check fails with
   "unable to open database file" (verify the message) unless something creates `data/` first.
3. **Health check creates the database.** Opening a SQLite connection creates the file if it is
   missing (verify). A DB check in `/health` would create an empty `data/typist.db` on the first
   request, before any migration has run. Setting `journal_mode=WAL` on it also creates the
   `-wal`/`-shm` files.
4. **Pragmas are per connection.**
   - `foreign_keys` and `synchronous` reset on every new connection. `journal_mode=WAL` persists
     in the database file (verify both).
   - A connection pool opens several connections.
   - Alembic's `env.py` builds its own engine, separate from the app's engine, so it does not get
     the app's pragmas unless it sets them too.
5. **WAL and in-memory databases.** `journal_mode=WAL` does not apply to `:memory:` databases
   (the pragma returns `memory`, verify). Section 17.2 specifies API tests "on a temporary SQLite
   file". A test using `sqlite://` (in-memory) would not exercise WAL, and each in-memory
   connection sees its own empty DB unless a shared pool is used (verify).
6. **SQLite and threads.** FastAPI runs sync path functions in a thread pool. The default
   `sqlite3` module refuses to use a connection from a different thread unless
   `check_same_thread=False` (verify). Example: a sync `/health` that uses a module-level
   connection fails intermittently with `ProgrammingError: SQLite objects created in a thread can
   only be used in that same thread`.
7. **Empty Alembic history.**
   - Before T1.1 there are no revisions, and `just migrate` runs `uv run alembic upgrade head`
     against an empty `versions/` (verify alembic's behaviour: expected to succeed with nothing to
     do, possibly creating the `alembic_version` table).
   - `alembic check` or autogenerate with no models compares against an empty `SQLModel.metadata`.
   - T1.1's acceptance "Migration up and down both work" needs `downgrade` too.
   - SQLite supports only limited `ALTER TABLE`, and Alembic handles that with "batch" migrations
     (verify). Whether that is configured in T0.3's `env.py` or in T1.1 is not stated.
8. **Alembic-generated files and the gate.** `alembic init` writes an `env.py` and a
   `script.py.mako` template. Every future revision file is rendered from that template. The
   generated `env.py` and revisions may fail `ruff check`, `ruff format --check` or pyright strict
   (untyped functions, `context` attribute access, unused imports) (verify).
   - If `alembic/` is inside pyright's scope, `just types` fails.
   - If ruff reformats revision files, the pre-commit hook rewrites them.
   - Section 17.1's strict rule names only `src/`, and `alembic/` sits beside `src/` (section 7).
9. **`typist.main:create_app` is not importable.** With a `src/` layout, `typist` is importable
   only if the project is installed into `.venv` (a uv "package" project with a build backend) or
   if `src` is on the path (verify uv defaults for projects with and without `[build-system]`).
   Example: `uv run uvicorn --factory typist.main:create_app` fails with
   `ModuleNotFoundError: No module named 'typist'`.
10. **Name clash with the typist package.** Section 7 has `src/typist/services/` (business logic)
    and a top-level repo directory `services/`. Section 7 also has `src/typist/api/routers/`
    inside a project that lives at `services/api/`. Nothing actually clashes on import, since only
    `src` is on the path, but the paths are easy to confuse. Example: `services/api/src/typist/api/`
    vs `services/api/`.
11. **Linux CI and cloud without mlx.**
    - A plain `uv sync` on Linux must not try to install mlx-lm.
    - The mlx group mechanism is not settled (CLAUDE.md says "optional dependency group"). uv has
      two different mechanisms: `[project.optional-dependencies]` extras, and PEP 735
      `[dependency-groups]`, of which `dev` is synced by default (verify).
    - If mlx-lm were put in the `dev` group without the marker, `uv sync` would fail on Linux.
    - `uv lock` still resolves mlx-lm for darwin-arm64 on any machine, which needs network access
      to PyPI metadata for those wheels.
    - `pip-audit` of the installed environment then sees different packages on Mac and Linux.
12. **`@pytest.mark.mlx` without registration.** An unregistered marker gives a
    `PytestUnknownMarkWarning`. With `--strict-markers` it is an error (verify). The skip-off-Mac
    behaviour needs a `conftest.py` hook or a `skipif`. No model test exists before T0.5.
13. **pytest with zero tests.** `pytest` exits with code 5 when no tests are collected (verify).
    Under `set -euo pipefail`, `just test`, and therefore `just check`, would fail. So T0.3 needs at
    least one collected test.
14. **In-process vs real HTTP.**
    - FastAPI's `TestClient` (which needs httpx) or `httpx.ASGITransport` tests the app without a
      port. The sandbox may allow these where it blocks port binding.
    - The literal acceptance, `curl`, needs a real bound port on 127.0.0.1:8000, which the sandbox
      blocks (follow-up 5).
    - The two prove different things: routing and prefix vs. the uvicorn command in `just dev`,
      including `--factory`.
15. **`uv run` changes files during `just check`.**
    - `uv run` syncs the environment and, by default, re-locks if `pyproject.toml` and `uv.lock`
      disagree (verify for uv 0.12). Example: someone edits `pyproject.toml` without re-locking,
      and then `just check` rewrites `uv.lock`. D21 says `check` "Never rewrites source files".
    - With no network, the implicit sync fails, and `just check` fails for an environment reason.
    - The flags that prevent this are `--locked` and `--frozen` (verify). No current recipe or
      hook uses them.
16. **pyright distribution.**
    - The `pyright` package on PyPI is a wrapper. On first run it downloads the pyright npm package
      and needs Node, or downloads Node itself (verify for the current wrapper).
    - Example: under the sandbox, or on a fresh CI runner, the first `uv run pyright` fails with a
      network error even though `uv sync` succeeded.
    - The downloaded pyright version may not be pinned by `uv.lock`: the wrapper may fetch the
      latest npm version unless it is configured to pin (verify). That conflicts with "lockfiles
      are the source of truth".
17. **pyright scope and SQLModel/FastAPI typing.**
    - Strict mode reports `reportUnknownMemberType`, `reportUnknownVariableType` and similar for
      partially typed libraries (verify for the installed SQLModel, Alembic and uvicorn).
    - SQLModel table classes (`table=True`) and `Field(...)` defaults are known to produce strict
      diagnostics in some versions (verify). T1.1 will hit this first, but the pyright
      configuration is T0.3's.
    - Tests using `TestClient` responses (`response.json()` returns `Any`) trip strict mode if
      `tests/` is strict.
18. **ruff config location and discovery.**
    - The ruff hook `cd`s into `services/api`, and ruff finds `services/api/pyproject.toml`
      (`[tool.ruff]`).
    - `just lint` runs `ruff check .` from `services/api`, so `alembic/` and `tests/` are linted
      unless excluded.
    - The web side uses line width 100 (T0.2 answer 9). Python style is not settled.
    - `--force-exclude` in the hook makes ruff honour `exclude` settings even for explicitly
      passed files.
19. **`just dev` with the real uvicorn `--reload` (follow-up 4).**
    - Process tree: the recipe's bash → subshell `exec uv run uvicorn ...` → uv, which spawns
      Python rather than exec'ing it (verify) → the uvicorn reloader (parent) → the server process
      (child, spawned via multiprocessing and watching for file changes; verify).
    - `kill $pids` sends SIGTERM only to the uv PID. Whether uv forwards SIGTERM and SIGINT to its
      child (verify for uv 0.12), and whether the reloader then stops its child, decides if port
      8000 is freed.
    - In a non-interactive bash, background jobs start with SIGINT ignored. An ignored disposition
      survives `exec`. CPython does not install its KeyboardInterrupt handler when SIGINT is
      ignored at start-up (verify).
    - Example: after Ctrl-C, `lsof -nP -iTCP:8000 -sTCP:LISTEN` still shows a `python` process.
      The next `just dev` then fails with `[Errno 48] Address already in use`.
    - `--reload` watches files under the working directory, `services/api` (verify which patterns
      uvicorn watches with and without `watchfiles`). If the DB were under `services/api/data/`
      and the patterns included it, DB writes could trigger reloads.
20. **FastAPI docs pages load third-party assets.**
    - FastAPI's default `/docs` (Swagger UI) and `/redoc` pages load their JavaScript and CSS from
      a public CDN, and ReDoc also loads Google Fonts (verify for the installed FastAPI version).
    - Opening them makes the browser contact third parties. D19 and CLAUDE.md say "Everything
      stays local". The T0.2 brief treated CDN assets as out of bounds for the web app.
    - The default docs paths (`/docs`, `/redoc`, `/openapi.json`) are outside `/api`, so the Vite
      proxy does not forward them. They work only directly on port 8000.
21. **FastAPI extras.** `fastapi[standard]` pulls in `fastapi-cli` and, in recent versions, a
    FastAPI Cloud CLI package (verify). That is a cloud-deploy tool in the dependency tree, in
    tension with D19. Plain `fastapi` plus `uvicorn` avoids it (verify). The `dev` recipe calls
    `uvicorn` directly, not `fastapi dev`.
22. **What `/health` reports before the worker exists.**
    - Section 14 lists "Liveness, DB check, worker heartbeat age". There is no worker until T2.5,
      and no table or column stores a heartbeat (section 8.1).
    - Example: a response field `worker_heartbeat_age_s` would have no source. If it were
      required, `/health` would have to report something other than "ok" until M2.
    - Once T2.5 adds it, the worker is expected to be missing on Linux (`just dev` and
      `just worker` are macOS-only). Whether a missing heartbeat means "not ok" is not settled.
23. **Status code vs body.** "Returns ok" could be satisfied by HTTP 200 with any body, or by a
    specific body. `curl` without `-f` prints the body even on 5xx, and exits 0 either way.
    Example: a `503` with `{"status":"degraded"}` still "returns" something to curl.
24. **Trailing slash and prefix.** FastAPI redirects between `/health` and `/health/` with a 307,
    depending on how the route is declared (verify). Example: `curl http://127.0.0.1:8000/api/v1/health/`
    returns a 307 and an empty body without `-L`. The web client builds `/api/v1/health` with no
    trailing slash.
25. **CORS vs proxy.** Section 6.2 says CORS for the Vite dev origin. T0.2 answer 16 chose a proxy
    "instead of CORS". Through the proxy, the browser request is same-origin (`127.0.0.1:5173`), so
    no CORS headers are needed. A browser calling `127.0.0.1:8000` directly would be cross-origin.
    With no CORS middleware, such calls fail. With CORS middleware, which origins to allow is not
    settled.

    - uv searches parent directories for a workspace root (`pyproject.toml` with

    - The main checkout on `main` has no `services/api` yet. If its working tree ever gains a

29. **pip-audit specifics.**

    FastAPI default `/openapi.json` sits at the root, not under `/api/v1`, so it is not proxied by
    Vite. Where the schema is served decides the future `gen-types` command.
35. **`--reload` and the `typist` package location.** uvicorn `--reload` with `--factory` re-imports
    `typist.main` in the child. If the package is installed non-editable (a copy in
    site-packages), edits under `src/` are not picked up (verify uv's default: editable for the
    project).
36. **Alembic run from the repo root.** `alembic.ini`'s `script_location` is relative to the
    `alembic.ini` directory or to the CWD, depending on the `%(here)s` usage (verify). Running
    `alembic -c services/api/alembic.ini upgrade head` from the root could then fail to find
    `alembic/`. The recipes always `cd services/api`, but the future CLI command
    (`typist db migrate`) may run from anywhere.
37. **UTC timestamps (section 8).** SQLite has no timezone type. Nothing is stored in T0.3, but
    `db.py` choices (if made here) affect T1.1.

## 8. Risks

1. **Participant data in git (follow-up 1).** A working-directory-relative DB path puts
   `typist.db` in `services/api/data/`. There, neither `.gitignore` (anchored) nor the reviewer's
   `just security` (semgrep ignores `data/` at any depth) flags it. It would first hold real data
   from T1.x on.
2. **Sandbox stalls.** Nearly every T0.3 step needs uv's network access or cache (lock, sync, first
   `uv run`, pyright's first run, pip-audit), or port binding (curl acceptance, `just dev`
   check). The builder cannot finish without owner-run resume points, and the sandbox must not be
   bypassed.
3. **`just check` red on the scaffold.** Generated Alembic files, pyright strict on
   SQLModel/FastAPI types, or zero collected tests (pytest exit 5) fail D21's gate, even when
   `/health` works.
4. **Linux breakage surfaces only in T0.4.** A wrongly marked mlx group, a pyright wrapper needing
   Node or network, or `uv run` re-locking would all show up only when CI runs on Linux, blocking
   "CI green on main".
5. **`/health` shape locks in too early or too late.** A body of exactly `ok` may not fit T2.5's
   "heartbeat visible on /health" and 14's "DB check". A richer shape now may contradict the
   literal acceptance. The web side (`apiPath`) and future `gen-types` types depend on it.
6. **Unpinned tool versions.** Examples: pyright's npm download, `uv` itself, bandit plugins and
   pip-audit's vulnerability service. These make `just check` and `just security` results change
   without a code change. This is section 18's "Library changes mid-project" risk.
7. **Stale uvicorn after Ctrl-C (follow-up 4).** It holds port 8000 and makes the next `just dev`
   fail. The Vite proxy would also keep hitting old code.
8. **D19 leaks through defaults.** Examples: FastAPI docs pages loading CDN assets and Google
   Fonts, `fastapi[standard]` pulling a cloud CLI, pip-audit/pyright network calls beyond what D22
   allows.
9. **Scope creep.** Typer CLI, pydantic-settings, hypothesis, CORS, static serving, gen-types, the
   mlx group, the pytest mlx marker and the section-7 skeleton are all mentioned by the design doc
   near T0.3, but none is in T0.3's title. Adding them all makes T0.3 several tasks ("One task per
   PR"). Leaving them out means some have no section-16 owner.
10. **The `security` keyword contract is broken by T0.3's new `security-py` body.** A pass
    reported as skipped, or a partial skip hiding a real pass or failure (edge case 30).
11. **Pre-commit bandit hook blocks commits of tests.** This happens if B101 is not handled
    (edge case 28), and it happens on the builder's own commits during T0.3.
