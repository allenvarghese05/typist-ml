## 2. Design

- **Draft first, JSON second** (process note, follow-up 3, answer 17).
  - Appendix A of this plan is the proposed derivation. The builder copies it verbatim into
    `T1.2-derivation.md` and adds a sign-off block.
  - Once the owner has signed, the JSON is a mechanical transcription of the **signed** document,
    using the exact rules in step 3.
  - If the owner changed any value, the signed document wins over Appendix A.
- **Numbers chosen to be exact.** All times are whole numbers or multiples of 0.25 (answer 13). The
  session totals are also exact binary fractions, so exact equality holds no matter how T1.9
  orders its operations:
  - correct first attempts are 55, a multiple of 5, so the word count 55/5 = 11 is exact;
  - elapsed time is 30000 ms = 0.5 min;
  - WPM is exactly 22;
  - accuracy is 55/64 = 0.859375.

  This needs 64 first attempts with 9 first-attempt errors, so the target is 65 characters
  (F1, accepted).
  - Rejected: a target of 60 characters or fewer. Its accuracy would be a ratio like 42/51 that
    has no short exact decimal form.
- **Each case is discriminating.** A wrong rule changes at least one expected value. For example:
  - the 2000 ms boundary (o) is the only IKI sample of `ld`;
  - the flag-only blur pause (m) is under 2000 ms;
  - the gap-only pause (n) has no flag;
  - the even-count median (`ll`, `th`) and the odd-count median that needs sorting (`he`, samples
    in seq order 140, 95, 110, median 110) are both present;
  - in case (d), the erased characters cross a space and change exactly one pair, `of`.

  WPM includes every pause (D26), so an implementation that still removes pauses gets a WPM other
  than 22.
- **The structural test computes no attribution** (answer 18). It checks:
  - the items in the owner's list;
  - the release-to-press arithmetic (amendment F12);
  - two direct encodings of answers 12c, 12d and 13a: quarter-ms values, and a median that is null
    if and only if `iki_n` is 0.
- **The test file lives in `tests/integration/`**, so it can reuse T1.1's `migrated_engine`
  fixture. One file holds every check.

  ```markdown
  # D25: Backspace rows record the post-move cursor position

  - Date: 2026-10-06
  - Status: accepted
  - Task: T1.2

  ## Context

  Section 8.1 defines `keystroke_events.target_index` as "Cursor position when the key was
  pressed". For a printable key that is the position it is compared with. A Backspace moves the
  cursor back one position, so "when the key was pressed" could mean the position before the move
  or the position it erases. The golden fixture (T1.2) must pin one reading, because TextCursor
  (T1.3) and every stored Backspace row must agree. The owner decided this on 2026-10-06 (T1.2
  owner answer 8a, follow-up 1). Section 17.3: "Any change to a decision gets a short ADR in
  docs/decisions/."

  ## Decision

  | ID | Decision | Choice | Why | Revisit if |
  |---|---|---|---|---|
  | D25 | target_index on Backspace rows | For Backspace rows, target_index records the post-move cursor position, not the pre-press position 8.1's general definition implies. | A Backspace row's meaningful position is what it erased/landed on, not where the cursor was a moment before — the general rule was written with forward-typing keystrokes in mind and doesn't cleanly apply to a key that moves the cursor backward. | A later key moves the cursor in another way (for example word delete), which is out of scope in v1 (D13) |

  ## Consequences

  - A Backspace pressed with the cursor at index i > 0 is stored with `target_index = i - 1`, the
    position it erased. A Backspace at index 0 erases nothing, is still stored as a row with
    `outcome = "backspace"` and `target_index = 0`, and does not count as "a backspace happened
    between a and b" for any pair (T1.2 owner answer 8b).
  - Backspace rows keep `expected_char` and `first_attempt` NULL (T1.1 owner answer 5).
  - TextCursor (T1.3) reports this position for Backspace; the golden fixture
    (`services/api/tests/fixtures/golden_session.json`) pins it on every Backspace row.
  - Attribution (T1.7) uses Backspace rows only through their `seq` (the "between a and b" test),
    so this choice changes no bigram statistic.
  - Section 8.1 is not edited; this ADR records the narrower meaning for Backspace rows.
  ```

### Step R2: ADR D26

- File: create `docs/decisions/D26-wpm-elapsed-time-and-idle-limit.md` (complete text):
  ```markdown
  # D26: Session WPM uses elapsed time with pauses included; idle limit on a block

  - Date: 2026-10-13
  - Status: accepted
  - Task: T1.2 (recorded); T1.5 and T1.9 (built)

  ## Context

  Section 12.3 says: "Session WPM is correct first-attempt characters divided by 5, divided by
  minutes of active typing (pauses removed)." Section 12.2 defines a pause as "IKI over 2000 ms,
  or first key after a blur", excluded from IKI statistics and still counted for errors. While
  drafting the golden fixture (T1.2), the owner reviewed the WPM rule and decided on 2026-10-13
  (T1.2 brief, "Amendments after plan approval") that the WPM timer must not stop for pauses, and
  added a limit on idle time within a block. Section 17.3: "Any change to a decision gets a short
  ADR in docs/decisions/."

  ## Decision

  | ID | Decision | Choice | Why | Revisit if |
  |---|---|---|---|---|
  | D26 | Session WPM time base, and idle limit | WPM = correct first-attempt characters / 5 / elapsed minutes. Elapsed time runs continuously from the first keystroke's press (`t_down_ms` of the block's first row) to the press of the final character; for a block that never reaches the end, to the last row's press. Pauses and time away from the window (blur) are included, not removed. This deviates from section 12.3's "minutes of active typing (pauses removed)". Pair speed is unchanged: an IKI sample is still skipped when `b.after_pause` is true or the press-to-press gap is over 2000 ms (D24, D23(a)). Idle rule: after 5 s with no keypress the block shows a warning while the timer keeps running; after 10 s with no keypress the block is abandoned and must be restarted. Blur counts as idle. Keystroke rows of an abandoned block are kept (append-only) and the block is marked abandoned. | Owner: WPM is the score shown to the user, so it reflects real elapsed time (the way Monkeytype times a test, used as a behaviour reference only). Pair speed (IKI) is what the system uses to learn the typist's patterns and train them, so it is kept separate and still excludes pauses. The idle limit keeps a long pause from silently distorting the score or the block. | Pilot data shows the idle limit abandons too many blocks, or the WPM time base makes baseline and retest sessions incomparable |

  ## Consequences

  - The golden fixture (T1.2) expects WPM on elapsed time: 55 correct first attempts / 5 / 0.5 min
    = 22, with no pause removed, while its IKI samples still skip the pauses.
  - T1.9 computes `sessions.wpm` this way. Attribution (T1.7) and `bigram_stats` are unchanged.
  - T1.5 builds the idle warning (5 s), the abandon-and-restart (10 s) and blur-as-idle. It must
    decide how an abandoned block is marked and how its restart is stored: `session_blocks` (T1.1)
    has no status column, and `UNIQUE (session_id, block_index)` stops a second row with the same
    index. That needs the owner's decision and possibly a migration in T1.5.
  - No press-to-press gap inside a completed block can exceed 10 s, so a pause adds at most about
    10 s to a block's elapsed time.
  - `docs/analysis-plan.md` (draft until T3.6): the exploratory measure "Overall WPM and accuracy"
    must cite this definition when the plan is pre-registered in T3.6, and T3.6 must say whether
    rows of an idle-abandoned block are excluded from outcome analysis (Exclusions rule 1 covers
    abandoned sessions only). Exclusion rule 2 ("Pauses, IKI only") already agrees with this ADR.
  - Free-practice modes (timed or word-count tests) are not built now. If added later they are a
    separate feature whose data stays out of the experiment's analysis.
  - Section 12.3 is not edited; this ADR records the deviation.
  ```

### A.0 Conventions

- `␣` is one space character (U+0020). In JSON it is written `" "`. Its `key` is `" "` and its
  `code` is `Space`.
- Backspace rows: `key` = `code` = `Backspace`, `expected_char` and `first_attempt` are `null`, and
  `target_index` is the post-move cursor position (D25). At index 0 the index stays 0 (answer 8b).
- `iki_ms(i) = t_down(i) − t_down(i−1)`, `null` at seq 0. `dwell_ms = t_up − t_down`, `null` when
  `t_up` is missing. `release_to_press(i) = t_down(i) − t_up(i−1)`, which is `null` at seq 0 and
  when `t_up(i−1)` is missing (A.8).
- Pair rule (12.3 with D24 and D23(a)):
  - For each j ≥ 1 where `target[j−1]` and `target[j]` are both letters:
    - a = first attempt at j−1, b = first attempt at j;
    - skip if a or b is missing;
    - skip if a is not correct;
    - skip if a Backspace row lies strictly between a.seq and b.seq;
  - otherwise the pair is an attempt. It is an error if b is an error. Otherwise it gives an IKI
    sample `b.t_down − a.t_down` when `b.seq == a.seq + 1`, `b.after_pause` is false and the gap
    is ≤ 2000.
- WPM (D26): correct first attempts / 5 / elapsed minutes. Elapsed time runs from the first row's
  `t_down` to the final character's `t_down` (here the last row), with pauses included.
- `handler_ms` is 0.5 for letters and spaces and 0.75 for Backspace. `dispatch_lag_ms` is 1.25 on
  every row. These are placeholders: no expected value depends on them (F14).
- Times are ms from block start. In the tables, `T`/`F` mean true/false.
