## 2. Design

- **Draft first, JSON second** (process note, follow-up 3, answer 17).
  - Appendix A of this plan is the proposed derivation. The builder copies it verbatim into
    `T1.2-derivation.md` and adds a sign-off block.
  - Once the owner has signed, the JSON is a mechanical transcription of the **signed** document,
    using the exact rules in step 3.
  - If the owner changed any value, the signed document wins over Appendix A.
- **Numbers chosen to be exact.** All times are whole numbers or multiples of 0.25 (answer 13). The
  session totals were also built to be exact binary fractions, so exact equality holds no matter
  how T1.9 orders its operations:
  - correct first attempts are 55, a multiple of 5, so the word count 55/5 = 11 is exact;
  - active time is 20625 ms, which is 0.34375 min = 11/32;
  - WPM is exactly 32;
  - accuracy is 55/64 = 0.859375.

  This forced 64 first attempts with 9 first-attempt errors, so the target is 65 characters
  (flag F1).
  - Rejected: a 60-character target. Its accuracy would be a ratio like 42/51 that has no short
    exact decimal form, and its WPM would depend on the order of operations.
- **Each case is discriminating.** A wrong rule changes at least one expected value. For example:
  - the 2000 ms boundary (o) is the only IKI sample of `ld`;
  - the flag-only blur pause (m) is under 2000 ms;
  - the gap-only pause (n) has no flag;
  - the even-count median (`ll`, `th`) and the odd-count median that needs sorting (`he`, samples
    in seq order 140, 95, 110, median 110) are both present;
  - in case (d), the erased characters cross a space and change exactly one pair, `of`.
- **The structural test computes no attribution** (answer 18). It checks only the items in the
  owner's list, plus two direct encodings of answers 12c, 12d and 13a (quarter-ms values; median
  null if and only if `iki_n` is 0).
  - Rejected: re-deriving `release_to_press_ms` in the test. It is not on the owner's list (flag
    F12).
- **The test file lives in `tests/integration/`**, so it can reuse T1.1's `migrated_engine`
  fixture. One file holds every check.

### Step 1: ADR D25

- File: create `docs/decisions/D25-backspace-target-index.md` (complete text):
  ```markdown
  # D25: Backspace rows record the post-move cursor position

  - Date: 2026-10-06
  - Status: accepted
  - Task: T1.2

  ## Context

  Section 8.1 defines `keystroke_events.target_index` as "Cursor position when the key was
  pressed". For a printable key that is the position it is compared with. A Backspace moves the
  cursor back one position, so "when the key was pressed" could mean the position before the move
  or the position it erases. The golden fixture (T1.2) must pin one reading, because TextCursor
  (T1.3) and every stored Backspace row must agree. The owner decided this on 2026-10-06 (T1.2
  owner answer 8a, follow-up 1). Section 17.3: "Any change to a decision gets a short ADR in
  docs/decisions/."

  ## Decision

  | ID | Decision | Choice | Why | Revisit if |
  |---|---|---|---|---|
  | D25 | target_index on Backspace rows | For Backspace rows, target_index records the post-move cursor position, not the pre-press position 8.1's general definition implies. | A Backspace row's meaningful position is what it erased/landed on, not where the cursor was a moment before — the general rule was written with forward-typing keystrokes in mind and doesn't cleanly apply to a key that moves the cursor backward. | A later key moves the cursor in another way (for example word delete), which is out of scope in v1 (D13) |

  ## Consequences

  - A Backspace pressed with the cursor at index i > 0 is stored with `target_index = i - 1`, the
    position it erased. A Backspace at index 0 erases nothing, is still stored as a row with
    `outcome = "backspace"` and `target_index = 0`, and does not count as "a backspace happened
    between a and b" for any pair (T1.2 owner answer 8b).
  - Backspace rows keep `expected_char` and `first_attempt` NULL (T1.1 owner answer 5).
  - TextCursor (T1.3) reports this position for Backspace; the golden fixture
    (`services/api/tests/fixtures/golden_session.json`) pins it on every Backspace row.
  - Attribution (T1.7) uses Backspace rows only through their `seq` (the "between a and b" test),
    so this choice changes no bigram statistic.
  - Section 8.1 is not edited; this ADR records the narrower meaning for Backspace rows.
  ```

### A.0 Conventions

- `␣` is one space character (U+0020). In JSON it is written `" "`. Its `key` is `" "` and its
  `code` is `Space`.
- Backspace rows: `key` = `code` = `Backspace`, `expected_char` and `first_attempt` are `null`, and
  `target_index` is the post-move cursor position (D25). At index 0 the index stays 0 (answer 8b).
- `iki_ms(i) = t_down(i) − t_down(i−1)`, `null` at seq 0. `dwell_ms = t_up − t_down`, `null` when
  `t_up` is missing. `release_to_press(i) = t_down(i) − t_up(i−1)`, which is `null` at seq 0 and
  when `t_up(i−1)` is missing (A.8).
- Pair rule (12.3 with D24 and D23(a)):
  - For each j ≥ 1 where `target[j−1]` and `target[j]` are both letters:
    - a = first attempt at j−1, b = first attempt at j;
    - skip if a or b is missing;
    - skip if a is not correct;
    - skip if a Backspace row lies strictly between a.seq and b.seq;
  - otherwise the pair is an attempt. It is an error if b is an error. Otherwise it gives an IKI
    sample `b.t_down − a.t_down` when `b.seq == a.seq + 1`, `b.after_pause` is false and the gap
    is ≤ 2000.
- `handler_ms` is 0.5 for letters and spaces and 0.75 for Backspace. `dispatch_lag_ms` is 1.25 on
  every row. These are placeholders: no expected value depends on them (F14).
- Times are ms from block start. In the tables, `T`/`F` mean true/false.

### A.9 Flagged rule points (each needs the owner's accept or change)

- **F1 Target length.** The target is 65 characters, over the "roughly 40–60" of answer 6. Exact
  accuracy and WPM need 64 first attempts with 9 errors: 55/64 = 0.859375 and 11 words / 0.34375
  min = 32. A target of 60 characters or fewer gives a ratio such as 42/51, which has no short
  exact decimal, and a WPM whose last bit depends on the order of operations. Alternative: a
  shorter target, with the 17-digit `repr` of the ratio produced by an arithmetic-only script.
- **F2 What a WPM pause interval is.** The interval is the press-to-press gap `t_down(i) −
  t_down(i−1)` between consecutive rows of any kind, Backspace rows included. A row's gap is
  removed whole when that row has `after_pause` or the gap is over 2000 ms. The rejected
  alternative measures from the previous key's release.
- **F3 "last t_up".** This could mean the last row's `t_up` or the largest `t_up` in the block. The
  fixture is built so that both are 31925. The rule stays open for blocks where they differ.
- **F4 WPM numerator.** Under follow-up 2's literal rule, four positions count as correct first
  attempts although they were later erased and retyped: 29 (seq 40), 31 (seq 44), 32 (seq 45) and
  33 (seq 46). Positions 5, 6, 11, 14, 19, 37, 38 and 45 were later fixed but do not count (their
  first attempt was an error).
- **F5 The pause flag on a, not b.** At j=25 (`he`), a = seq 35 has `after_pause` and b does not.
  The pair counts with sample 95, because D24 tests only the second key.
- **F6 Backspace at index 0, "does not count between" (answer 8b).** This rule can never change a
  result. Reaching index 0 after any first attempt needs an earlier Backspace that erased
  something, and that Backspace already lies between the same a and b. Case (e) therefore pins
  the index clamp and that seq 1 is still a first attempt, not the "between" rule.
- **F7 isDone and ignored keys (answers 9a, 9b).**
  - Keys ignored after `isDone()` produce no rows, so a rows-only fixture cannot show them.
  - Case (j) needs an unfinished block, so a finished block with errors cannot be shown either.
  - (i) is read as "an error never corrected, still on screen when the block ends".
  - T1.3 must test `isDone` separately.
- **F8 Skip reason in the trace.** When several reasons apply, the trace gives the first failing
  check in 12.3's order (for example `al`: a is an error and Backspaces lie between). It is a
  review aid only.
- **F9 release_to_press under overlap and missing key-up.** The value always uses the immediately
  preceding row:

  - seq 26 is null even though earlier rows' `t_up` are known.
- **F10 JSON numbers.** Whole values are written as integers (`32`, `1500`). Python reads them as

- **F11 Metadata.** `author` is "allen (owner)" plus the drafting note. `created_date` and the

- **F12 No release-to-press check in the structural test.** A check that A.8 equals `t_down(i) −
