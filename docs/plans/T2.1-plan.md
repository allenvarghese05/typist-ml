## 2. Design

- **One migration, one model module per table group (mirror the existing layout).**
  `bigram_assignment.py` (one class), `drills.py` (one class), `generation.py`
  (`GenerationJob` + `GenerationAttempt`, as `sessions.py` holds two). Migration `0004_m2_tables`
  creates all four. Rejected: four separate migrations — the acceptance is one "Migration works",
  and the four tables form one dependency cluster (`generation_attempts` → jobs + drills) best
  created/dropped together.
- **Models are the source of truth; the migration mirrors them byte-for-byte (T1.9 precedent).**
  Column types, nullability, server defaults, named constraints and indexes are identical in the
  model and the hand-written migration so `test_migrated_schema_matches_the_models`
  (`compare_metadata`, `compare_type=True`) stays empty. JSON columns are `JSONText` in the model
  and `sa.Text()` in the migration exactly as 0001 did; server defaults are not compared
  (`compare_server_default` is off), so `CURRENT_TIMESTAMP`/`0` defaults are free. Rejected:
  `--autogenerate` — the repo writes migrations by hand with `op.f(...)` names (0001–0003).
- **Enum + range CHECKs on every constrained column (owner answer 3, existing convention).**
  `set_label`, `arm`, `status` get `IN (...)` CHECKs via `sql_in`; `baseline_rank >= 1`,
  `baseline_attempts >= 0`, `baseline_errors >= 0`, `requested >= 1`, `retries >= 0`,
  `length(bigram) = 2`. Boolean `accepted` gets no CHECK (SQLAlchemy `Boolean()` emits none — the
  `after_pause`/`is_builder` precedent). Rejected: leaving the literal §8.1 text unconstrained —
  every existing table CHECKs its enums; owner answer 3 is explicit.
- **FKs on both `participant_id` columns and the full delete path (owner answer 4, §14).**
  `bigram_assignment.participant_id`, `drills.participant_id`, `generation_jobs.participant_id` →
  `participants.id`; `drills.used_in_block_id` → `session_blocks.id`;
  `generation_attempts.job_id` → `generation_jobs.id`; `generation_attempts.drill_id` →
  `drills.id`. No `ON DELETE CASCADE` (T1.1 answer 10); `delete_participant` deletes them in order.
  Rejected: leaving jobs un-FK'd — orphan jobs would survive a participant delete (§14).
- **`generation_attempts.id` is an INTEGER rowid (owner answer 1).** It is the third high-volume
  audit table (one row per model call), matching the `keystroke_events`/`bigram_stats` rationale in
  §8. `id: int | None = Field(default=None, primary_key=True)`, no `AUTOINCREMENT`. Rejected: UUID
  TEXT — §8.1 literally prints `INTEGER` and the owner confirmed it.

  ```python
  from typing import Any, ClassVar, Final

  import sqlalchemy as sa
  from sqlmodel import Field, SQLModel

  from typist.models.base import sql_in
  from typist.models.drills import DRILL_ARMS

  SET_LABELS: Final[tuple[str, ...]] = ("A", "B", "C", "D")


  class BigramAssignment(SQLModel, table=True):
      """One (participant_id, bigram) assignment row (section 8.1 columns, section 3.4 snapshot).

      Composite PK (participant_id, bigram); participant_id is also a FK to participants.id. set_label
      is A/B/C/D, arm is one of D03's four generated arms (DRILL_ARMS, no 'test'). length(bigram) = 2
      enforces the two-letter key (D13). baseline_rank >= 1 and the two baseline counts >= 0.

      __table_args__ = (
          sa.CheckConstraint(sql_in("set_label", SET_LABELS), name="set_label"),
          sa.CheckConstraint(sql_in("arm", DRILL_ARMS), name="arm"),
          sa.CheckConstraint("length(bigram) = 2", name="bigram"),
          sa.CheckConstraint("baseline_rank >= 1", name="baseline_rank"),
          sa.CheckConstraint("baseline_attempts >= 0", name="baseline_attempts"),
          sa.CheckConstraint("baseline_errors >= 0", name="baseline_errors"),
      )

      participant_id: str = Field(foreign_key="participants.id", primary_key=True)
      bigram: str = Field(primary_key=True)
      set_label: str
      arm: str
      baseline_rank: int
      weakness_score: float
      baseline_attempts: int
      baseline_errors: int
      frozen_at: datetime | None = None
  ```

  ```python
  arms. created_at is filled by the database (CURRENT_TIMESTAMP) when the app leaves it None.

  from sqlmodel import Field, SQLModel

      arm IN DRILL_ARMS and status IN DRILL_STATUSES are the only CHECKs (the fairness metrics have no

          sa.Index("ix_drills_participant_id_arm_status", "participant_id", "arm", "status"),

      target_density: float

      status: str
  ```

### Step 3: `generation` model (`GenerationJob` + `GenerationAttempt`, owns `JOB_STATUSES`)

- Files: create `services/api/src/typist/models/generation.py`.
- Exact change — full module:
  ```python
  """generation_jobs and generation_attempts tables (design doc section 8.1; D11, section 10.2, 13.5).

  generation_jobs is the batch worker's queue (one job = produce N drills for one arm); status is
  pending/running/done/failed. generation_attempts is the per-call audit log (up to 5 LLM attempts per
  accepted drill, section 13.5): one row per model call, kept for the rejection rate and the write-up.

  generation_attempts.id is an INTEGER rowid (section 8.1 prints "attempts.id ... INTEGER"): it is the
  third high-volume audit table (one row per model call, many per drill), the same rationale section 8
  gives for keystroke_events and bigram_stats using integer ids. drill_id is NULL until an attempt is
  accepted (section 8.1 "drill_id set when accepted"); gen_ms/gen_tokens/tokens_per_sec/peak_memory_mb
  are LLM-only and NULL for other arms; reject_reasons is a JSON list, [] when accepted.
  """

  from datetime import datetime
  from typing import Any, ClassVar, Final

  import sqlalchemy as sa
  from sqlmodel import Field, SQLModel

  from typist.models.base import JSONText, new_id, sql_in
  from typist.models.drills import DRILL_ARMS

  JOB_STATUSES: Final[tuple[str, ...]] = ("pending", "running", "done", "failed")


  class GenerationJob(SQLModel, table=True):
      """One drill-generation job (section 8.1 columns).

      arm IN DRILL_ARMS, status IN JOB_STATUSES, requested >= 1, retries >= 0 (retries server-defaults
      to 0). participant_id FK -> participants (owner answer 4: jobs are a per-participant table).
      created_at is DB-filled (CURRENT_TIMESTAMP); started_at/finished_at are NULL until the worker
      claims/finishes the job; error is NULL unless the job failed.
      """

      # ClassVar[Any]: see "Table names" in typist/models/__init__.py.
      __tablename__: ClassVar[Any] = "generation_jobs"
      __table_args__ = (
          sa.CheckConstraint(sql_in("arm", DRILL_ARMS), name="arm"),
          sa.CheckConstraint(sql_in("status", JOB_STATUSES), name="status"),
          sa.CheckConstraint("requested >= 1", name="requested"),
          sa.CheckConstraint("retries >= 0", name="retries"),
          sa.Index("ix_generation_jobs_status_created_at", "status", "created_at"),
      )

      id: str = Field(default_factory=new_id, primary_key=True)
      participant_id: str = Field(foreign_key="participants.id")
      arm: str
      requested: int
      status: str
      retries: int = Field(default=0, sa_column_kwargs={"server_default": sa.text("0")})
      error: str | None = None
      created_at: datetime | None = Field(
          default=None,
          nullable=False,
          sa_column_kwargs={"server_default": sa.text("CURRENT_TIMESTAMP")},
      )
      started_at: datetime | None = None
      finished_at: datetime | None = None


  class GenerationAttempt(SQLModel, table=True):
      """One model call for a job (section 8.1 columns); id is the SQLite rowid (INTEGER, no AUTOINCREMENT).

      job_id FK -> generation_jobs (NOT NULL); drill_id nullable FK -> drills (set when accepted). density
      and accepted are always present; reject_reasons is a JSON list ([] when accepted). The four LLM-only
      timing/memory columns are nullable (NULL for non-LLM arms). accepted is a plain Boolean (no CHECK,
      matching keystroke_events.after_pause). An (job_id) index serves the worker's per-job lookups (8.2).
      """

      # ClassVar[Any]: see "Table names" in typist/models/__init__.py.
      __tablename__: ClassVar[Any] = "generation_attempts"
      __table_args__ = (sa.Index("ix_generation_attempts_job_id", "job_id"),)

      id: int | None = Field(default=None, primary_key=True)
      job_id: str = Field(foreign_key="generation_jobs.id")
      drill_id: str | None = Field(default=None, foreign_key="drills.id")
      raw_output: str
      clean_text: str
      density: float
      accepted: bool
      reject_reasons: list[str] = Field(sa_type=JSONText)
      gen_ms: float | None = None
      gen_tokens: int | None = None
      tokens_per_sec: float | None = None
      peak_memory_mb: float | None = None
  ```

### Step 5: migration `0004_m2_tables`

- Files: create `services/api/alembic/versions/0004_m2_tables.py`.
- Exact change — full migration (no app imports; every name wrapped in `op.f(...)`; JSON columns
  `sa.Text()`; `accepted` `sa.Boolean()`; server defaults `CURRENT_TIMESTAMP` and `0`; create
  parents before children, drop children before parents):
  ```python
  """m2 tables: bigram_assignment, drills, generation_jobs, generation_attempts (design doc 8.1, 8.2).

  Revision ID: 0004_m2_tables
  Revises: 0003_bigram_stats
  Create Date: 2026-10-21 00:00:00.000000

  Adds the four remaining M2 tables (bigram_stats was created in 0003_bigram_stats; T1.9 owner answer 1).
  bigram_assignment has the composite PK (participant_id, bigram) -- the first composite PK in the
  schema. Indexes (8.2): drills (participant_id, arm, status); generation_jobs (status, created_at);
  generation_attempts (job_id). Constraint and index names follow typist.models.base.NAMING_CONVENTION,
  written out with op.f(). Column types are plain SQLAlchemy types, so this file imports no app code;
  tests/integration/test_schema.py proves the result matches the SQLModel classes. Downgrade drops the
  four tables children-first (with foreign_keys=ON, DROP TABLE first deletes rows, which fails while
  child rows still reference them).
  """

  from collections.abc import Sequence

  import sqlalchemy as sa
  from alembic import op

  # revision identifiers, used by Alembic.
  revision: str = "0004_m2_tables"
  down_revision: str | Sequence[str] | None = "0003_bigram_stats"
  branch_labels: str | Sequence[str] | None = None
  depends_on: str | Sequence[str] | None = None


  def upgrade() -> None:
      """Create the four tables with their constraints and indexes (parents before children)."""
      op.create_table(
          "bigram_assignment",
          sa.Column("participant_id", sa.String(), nullable=False),
          sa.Column("bigram", sa.String(), nullable=False),
          sa.Column("set_label", sa.String(), nullable=False),
          sa.Column("arm", sa.String(), nullable=False),
          sa.Column("baseline_rank", sa.Integer(), nullable=False),
  ```

  ```python
      """Delete every row that belongs to one participant, children before parents, and commit.

      Order: generation_attempts of the participant's generation_jobs, generation_jobs, drills
      (before session_blocks, because drills.used_in_block_id references a block), bigram_assignment,

      participant's own text_passages (participant_id set; shared passages with a NULL participant_id
      are never touched), then the participants row. There is no ON DELETE CASCADE, so this is the only
      delete path. Raises ParticipantNotFoundError, deleting nothing, if the participant does not
      exist. Any database error rolls the whole delete back.
      """
      if session.get(Participant, participant_id) is None:
          raise ParticipantNotFoundError(participant_id)
      session_ids = list(
          session.exec(
              select(TypingSession.id).where(col(TypingSession.participant_id) == participant_id)
          ).all()
      )
      block_ids = list(
          session.exec(
              select(SessionBlock.id).where(col(SessionBlock.session_id).in_(session_ids))
          ).all()
      )
      job_ids = list(
          session.exec(
              select(GenerationJob.id).where(col(GenerationJob.participant_id) == participant_id)
          ).all()
      )
      try:
          attempts = session.exec(
              delete(GenerationAttempt).where(col(GenerationAttempt.job_id).in_(job_ids))
          ).rowcount
          jobs = session.exec(
              delete(GenerationJob).where(col(GenerationJob.participant_id) == participant_id)
          ).rowcount
          drills = session.exec(
              delete(Drill).where(col(Drill.participant_id) == participant_id)
          ).rowcount
          assignments = session.exec(
              delete(BigramAssignment).where(
                  col(BigramAssignment.participant_id) == participant_id
              )
          ).rowcount
          events = session.exec(
              delete(KeystrokeEvent).where(col(KeystrokeEvent.block_id).in_(block_ids))
          ).rowcount
          blocks = session.exec(
              delete(SessionBlock).where(col(SessionBlock.id).in_(block_ids))
          ).rowcount
          bigrams = session.exec(
              delete(BigramStat).where(col(BigramStat.session_id).in_(session_ids))
          ).rowcount
          sessions = session.exec(
              delete(TypingSession).where(col(TypingSession.id).in_(session_ids))
          ).rowcount
          passages = session.exec(
              delete(TextPassage).where(col(TextPassage.participant_id) == participant_id)

          participants = session.exec(
              delete(Participant).where(col(Participant.id) == participant_id)
          ).rowcount
          session.commit()
      except Exception:
          session.rollback()
          raise
      return ParticipantDeletion(

          generation_jobs=jobs,
  ```
