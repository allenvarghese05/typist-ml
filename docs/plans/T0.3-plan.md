## 1. Summary

- `services/api/` becomes a uv project (`typist-api`, import package `typist`) with exact `==` pins
  and a committed `uv.lock`. `typist.main:create_app` serves `GET /api/v1/health`, which returns

- A SQLite engine runs the WAL, `foreign_keys` and `synchronous` pragmas on every connection. The

## 2. Design

- **Project layout.** A uv "package" project in `services/api`, built with the `uv_build` backend
  (`module-name = "typist"`, `src/` layout). `uv sync` installs it editable, which gives two
  things:
  - `typist.main:create_app` imports after `uv run`.
  - `__file__` points into the source tree, which the DB path relies on.
- **Pins (owner answer 14).**
  - `pyproject.toml` is written by hand with `==` versions. They are the latest stable PyPI
    releases, printed by the owner in a preflight (RESUME POINT A).
  - The owner then runs `uv lock` and `uv sync --locked` (RESUME POINT B).
  - The builder never runs `uv add`, `uv lock` or `uv sync`. It checks that every pin equals the
    version in `uv.lock`.
- **`pyproject.toml` is frozen after RESUME POINT B.** uv reinstalls the editable project whenever
  `pyproject.toml` changes, and that needs the build backend from the uv cache or the network,
  both of which the sandbox blocks.
  - So every setting in it, tool config included, is written once in step 2.
  - Later steps only add files that the editable install picks up without a reinstall.
- **DB path (owner answers 4 and 6).**
  - `typist.config` computes `API_DIR = parents[2]` and `REPO_ROOT = parents[4]` of its own file.
    The default `db_path` is `REPO_ROOT/data/typist.db`.
  - A relative `TYPIST_DB_PATH` is resolved against `REPO_ROOT`, never the working directory. So
    the `services/api/data/` trap (brief follow-up 1) cannot happen, even with an override.
  - pydantic-settings reads `TYPIST_*` variables and `services/api/.env`, given as an absolute
    path.
- **Engine (owner answer 5).** `create_db_engine(path)`:
  - creates the parent directory;
  - sets `check_same_thread=False`, because FastAPI runs sync handlers in a thread pool;
  - registers a `"connect"` listener that runs the three PRAGMAs on every new DBAPI connection.

  The app stores its engine on `app.state`, and the lifespan disposes of it on shutdown.
  `alembic/env.py` opens its connection with the same function and the same setting, and uses
  `render_as_batch=True`.
- **Health (owner answers 1 to 3).** `check_database` runs `SELECT 1`, so it needs no tables. The
  router is thin and returns a `HealthResponse` schema. There is no worker field.
- **Docs and CORS (owner answers 16 and 18).**
  - `docs_url=None` and `redoc_url=None`; the schema is served at `/api/v1/openapi.json`.
  - There is no CORS middleware, and a test proves that no CORS header is sent.
- **Migrations and CLI (owner answers 7 and 8).**
  - `typist.migrations.upgrade_to_head()` wraps `alembic upgrade head`. It finds `alembic.ini`
    through `API_DIR`, so it works from any working directory.
  - The Typer command `typist db migrate` calls it, and `just migrate` calls that command.
  - `alembic/versions/` stays empty.
- **Generated revisions pass the gate (owner answer 13).**
  - `alembic.ini` post-write hooks run the pinned ruff (`check --fix`, then `format`) on every new
    revision, and a test proves this on a temporary copy.
  - No test calls `subprocess`, because semgrep's `p/security-audit` flags non-literal subprocess
    calls.
- **pytest.**
  - The `mlx` marker is registered in `tests/conftest.py`, and `--strict-markers` is set in
    `addopts`.
  - A collection hook skips `mlx` tests unless `sys.platform == "darwin"` and
    `platform.machine() == "arm64"`. This is proven with `pytester`, loaded through `-p pytester`.
  - An autouse fixture points `TYPIST_DB_PATH` at a per-test temp file and turns `.env` reading
    off.
- **pyright (owner answer 12).**
  - Standard mode, strict for `src/`, with `alembic/versions` excluded.
  - One execution environment each for `src`, `tests` and `alembic`. That way the local `alembic/`
    directory can never shadow the installed `alembic` package.
  - Generator-based dependencies are annotated `Generator[T, None, None]` rather than
    `Iterator[T]`, so callers may call `.close()` on them.
- **ruff (owner answer 13).**
  - Defaults plus `I`, `UP`, `B`, `SIM`, line length 100, target `py312`.
  - `src = ["src"]` and `known-first-party = ["typist"]`, so the local `alembic/` directory is not
    sorted as first-party.
- **`security-py` (owner answer 19).** The recipe runs, in order:
  1. bandit, with `-r src -ll`.
  2. A `curl` probe of `https://pypi.org/`, in the same form as D22's other probes.
  3. If the probe gets a response: `uv export --locked --no-emit-project`, whose output feeds
     `pip-audit --requirement <file> --no-deps --disable-pip`.
  4. A summary. The recipe exits 1 if either tool failed.

  A skipped pip-audit prints a message containing `skipping`, so the D22 keyword rule is kept.
- **`just dev` (owner answer 21).**
  - The API line gets `--locked` and `--reload-dir src`. The second flag needs the owner's
    confirmation at this gate (Review focus 4).
  - Reason for `--reload-dir src`: plain uvicorn has no watchfiles, so its StatReload polls every
    `*.py` file under the working directory, including `.venv`.
  - Ctrl-C is proven by an owner-run script (RESUME POINT C). The line changes further only
    through step 14's decision rule.
- **Rejected alternatives:**
  - `uv add`: it writes `>=` ranges and needs the network.
  - hatchling: it needs more configuration.
  - A separate `pyrightconfig.json`: one config file is enough.
  - CORS middleware: rejected by the owner in answer 16.
  - Tests that run ruff through `subprocess`: semgrep flags them.
  - A health check that creates tables: `SELECT 1` needs none.

```python
"""Database engine, session dependency and SQLite pragmas (design doc sections 5.2, 7 and 8)."""

import logging
import sqlite3
from collections.abc import Generator
from pathlib import Path
from typing import Annotated

from fastapi import Depends, Request
from sqlalchemy import Engine, create_engine, event, text
from sqlalchemy.exc import SQLAlchemyError
from sqlmodel import Session

logger = logging.getLogger(__name__)

# Section 8. foreign_keys and synchronous reset on every new connection, so all three run on each.
SQLITE_PRAGMAS: tuple[str, ...] = (
    "PRAGMA journal_mode=WAL",
    "PRAGMA foreign_keys=ON",
    "PRAGMA synchronous=NORMAL",
)


def _apply_sqlite_pragmas(dbapi_connection: sqlite3.Connection, _connection_record: object) -> None:
    """SQLAlchemy "connect" listener: run SQLITE_PRAGMAS on a new DBAPI connection."""
    cursor = dbapi_connection.cursor()
    try:
        for pragma in SQLITE_PRAGMAS:
            cursor.execute(pragma)
    finally:
        cursor.close()


def create_db_engine(db_path: Path) -> Engine:
    """Create an engine for the SQLite file at db_path.

    Creates the parent directory if it is missing (the file itself is created on first connect).
    Every pooled connection gets SQLITE_PRAGMAS. check_same_thread is off because FastAPI runs
    sync handlers in a thread pool. Does not open a connection.
    """
    db_path.parent.mkdir(parents=True, exist_ok=True)
    engine = create_engine(f"sqlite:///{db_path}", connect_args={"check_same_thread": False})
    event.listen(engine, "connect", _apply_sqlite_pragmas)
    return engine


def check_database(engine: Engine) -> bool:
    """Return True if a connection opens and `SELECT 1` runs; else log the error, return False.

    Needs no tables, so it works before any migration.
    """
    try:
        with engine.connect() as connection:
            connection.execute(text("SELECT 1"))
    except (SQLAlchemyError, sqlite3.Error):
        logger.warning("database check failed", exc_info=True)
        return False
    return True


def get_engine(request: Request) -> Engine:
    """FastAPI dependency: the engine that create_app stored on app.state."""
    engine: Engine = request.app.state.engine
    return engine


def get_session(
    engine: Annotated[Engine, Depends(get_engine)],
) -> Generator[Session, None, None]:
    """FastAPI dependency: one SQLModel session per request, closed when the request ends."""
    with Session(engine) as session:
        yield session
```

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from importlib.metadata import version

from fastapi import FastAPI
from sqlalchemy import Engine

from typist.api.routers import health
from typist.config import Settings, get_settings

API_PREFIX = "/api/v1"


@asynccontextmanager
async def _lifespan(app: FastAPI) -> AsyncIterator[None]:
    """Dispose of the engine's pooled connections when the server stops."""
    yield
    engine: Engine = app.state.engine
    engine.dispose()


def create_app(settings: Settings | None = None) -> FastAPI:
    """Build the API app. uvicorn calls it with no arguments; tests pass their own Settings.

        title="Typist-ML API",

        docs_url=None,
        redoc_url=None,

        lifespan=_lifespan,
    )
```

```python
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
        render_as_batch=True,
    )
    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    """Apply migrations over a connection that has the app's pragmas (WAL, foreign keys)."""
    engine = create_db_engine(get_settings().db_path)
    try:
        with engine.connect() as connection:
            context.configure(
                connection=connection,
                target_metadata=target_metadata,
                render_as_batch=True,
            )
            with context.begin_transaction():
                context.run_migrations()
    finally:
        engine.dispose()


if context.is_offline_mode():
```
