# T1.7 brief: attribution.py with fixture tests and a hypothesis property test

Analyst brief (phase 1). Facts only; no design, plan or code. Owner answers (if any) are at the end.

---

## 1. Task

- **ID:** T1.7
- **Title (design doc section 16, M1 table):** "attribution.py with fixture tests and a hypothesis property test"
- **Acceptance criteria (section 16, verbatim):** "Fixture matches; property: attempts never exceed letter-pair positions"

The two clauses, read against the rest of the doc:
- *Fixture matches* — the Python attribution code reproduces the hand-derived `expected_bigram_stats`
  in `services/api/tests/fixtures/golden_session.json` exactly (attempts, errors, `iki_median_ms`, `iki_n`).
- *property: attempts never exceed letter-pair positions* — a Hypothesis property test asserts an invariant:
  over any generated target text and keystroke stream, the total number of attributed attempts never
  exceeds the number of positions `j` where `target[j-1]` and `target[j]` are both letters.

---

## 2. Why it matters

- Section 12 opening, verbatim: "This is the most correctness-sensitive part of the project. If a
  keystroke is attributed to the wrong bigram, every result downstream is wrong. Build it test-first
  against the golden fixture." Attribution is the single Python computation that turns raw
  `keystroke_events` rows into per-bigram `attempts`, `errors` and IKI samples.
- CLAUDE.md correctness rule: "Bigram attribution runs only in Python
  (`services/api/src/typist/services/attribution.py`). The browser computes display stats only." This
  task creates that file. The browser (TextCursor, T1.3) only aligns keystrokes to positions; it never
  attributes bigrams.
- What this enables later:
  - **T1.9** "Session completion: bigram_stats, WPM, accuracy" (acceptance: "typist stats recompute
    reproduces the same numbers") consumes attribution output to populate per-session `bigram_stats`.
  - **T2.2** `assignment.py` ranks weak bigrams from a smoothed error rate and median-IKI z-score
    (section 3.4); those inputs are exactly attribution's `attempts`, `errors`, `iki_median_ms`.
  - **D05** outcomes: "Primary: change in pooled error rate per set minus change in the control set.
    Key secondary: same for median inter-key interval." Both primary and secondary outcomes are built
    directly on attribution's `errors/attempts` and median IKI.
- What breaks if it is wrong: a mis-skip or mis-count silently corrupts weak-bigram selection
  (T2.2), the drills generated against those bigrams (M2/M3), and every reported result. Because the
  golden fixture is frozen (CLAUDE.md: "Never edit expected values to make a test pass; flag it in the
  PR instead"), a wrong attribution shows up as a fixture mismatch rather than as silently wrong data.

## 3. Governing decisions

Each decision and what it forces on T1.7. D01–D20 are in the design doc section 2; D21+ are ADRs in
`docs/decisions/`.

- **D13** (section 2): "English, QWERTY, lowercase a to z and space, no punctuation. Tracked bigrams
  are letter-letter only." Forces: only pairs where both characters are letters are attributed;
  bigrams across a space (e.g. `e` then space) are not tracked. Section 12.3 restates: "Bigrams across
  a space (for example e then space) are not tracked in v1 (D13)."
- **D14** (section 2): "First-attempt substitution at position j, counted only when position j-1 was
  correct on first attempt. Backspace allowed." This is the error definition attribution enforces via
  the `a.outcome != "correct"` skip.
- **D15** (section 2): "Timestamps from event.timeStamp. IKI = press-to-press." Forces: an IKI sample
  is `b.t_down - a.t_down`.
- **D05** (section 2): fixes `attempts`, `errors` and median IKI as the quantities outcomes are built
  from; attribution must expose exactly these.
- **D24** (`docs/decisions/D24-keystroke-events-after-pause-column.md`), Consequences, verbatim:
  "Attribution (T1.7) treats a pair as a pause when the second key has `after_pause` true or the
  press-to-press gap is over 2000 ms. The `b.after_pause` test in section 12.3 stands for both parts
  of the section 12.2 definition, not for the column alone." Forces: a pair is paused (no IKI sample,
  still an attempt and still an error if `b` is an error) when `b.after_pause` is true **or**
  `b.t_down - a.t_down > 2000`.
- **D23(a)** (`docs/decisions/D23-analysis-plan-definitions.md`), verbatim: "Pauses (section 12.2:
  'IKI over 2000 ms, or first key after a blur') are excluded from IKI statistics only and are still
  counted for errors." Forces: a paused pair still contributes to `attempts` and, if `b` is an error,
  to `errors`; only the IKI sample is dropped. The fixture's case p (seq 67→68) is a paused error that
  still counts an attempt and an error.
- **D25** (`docs/decisions/D25-backspace-target-index.md`): Backspace rows record the post-move cursor
  position. Relevant because attribution detects "a Backspace happened between a and b" by scanning
  rows between `a.seq` and `b.seq` for `outcome == "backspace"`; it does not rely on Backspace
  `target_index`.
- **D26** (`docs/decisions/D26-wpm-elapsed-time-and-idle-limit.md`): governs WPM time base. **Out of
  scope for attribution** — WPM/accuracy are session stats (T1.9), not bigram attribution. Noted only
  because the fixture's `expected_session` block carries WPM 22 / accuracy 0.859375 that T1.7 does not
  assert.
- **D27** (`docs/decisions/D27-iki-and-dwell-computed-in-browser.md`): `release_to_press_ms` is not a
  stored row field and attribution does not use it (it uses `t_down`). No effect on attribution logic.

## 4. Current state

### 4.1 The attribution rule (design doc section 12.3, verbatim)

> Attribution then runs in Python over the stored rows:
>
>     for each position j >= 1 where target[j-1] and target[j] are letters:
>         a = first_attempt keystroke at j-1
>         b = first_attempt keystroke at j
>         if a is missing or b is missing:          skip
>         if a.outcome != "correct":                skip   # context was wrong
>         if a backspace happened between a and b:  skip   # not a clean transition
>         bigram = target[j-1] + target[j]
>         attempts[bigram] += 1
>         if b.outcome == "error": errors[bigram] += 1
>         elif b.seq == a.seq + 1 and not b.after_pause:
>             iki_samples[bigram].append(b.t_down - a.t_down)

The derivation (`docs/plans/T1.2-derivation.md`, A.0) amends the IKI-sample branch with the pause gap:
"otherwise it gives an IKI sample `b.t_down − a.t_down` when `b.seq == a.seq + 1`, `b.after_pause` is
false **and the gap is ≤ 2000**." (D24). Per-position skip order when several reasons apply is: a/b
missing, then a-not-correct, then backspace-between (derivation A.5, F8).

## 5. Inputs and outputs

**Inputs:**
- An ordered set of `keystroke_events` rows for one block (or, for session stats later, one session —
  but a pair is never formed across a block boundary; derivation/T1.2 edge case 25). Fields used:
  `seq`, `target_index`, `outcome`, `first_attempt`, `after_pause`, `t_down_ms`.
- The block's `target_text` (from `SessionBlock.target_text`), to know which `j` are letter-pairs and
  to form the bigram string `target[j-1] + target[j]`.
- Source of the rows: either stored DB rows (via an ORM `Session`, matching sibling services) or
  in-memory row objects. The fixture is JSON on disk; `test_golden_fixture.py` both reads it and inserts
  it into the DB (see open question 2).

**Outputs:**
- Per-bigram aggregates: `attempts: int`, `errors: int`, `iki_median_ms: float | None`,
  `iki_n: int`, keyed by two-letter bigram. Shape mirrors the `bigram_stats` columns (section 8.1):
  `bigram TEXT`, `attempts, errors INTEGER`, `iki_median_ms REAL`, `iki_n INTEGER`, "Only clean,
  correct pairs; pauses over 2000 ms excluded." Only bigrams with ≥ 1 attempt appear.
- Where it lives: returned in memory from `attribution.py` (no `bigram_stats` table exists in M1).
  T1.9 later persists these into `bigram_stats` (`participant_id, session_id, bigram`, unique
  `(session_id, bigram)`), but that persistence is not in T1.7's scope.

## 6. Constraints

- **Python-only** (CLAUDE.md): attribution lives only in `services/api/src/typist/services/attribution.py`;
  no attribution logic in TS.
- **Frozen fixture** (CLAUDE.md): `golden_session.json` must never be edited to make a test pass; a
  genuine mismatch is flagged in the PR. Changes to the fixture need an owner-approved PR plus a dated
  changelog entry (fixture `_note`, T1.2 answer 19).
- **Seeded randomness** (CLAUDE.md): "Randomness always comes from a seeded generator passed in by the
  caller." Hypothesis uses its own deterministic generation; any explicit randomness in test helpers
  must be seeded. Avoid flaky property tests (set a fixed seed / `@settings` deterministic profile as
  appropriate — leave the mechanism to the architect).
- **Hypothesis is not installed.** It is absent from `services/api/pyproject.toml` `[dependency-groups].dev`
  and has 0 occurrences in `services/api/uv.lock` (confirmed). Tests run via `uv run --locked pytest`
  (`justfile`), so `--locked` will fail CI unless `hypothesis` is added to the dev group **and**
  `uv.lock` is regenerated in the same PR. Exact versions are pinned (T0.3 answer 14 style): a pinned
  `hypothesis==<x>` is expected.
- **Platform:** attribution is pure Python with no mlx dependency; it runs on Linux CI (no `@pytest.mark.mlx`).
- **`just check`** must pass before push (ruff, pyright strict on `src`, pytest). New code is pyright-strict.
- **Float exactness:** fixture times are whole numbers or multiples of 0.25, chosen so tests compare by
  exact equality (fixture `_note`). IKI samples are differences of such values; medians of even counts
  are means of two such values (e.g. `165.25`). Watch IEEE-754: a hand-expected literal must equal the
  computed double (T1.2 edge case 22).
- **One task per PR** (CLAUDE.md).

## 7. Edge cases

Every case below is in the fixture (`case_index`) and its expected output is pinned. Concrete examples
use (seq a → seq b, bigram, j).

1. **Error at j-1 suppresses the pair at j** (case a): seq 27→28 `th` (j=19) is an attempt and an error;
   the next pair `he` (j=20, seq 28→31) is *skipped* because `a` (seq 28) is an error — even though `h`
   and `e` end up correct after correction. Expected: `th` errors includes this; `he` does **not** gain
   an attempt here.
2. **Correction then retype is not a first attempt** (case b): seq 29 Backspace, seq 30 `h` retyped with
   `first_attempt=false`; the first attempt at position 19 stays seq 28 (the error).
3. **Backspace between a clean a and b** (case c): `si` (seq 39→40, j=29) counts with sample 140; `id`
   (seq 40→43, j=30) is *skipped* because Backspace seq 41 lies strictly between; `de` (seq 43→44, j=31)
   counts with sample 120.
4. **Several Backspaces across a space** (case d): `of` (seq 46→53, j=34) skipped — Backspaces 47,48,49
   lie between a (46) and b (53); the erased correct characters were already counted (`de` earlier).
5. **Backspace at index 0** (case e): seq 0 is a no-op Backspace at index 0; seq 1 `t` is still the first
   attempt at 0. Attribution must not treat seq 0 as the `a` of any pair (it is a backspace row, not a
   first-attempt letter).
6. **Omission cascade** (case f): `m` omitted; `a` and `l` land one position early as errors. `sm`
   (j=5) attempt+error; `ma` (j=6) and `al` (j=7) skipped (a-not-correct). The retyped `m`,`a` are not
   first attempts.
7. **Transposition "teh"** (case g): `th` (seq 55→56, j=37) is one bigram error; `he` (seq 56→57, j=38)
   is *skipped* (a is an error), not a second error. One slip → one bigram error.
8. **Space for a letter / letter for a space** (case h): a space typed at `i`'s position → `hi` (j=11)
   attempt+error, `il` (j=12) skipped; a letter `b` typed at a space position (seq 21) is an accuracy
   error but is in **no** bigram (the target position is a space; not letter-letter, D13).
9. **Uncorrected error at block end** (case i): `s` for `a` at 62 never corrected → `fa` (j=62)
   attempt+error; `ar` (j=63) skipped (a is an error).
10. **Unfinished block, untyped tail** (case j): block ends at index 64 of 65; `rm` (j=64, seq 88→null)
    skipped because `b` is missing. Attribution handles a missing trailing first-attempt gracefully.
11. **Simple rollover** (case k): `h` pressed before `t` released (release-to-press −30). The `th`
    sample (90) is unaffected — attribution uses `t_down` only.
12. **Nested overlap** (case l): `r` pressed and released while `e` held (release-to-press −100); `he`
    (95) and `er` (60) samples unaffected.
13. **Blur pause, gap < 2000** (case m): seq 35 `after_pause=true`, gap 1800. `th` (j=24, seq 34→35) is
    an attempt with **no** IKI sample (the flag suppresses it); still counts as an attempt.
14. **Gap > 2000 without blur** (case n): seq 64 gap 2500, no flag. `ol` (j=41, seq 63→64) attempt with
    no sample (gap > 2000). Pause-by-gap, not by flag (D24).
15. **Gap exactly 2000** (case o): seq 65 gap 2000. `ld` (j=42, seq 64→65) **does** get sample 2000 —
    "over 2000" is strict `>`, so exactly 2000 is not a pause.
16. **First key after blur is a Backspace, or an error** (case p): seq 22 Backspace carries the flag
    (not seq 23); seq 68 `w` is a flagged error → `re` (j=45, seq 67→68) still counts an attempt and an
    error (D23(a)), with no IKI sample.
17. **Missing key-up** (case q): seq 25 `n` has null `t_up`/`dwell`; `on` (j=16, seq 24→25) sample 130
    unaffected (attribution uses `t_down`, not `t_up`).
18. **Repeated letter on same key** (case s): two `ll` pairs on `KeyL` (j=8 sample 160, j=13 sample
    170.5); both count; `ll` aggregates to attempts 2, median 165.25.
19. **Non-adjacent a and b** (`b.seq != a.seq + 1`): even with no backspace between, the IKI sample is
    only taken when `b.seq == a.seq + 1`. The fixture's counted pairs all happen to be adjacent after
    the backspace-between skip, so the property test (section 1) is the main guard for this branch.
20. **Even-count median** (`th` `[90,100]`→95, `ll` `[160,170.5]`→165.25): mean of the two middle
    values; `statistics.median` gives this. Odd count `he` requires sorting first (`[140,95,110]`→110).
21. **Property invariant:** total attempts ≤ number of letter-pair positions. In the fixture: 26 ≤ 36.
    The property test must generate targets/keystrokes where this can be exercised near the bound
    (e.g. an all-letter target typed cleanly: attempts == letter-pair positions == length−1).

## 8. Risks

1. **Silent fixture-fidelity bug:** attribution passes the property test but mis-handles a skip rule the
   fixture pins (e.g. counting `he` in case a/g, or sampling the 2000-ms boundary as a pause). Mitigated
   only by asserting every one of the 19 expected bigram rows, not a subset.
2. **Median semantics:** using the unsorted middle (`he`→95 instead of 110), a lower/upper median, or
   integer truncation (`165.25`→165). Must sort and use mean-of-middles.
3. **Pause rule half-implemented:** honouring `after_pause` but not the `> 2000` gap, or vice versa; or
   using `>=` 2000 and losing the `ld` sample. D24 requires the OR of both, strict `>`.
4. **Reading the wrong "first attempt":** using the latest row at a position, or a backspace/retype row,
   as `a` or `b`. `a`/`b` must be the `first_attempt == true` letter rows at `j-1`/`j`.
5. **Backspace-between detection:** scanning the wrong seq interval (inclusive vs strict), or missing
   multiple Backspaces (cases c, d). Must be "strictly between a.seq and b.seq".
6. **Float literal mismatch:** a hand-written expected median that is a different IEEE-754 double than
   the computed one (T1.2 edge case 22). The brief recommends asserting against the fixture's own
   numbers, not fresh literals.
7. **Hypothesis not installed / lockfile drift:** forgetting to add `hypothesis` to the dev group and
   regenerate `uv.lock` makes `uv run --locked pytest` fail in CI; an unseeded/over-broad strategy makes
   the property test slow or flaky.
8. **Attempting to persist to `bigram_stats`:** that table does not exist until T2.1; writing a model or
   migration here is scope creep (T2.1's job) and risks a second attribution path outside `attribution.py`.
9. **Cross-block pairing:** if attribution ever runs over a whole session, forming a pair across a block
   boundary would be wrong (each block has its own target). T1.7's fixture is single-block, so this is
   not exercised by "Fixture matches" and must be guarded by design, not left to the fixture.

## 9. Open questions

Numbered so the owner (orchestrator) can answer by number.

1. **Return type / shape.** The design names columns (`bigram, attempts, errors, iki_median_ms,
   iki_n`) but no Python signature. Should attribution return a frozen dataclass per bigram (like
   `EventIngestResult` in `events.py`), a dict keyed by bigram, or a list? And should the function take
   an ORM `Session` + block/session id (sibling-service style) or an already-loaded list of rows?
2. **Input source for the fixture test.** Should the fixture test (a) insert the 89 rows into the
   migrated DB via `migrated_engine` and run attribution over queried `KeystrokeEvent` rows, or (b) run
   attribution over the row dicts read straight from `golden_session.json`? (a) matches 12.3 "over the
   stored rows" and `test_golden_fixture.py`; (b) is lighter. Which is intended for T1.7?
3. **Unit of attribution: block or session.** `bigram_stats` is per session (section 8.1), but pairs
   never cross a block boundary. Should `attribution.py` operate per block and let T1.9 aggregate
   across a session's blocks, or accept a session's rows and aggregate internally (grouping by block to
   avoid cross-block pairs)? The single-block fixture does not disambiguate.
4. **Hypothesis dependency.** Confirm `hypothesis` is to be added to `services/api/pyproject.toml`
   `[dependency-groups].dev` with an exact pin and `uv.lock` regenerated in this PR (it is currently
   absent). Any preferred version, or `@settings` profile / fixed seed for determinism?
5. **Property strategy scope.** "attempts never exceed letter-pair positions" — should the property
   generate (i) arbitrary target strings over `[a-z ]` plus arbitrary keystroke rows, or (ii)
   well-formed keystroke streams produced by driving `TextCursor`-equivalent logic? Scope affects how
   much row-construction logic the test needs. Are any further invariants wanted (e.g. `errors ≤
   attempts`, `iki_n ≤ attempts`), or strictly the one named in the acceptance criteria?
6. **Tie-break detail in median.** The fixture only has even counts of 2 and odd counts of 1 and 3.
   Confirm `statistics.median` (mean of middles for even n) is the intended definition for all n, to be
   recorded if it needs an ADR (it is currently only implied by the derivation).
