# T2.4 plan — control and heuristic generators

*Architect blueprint. The builder implements this verbatim and makes no design decisions. The
brief's "## Owner answers" (1–9) are binding and are implemented exactly as written; nothing here
overrides them. Every generator rule, constant and SQL value below was prototyped against the real
20,000-word / 150-bigram corpus (built with `build_corpus` under `/tmp` only) and the real
`validate`: all 50 control candidates and all 150 heuristic candidates (50 seeds × 3 target sets)
pass on the first attempt, with measured density **0.223–0.281** — comfortably inside `[0.15, 0.40]`
— and no seed failing. The governor midpoint `(d_min + d_max) / 2 = 0.275` needs **no tuning** (see
§ "Measured results").*

## 1. Summary

When this plan is done: `generation/sampling.py` provides two pure, seeded samplers
(`weighted_choice`, `softmax_choice`) that consume exactly one `rng` draw each; `generation/
control.py` defines `ControlGenerator` (frequency-weighted random words over `index.words[:pool_size]`,
sqrt-frequency weights, ≤2 uses per word, fill to a word boundary ≤ `length_chars`, empty targets);
`generation/heuristic.py` defines `HeuristicGenerator` (lowest-coverage target with rng tie-break,
§13.3 step-4 scoring `density × log(freq/min_freq)`, top-50 softmax at temperature 0.5, ≤2 uses, a
density governor that falls back to sqrt-frequency fillers once running density exceeds the d_min/
d_max midpoint, terminating at `length_chars`). A data-only migration `0007_generator_config` seeds
`control_word_pool: 5000`. `tests/unit/test_generators.py` builds the corpus once per module and
proves: 50 control candidates validate; 50 × a common 4-set, a rare 4-set and a 3-set validate;
determinism (same seed → identical, different seed → different); density explicitly inside bounds;
clean charset and no double space; ≤2 word uses. `tests/integration/test_migration_0007.py` proves
the migration; head/config pins advance to `0007` / `SEEDED_CONFIG_ROWS = 23` / `EXPECTED_CONFIG`
gains `control_word_pool`. Acceptance ("50 drills each pass the validator; deterministic by seed") is
proven by the per-arm 50-seed validation tests plus the determinism tests.

## 2. Design

Three new modules sit behind the frozen `DrillGenerator` protocol from T2.3 (`base.py`) and in front
of the frozen `validate` gate (`validator.py`). `sampling.py` holds the two seeded idioms both
generators share, factored out of (not imported from) `services/test_composer.py` so the frozen
baseline composer is left untouched (owner answer 4): `weighted_choice` is §13.2's sqrt-frequency
draw, `softmax_choice` is §13.3 step-4's softmax-over-top-50. Both take the caller's `random.Random`
and consume exactly one `rng.random()` draw, so determinism is a property of the inputs
(CLAUDE.md: randomness is always seeded by the caller; owner answer 2 seeds solely from
`spec.seed`).

`ControlGenerator` is the comparison floor (§3.3): it draws from the control pool
(`index.words[:pool_size]`, rank-ordered, so the slice *is* "the 5,000 most frequent words"; owner
answer 1) weighted by `sqrt(frequency)` (§13.2), caps each word at **2** uses per drill so it can
never trip the validator's `word_repeat` (owner answer 8: 2 < 3), and only appends a word that still
fits within `spec.length_chars` counting the joining space, so the joined text is ≤ `length_chars` at
a word boundary with no leading/trailing/doubled space (owner answers 5/8; the 270 floor is safe —
measured 299–300).

`HeuristicGenerator` is the dictionary baseline the LLM must beat (§13.3). Per step it computes the
running target density and, if it exceeds the midpoint `(spec.min_density + spec.max_density) / 2`,
picks a **filler** (a control-pool word containing no target bigram, sqrt-frequency weighted);
otherwise it picks a **target word**: choose the target with the lowest coverage counter (ties
broken by `rng`), then softmax-sample one of the top 50 eligible words ranked by §13.3's score
`(occurrences of target in word / number of letter bigrams in word) × log(frequency / min_frequency)`
where `min_frequency` is the smallest frequency in the index (owner answer 5: keeps the log ≥ 0 so it
never flips the ranking). Words are skipped once used twice; the loop ends when the next word would
exceed `length_chars`. The governor is what keeps density inside `[d_min, d_max]` without changing
the §13.3 recipe for target words (owner answer 5) — a greedy target-dense loop with no governor
overshoots 0.40 (brief §7 edge 4).

The per-target candidate lists and their scores are precomputed once per `generate` call (score
depends only on word and target, never on coverage), so each step is `O(words-per-target)` for a
target pick and `O(pool)` for a filler pick; no step re-ranks or scans the full 20,000-word
vocabulary (brief performance note).

Both generators are single-shot: `generate` returns exactly one `DrillCandidate` (`text ==
raw_output`, LLM fields `None`) and never calls `validate` — the validate-and-retry loop is T2.5's
(owner answer 3). They are constructed with `(index, config, pool_size)` for a uniform T2.5 wiring;
`config` is accepted but unused (neither arm reads a validator key: control enforces its own 2-use
cap, the heuristic reads density bounds and length off the spec). `control_word_pool` is seeded in
`0007` but, like `drill_length_chars` in T2.3, is **read by T2.5**, not by T2.4 (the test passes
`pool_size=5000` directly).

Rejected: extracting a shared loop out of `test_composer.py` and reusing it (owner answer 4 — T1.8's
form-A text is frozen once used; refactoring its composer now risks changing it). Rejected: a
coverage-only heuristic without a density governor (the §13.3 floor over 4 targets dominates coverage
— 12 occurrences vs ~30 needed, brief §7 edge 3 — and no governor overshoots 0.40, edge 4).

- Exact change — full file:
  ```python
  """Seeded, deterministic sampling helpers shared by the non-LLM generators (design doc 13.2, 13.3).

  Both functions take a random.Random passed in by the caller (CLAUDE.md: randomness is always
  seeded by the caller) and consume exactly one rng.random() draw, so a given rng state plus inputs
  always yields the same item -- the determinism the acceptance requires. weighted_choice is 13.2's
  frequency-weighted draw (the caller supplies the weights, e.g. sqrt(frequency)); softmax_choice is
  13.3 step 4's softmax-over-top-50 at a given temperature, the same idiom as the baseline composer's
  _choose_word (copied, not imported, so the frozen composer is untouched; owner answer 4). Pure: no
  I/O, no mlx, importable on Linux CI.
  """

  import math
  import random
  from collections.abc import Sequence
  from typing import TypeVar

  _T = TypeVar("_T")


  def weighted_choice(
      rng: random.Random, items: Sequence[_T], weights: Sequence[float]
  ) -> _T:
      """Return one item chosen with probability proportional to its weight, using one rng draw.

      items and weights must be non-empty and the same length; every weight must be >= 0 and their
      sum must be > 0. Deterministic for a given rng state. The cumulative scan mirrors the composer's
      seeded selection; the final item is returned when floating-point rounding leaves the threshold
      exactly at the top of the cumulative sum.
      """
      threshold = rng.random() * sum(weights)
      cumulative = 0.0
      for item, weight in zip(items, weights, strict=True):
          cumulative += weight
          if threshold <= cumulative:
              return item
      return items[-1]


  def softmax_choice(
      rng: random.Random,
      items: Sequence[_T],
      scores: Sequence[float],
      temperature: float,
  ) -> _T:
      """Return one item sampled from the softmax of scores at temperature, using one rng draw.

      items and scores must be non-empty and the same length; temperature must be > 0. Scores are
      shifted by their maximum before exponentiating (numerical stability; identical to the composer's
      _choose_word idiom, 13.3 step 4). Deterministic for a given rng state.
      """
      highest = max(scores)
      weights = [math.exp((score - highest) / temperature) for score in scores]
      threshold = rng.random() * sum(weights)
      cumulative = 0.0
      for item, weight in zip(items, weights, strict=True):
          cumulative += weight
          if threshold <= cumulative:
              return item
      return items[-1]
  ```

- Exact change — full file. The 2-use cap is a module literal (< the validator's 3, so `word_repeat`

  ```python
  """The control drill generator: frequency-weighted random words, no targets (design doc 3.3, 13.2).

  ControlGenerator draws words from the control pool -- the pool_size most frequent a-z words, which is
  index.words[:pool_size] because words.json is rank-ordered (owner answer 1) -- weighted by
  sqrt(frequency) (13.2), capping each word at _MAX_USES_PER_DRILL uses per drill so it can never trip
  the validator's word_repeat rule (owner answer 8: 2 < the config's 3). It fills up to
  spec.length_chars at a word boundary without exceeding it (owner answer 5); measured length is
  299-300 for length_chars 300, safely above the 270 floor. It targets nothing, so target_bigrams is
  empty and the validator skips density/coverage (3.3). The only randomness is random.Random(spec.seed)
  (owner answer 2). Pure: returns one DrillCandidate per call (text == raw_output; owner answer 3) and
  writes no DB rows (T2.5 validates and persists).
  """

  import math
  import random
  from typing import Final

  from typist.corpus.word_index import WordIndex
  from typist.generation.base import Arm, DrillCandidate, DrillSpec
  from typist.generation.sampling import weighted_choice
  from typist.generation.validator import ValidatorConfig

  _VERSION: Final = "control-v1"
  # 13.3 step-5 cap, kept below the validator's drill_max_word_repeats (3) so control never fails
  # word_repeat; not an experiment knob (owner answer 7), so a module literal like the composer's.
  _MAX_USES_PER_DRILL: Final = 2


  class ControlGenerator:
      """Frequency-weighted random-word generator for the control arm (design doc 3.3, 13.2)."""

      arm = Arm.CONTROL
      version = _VERSION

      def __init__(
          self, index: WordIndex, config: ValidatorConfig, pool_size: int
      ) -> None:
          """index supplies the ranked words and their frequencies; config is accepted for a uniform
          generator constructor (T2.5 wires every arm the same way) though control reads nothing from
          it; pool_size is control_word_pool (owner answer 1) -- the pool is index.words[:pool_size].
          Precomputes the pool and its sqrt-frequency weights once."""
          self._config = config
          self._pool: tuple[str, ...] = index.words[:pool_size]
          self._sqrt_freq: dict[str, float] = {
              word: math.sqrt(index.frequencies[word]) for word in self._pool
          }

      def generate(self, spec: DrillSpec) -> DrillCandidate:
          """Compose one control drill and return it as a DrillCandidate (text == raw_output).

          Draws words from the pool weighted by sqrt(frequency) with a seeded rng
          (random.Random(spec.seed)); each word is used at most _MAX_USES_PER_DRILL times; a word is
          added only if it still fits within spec.length_chars (counting the joining space), so the
          joined text is <= spec.length_chars at a word boundary with no leading/trailing/doubled
          space. Stops when no eligible word fits. Deterministic for a given spec.seed.
          """
          rng = random.Random(spec.seed)
          used: dict[str, int] = {}
          words: list[str] = []
          length = 0
          while True:
              fits = [
                  word
                  for word in self._pool
                  if used.get(word, 0) < _MAX_USES_PER_DRILL
                  and length + len(word) + (1 if words else 0) <= spec.length_chars
              ]
              if not fits:
                  break
              weights = [self._sqrt_freq[word] for word in fits]
              word = weighted_choice(rng, fits, weights)
              used[word] = used.get(word, 0) + 1
              length += len(word) + (1 if words else 0)
              words.append(word)
          text = " ".join(words)
          return DrillCandidate(
              text=text,
              raw_output=text,
              generator_version=_VERSION,
              seed=spec.seed,
          )
  ```

### Step 3: `generation/heuristic.py` — `HeuristicGenerator`

- Files: create `services/api/src/typist/generation/heuristic.py`.
- Exact change — full file. Constants are module literals (owner answer 7). `_word_score` is §13.3
  step 4 verbatim with `min_frequency` normalisation (owner answer 5). The governor compares the
  **running** density to the midpoint `(spec.min_density + spec.max_density) / 2`. Per-target ranked
  lists and scores are precomputed once per `generate` (score is coverage-independent), so each step
  is `O(words-per-target)` for a target pick; the filler pool is precomputed and only filtered (never

  fills.
  ```python
  """The heuristic drill generator: the 13.3 dictionary baseline the LLM must beat (design doc 13.3).

  Per step HeuristicGenerator picks the target bigram with the lowest coverage counter (ties broken by
  rng; owner answer 5), then softmax-samples one of the top _TOP_CANDIDATES eligible words ranked by
  the 13.3 step-4 score (_word_score): (occurrences of the target in the word / number of letter
  bigrams in the word) * log(frequency(word) / min_frequency), where min_frequency is the smallest
  frequency in the index so the log is >= 0 and never flips the ranking (owner answer 5). Words are
  skipped once used _MAX_USES_PER_DRILL times (13.3 step 5). A density governor keeps the drill inside
  [spec.min_density, spec.max_density] without changing the 13.3 recipe: before each pick it compares
  the running target density to the midpoint (spec.min_density + spec.max_density) / 2 and, if above,
  picks a sqrt-frequency *filler* from the control pool that contains no target bigram instead of a
  target word (owner answer 5; a greedy target-dense loop with no governor overshoots 0.40). The loop
  terminates when the next word would exceed spec.length_chars (word boundary, <= length_chars). The
  only randomness is random.Random(spec.seed) (owner answer 2). Pure: one DrillCandidate per call
  (text == raw_output; owner answer 3); no DB write (T2.5 validates and persists). Per-target candidate
  lists and scores are precomputed once per generate, so each step is O(words-per-target), never a
  full-vocabulary scan (brief performance note).
  """

  import math
  import random
  from typing import Final

  from typist.corpus.word_index import WordIndex, word_bigrams
  from typist.generation.base import Arm, DrillCandidate, DrillSpec
  from typist.generation.sampling import softmax_choice, weighted_choice
  from typist.generation.validator import ValidatorConfig

  _VERSION: Final = "heuristic-v1"
  # 13.3 algorithm constants (owner answer 7), module literals like the composer's.
  _TEMPERATURE: Final = 0.5  # 13.3 step-4 softmax temperature.
  _TOP_CANDIDATES: Final = 50  # 13.3 step-4 "sample one of the top 50".
  _MAX_USES_PER_DRILL: Final = 2  # 13.3 step-5 "skip words already used twice".
  _MIN_WORD_LEN: Final = 2  # 13.4 word-length range, applied to target and filler words.
  _MAX_WORD_LEN: Final = 10


  class HeuristicGenerator:
      """The 13.3 dictionary-baseline generator for the heuristic arm."""

      arm = Arm.HEURISTIC
      version = _VERSION

      def __init__(
          self, index: WordIndex, config: ValidatorConfig, pool_size: int
      ) -> None:
          """index supplies the words, frequencies and bigram index; config is accepted for a uniform
          generator constructor (T2.5) though the heuristic reads density bounds and length off the
          spec, not config; pool_size is control_word_pool, used for the filler pool (owner answers
          1, 5). Precomputes min_frequency, the 2-10-letter filler pool and its sqrt-frequency
          weights."""
          self._index = index
          self._config = config
          self._min_frequency = min(index.frequencies.values())
          self._filler_pool: tuple[str, ...] = tuple(
              word
              for word in index.words[:pool_size]
              if _MIN_WORD_LEN <= len(word) <= _MAX_WORD_LEN
          )
          self._sqrt_freq: dict[str, float] = {
              word: math.sqrt(index.frequencies[word]) for word in self._filler_pool
          }

      def _word_score(self, word: str, target: str) -> float:
          """13.3 step-4 score (owner answer 5): (occurrences of target in word / number of letter
          bigrams in word) * log(frequency(word) / min_frequency). min_frequency is the smallest
          frequency in the index, so the log is >= 0. Returns 0.0 for a word with no bigrams (never
          reached for a word that contains target)."""
          bigrams = word_bigrams(word)
          if not bigrams:
              return 0.0
          density = bigrams.count(target) / len(bigrams)
          return density * math.log(self._index.frequencies[word] / self._min_frequency)

      def generate(self, spec: DrillSpec) -> DrillCandidate:
          """Compose one heuristic drill and return it as a DrillCandidate (text == raw_output).

          Deterministic for a given spec.seed (random.Random(spec.seed)). See the module docstring for
          the step logic: lowest-coverage target (rng tie-break), top-50 softmax by _word_score, the
          density governor at the (min+max)/2 midpoint with sqrt-frequency non-target fillers, 2-use
          cap, and termination at spec.length_chars on a word boundary.
          """
          rng = random.Random(spec.seed)
          targets = spec.target_bigrams
          coverage: dict[str, int] = {bigram: 0 for bigram in targets}
          target_set = frozenset(targets)
          ranked: dict[str, tuple[str, ...]] = {}
          scores: dict[str, dict[str, float]] = {}
          for bigram in targets:
              words = [
                  word
                  for word in self._index.words_containing(bigram)
                  if _MIN_WORD_LEN <= len(word) <= _MAX_WORD_LEN
              ]
              word_scores = {word: self._word_score(word, bigram) for word in words}
              ranked[bigram] = tuple(
                  word for _, word in sorted(
                      (-word_scores[word], word) for word in words
                  )
              )
              scores[bigram] = word_scores
          fillers = tuple(
              word
              for word in self._filler_pool
              if not (frozenset(word_bigrams(word)) & target_set)
          )
          midpoint = (spec.min_density + spec.max_density) / 2
          used: dict[str, int] = {}
          chosen_words: list[str] = []
          length = 0
          target_occurrences = 0
          total_bigrams = 0
          while True:
              density = target_occurrences / total_bigrams if total_bigrams else 0.0
              word: str | None = None
              if not density > midpoint:
                  lowest = min(coverage[bigram] for bigram in targets)
                  tied = sorted(
                      bigram for bigram in targets if coverage[bigram] == lowest
                  )
                  rng.shuffle(tied)
                  for bigram in tied:
                      eligible = [
                          candidate
                          for candidate in ranked[bigram]
                          if used.get(candidate, 0) < _MAX_USES_PER_DRILL
                      ][:_TOP_CANDIDATES]
                      if eligible:
                          word = softmax_choice(
                              rng,
                              eligible,
                              [scores[bigram][candidate] for candidate in eligible],
                              _TEMPERATURE,
                          )
                          break
              if word is None:
                  eligible_fillers = [
                      candidate
                      for candidate in fillers
                      if used.get(candidate, 0) < _MAX_USES_PER_DRILL
                  ]
                  if not eligible_fillers:
                      break
                  word = weighted_choice(
                      rng,
                      eligible_fillers,
                      [self._sqrt_freq[candidate] for candidate in eligible_fillers],
                  )
              addition = len(word) + (1 if chosen_words else 0)
              if length + addition > spec.length_chars:
                  break
              used[word] = used.get(word, 0) + 1
              length += addition
              word_bg = word_bigrams(word)
              total_bigrams += len(word_bg)
              for bigram in targets:
                  count = word_bg.count(bigram)
                  coverage[bigram] += count
                  target_occurrences += count
              chosen_words.append(word)
          text = " ".join(chosen_words)
          return DrillCandidate(
              text=text,
              raw_output=text,
              generator_version=_VERSION,
              seed=spec.seed,
          )
  ```
  Notes: the `word: str | None = None` / per-step reassignment is what lets the governor fall back to
  a filler; when the governor allows a target but every tied target is exhausted, the loop also falls
  through to a filler (length keeps filling). `rng.shuffle(tied)` consumes no draw when `len(tied) ==
  1`, so determinism is unaffected. The target words come from `words_containing` over the full index
  (§13.3 step 1 indexes 20,000 words) while fillers come from the control pool (owner answer 5);
  both are length-filtered to 2–10 (§13.4), which for a bigram-containing word is already satisfied
  except at the long tail.

## 8. Review focus

1. **The density governor and the §13.3 scoring (step 3 `generate`/`_word_score`; owner answer 5).**
   Confirm the governor compares the *running* density (`target_occurrences / total_bigrams`) to the
   midpoint `(spec.min_density + spec.max_density) / 2`, picks a non-target sqrt-frequency filler when
   above and a target word otherwise, and that `_word_score` is exactly `(count of target in word /
   len(word_bigrams)) × log(frequency / min_frequency)` with `min_frequency = min(index.frequencies
   .values())`. This is the one place that keeps all 150 heuristic candidates inside `[0.15, 0.40]`.
2. **Determinism (steps 1–3; owner answer 2).** Confirm the only randomness is
   `random.Random(spec.seed)`, that `weighted_choice`/`softmax_choice` each consume one draw, that
   `rng.shuffle(tied)` is the only other draw and is consumed identically every run, and that no
   `set`/`dict` iteration order leaks into word choice (targets iterate the spec tuple; `tied` is
   `sorted` before shuffle; pools are tuples in rank order).
3. **The length/word-boundary and 2-use cap (steps 2–3; owner answers 5, 8).** Confirm a word is
