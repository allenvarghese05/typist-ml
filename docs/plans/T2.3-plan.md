## Revisions

**R1 (2026-10-22) — `_metrics` must not count empty tokens as words.** The builder (steps 1–6
built and committed on `t2-3-validator`) found that step 2's `_metrics` tokenised with
`text.split(" ")`, so whitespace-only input `"   "` yields four empty tokens, giving
`max_word_count = 4` and firing `WORD_REPEAT`. That contradicts the binding owner answer 9, which
requires `"   "` to reject with exactly `(TOO_SHORT, BAD_CHARSET)` (see
`test_whitespace_only_text_is_too_short_and_bad_charset`). Empty tokens are not words. Fix: in
`_metrics`, define `words = [token for token in text.split(" ") if token]` and use `words` for every
word-based metric (`mean_word_len`, `real_word_ratio`, `max_word_count`). Charset detection is
unchanged — it reads double/leading/trailing spaces from the **raw** text in `_charset_ok`
(`"  " in text`, `text[0] == " "`, `text[-1] == " "`), so whitespace input still yields
`BAD_CHARSET`. `mean_word_len` for zero words is `0.0` (the `if words else 0.0` guard — never
raises; owner answer 9). `_longest_bigram_run` is **not** changed: it already iterates
`text.split(" ")` and an empty word yields `word_bigrams("") == []`, contributing nothing, so empty
tokens never affect `bigram_run`.

**No step-3 expected test value changes.** Every other test string in step 3 has no leading,
trailing or doubled space, so filtering empty tokens is a no-op for them; this was re-verified with
the real `count_bigrams` (importable from `services/api`): `density_low` density `0.10` / `max_word_count`
3, `density_high` `0.45` / 1, `coverage` `{ck:5, ow:2}` / density `0.20`, `accepted` density `0.15` /
`mean_word_len` `6.0` / `real_word_ratio` `0.75`, `multi` `max_word_count` 4 / density `0.0`, `at_max`
density `0.40`, `real_word_ratio` `1/3`. The only difference from the previous code is that
whitespace-only `"   "` now gives `max_word_count = 0` (was 4) and empty/zero-word text keeps
`mean_word_len = 0.0` without relying on the `[""]` single-empty-token accident. The already-written
`test_whitespace_only_text_is_too_short_and_bad_charset` now passes; no test is edited to fit the
code. Only step 2's `_metrics` block changes (exact diff at the end of step 2).

## 1. Summary

When this plan is done: `generation/base.py` defines the shared contracts `Arm` (StrEnum, D03's four
arms), `DrillSpec` and `DrillCandidate` (frozen dataclasses) and the `DrillGenerator` Protocol, with
no I/O and no `mlx-lm` import; `generation/validator.py` defines `RejectReason` (StrEnum, the eight
reason tokens), `ValidatorConfig`, `DrillMetrics`, `ValidationResult`, a pure
`validate(text, spec, config, known_words) -> ValidationResult` that collects **all** failing
reasons, and `load_validator_config(session)`; a data-only migration `0006_validator_config` seeds
six config keys (downgrade removes them). Unit tests prove one failing case per `RejectReason`, an
accepted drill, control passes / control word_repeat, multi-reason collection, determinism, empty
text, the `thth`/`ththth`/across-space run examples, and the `d_min`/`d_max` density boundaries; an
integration test proves the migration; the head/config pins are updated. The acceptance ("Each
rejection reason has a test") is proven by the eight per-reason unit tests.

## 2. Design

The two files are the shared spine of the generation subsystem (brief §2). `base.py` is pure type
definitions; `validator.py` is one pure function plus one small config reader. The validator is
split exactly like `assignment.py`/`test_composer.py`: a **pure** `validate(...)` that takes plain
dataclasses and a `Collection[str]` of known words so unit tests need no database and can
hand-verify every number, and a **DB-facing** `load_validator_config(session)` that reads the
config keys (same pattern as `load_assignment_config`/`load_baseline_config`). The validator never
mutates text (owner answer 6: cleaning is the generator's job) and never raises on generator output
(owner answer 9). It reuses the single project bigram definition `count_bigrams`/`word_bigrams`
(CLAUDE.md "one source of truth", D13) and computes the three recorded fairness metrics plus the
rule-only metrics. Density/coverage are skipped when `spec.target_bigrams` is empty (covers control
and any degenerate targetless spec, owner answer 4/8); the real-word-ratio **gate** fires only for
`Arm.LLM` (owner answers, brief §4.3), though the ratio is recorded for every arm. The density
bounds come from `spec.min_density`/`spec.max_density` (brief §5: they reach the validator on the
spec); the length floor, coverage/repeat limits and the ratio threshold come from `ValidatorConfig`
(owner answer 5: config, never literals, §17.1). All reasons are collected in `RejectReason`
definition order for a deterministic result tuple.

**Word source for real_word_ratio:** the validator takes an injectable `Collection[str]` of known
words, **not** the whole `WordIndex`. The service (T2.5) passes `WordIndex.words`; unit tests pass a
small `frozenset[str]`. This is simpler for tests and keeps the validator decoupled from artifact
loading (owner answer 3: the 20,000-word `words.json` list via `WordIndex` is the source; its size
is a config knob, `corpus_word_count`, not a code change, if M3's LLM arm is starved).

Rejected: putting the density bounds in `ValidatorConfig` instead of on the spec — the §9.1
`DrillSpec` already carries `min_density`/`max_density` (brief §4.2/§5), so reading them off the spec
keeps one source and lets T2.5 override per spec. Rejected: passing the whole `WordIndex` into
`validate` — the validator only needs membership, so a `Collection[str]` is the smaller contract.

  ```python
  """Shared generation contracts: the arm enum, the drill request/response dataclasses and the
  generator protocol every arm implements (design doc 7, 9.1; D03, D09, D10).

  Pure type definitions only: no database, no file and no mlx-lm import, so this module imports on
  Linux CI (CLAUDE.md: mlx-lm is Apple-Silicon-only; LLM-specific code lives in generation/llm/).
  DrillSpec is the request the GenerationService builds per participant/arm (its target_bigrams come
  from the frozen bigram_assignment rows, T2.2; empty for control). DrillCandidate is what a
  generator returns before validation -- it carries the text and the reproducibility/timing fields
  that map onto the drills/generation_attempts columns (section 8.1), but NO fairness metrics: the
  DrillValidator computes those, so a candidate can never report stale or self-measured numbers
  (owner answer 1). DrillGenerator is the one protocol control/heuristic/markov/llm all satisfy
  (9.1 "Every generator implements the same DrillGenerator protocol").
  """

  from dataclasses import dataclass, field
  from enum import StrEnum
  from typing import Protocol, runtime_checkable


  class Arm(StrEnum):
      """The four generated arms (D03); mirrors models.drills.DRILL_ARMS. CONTROL has no targets."""

      CONTROL = "control"
      HEURISTIC = "heuristic"
      MARKOV = "markov"
      LLM = "llm"


  @dataclass(frozen=True)
  class DrillSpec:
      """One drill request (design doc 9.1). target_bigrams is empty for CONTROL; min_density and
      max_density are the d_min/d_max range the validator enforces for targeted arms; length_chars is
      the target length the generator aims for (the validator's floor is a separate config key). seed
      makes generation reproducible (determinism, 13.1)."""

      participant_id: str
      arm: Arm
      target_bigrams: tuple[str, ...]  # empty for CONTROL
      length_chars: int = 300
      min_density: float = 0.15
      max_density: float = 0.40
      seed: int = 0


  @dataclass(frozen=True)
  class DrillCandidate:
      """A generator's output before validation (owner answer 1). text is the cleaned a-z+space drill
      the generator hands to the validator; raw_output equals text for non-LLM arms and is the
      model's pre-clean output for the LLM arm. generator_version and seed are the reproducibility
      fields; model_id/prompt_version are LLM-only (None otherwise); gen_ms/gen_tokens/
      tokens_per_sec/peak_memory_mb are the LLM timing/memory metrics (None for non-LLM arms). Carries
      NO fairness metrics -- the validator computes those."""

      text: str
      raw_output: str
      generator_version: str
      seed: int
      model_id: str | None = None
      prompt_version: str | None = None
      gen_ms: float | None = None
      gen_tokens: int | None = None
      tokens_per_sec: float | None = None
      peak_memory_mb: float | None = None


  @runtime_checkable
  class DrillGenerator(Protocol):
      """The contract every arm implements (design doc 9.1). arm identifies the arm; version is the
      generator_version stamped onto drills/attempts; generate turns a spec into one candidate."""

      arm: Arm
      version: str

      def generate(self, spec: DrillSpec) -> DrillCandidate: ...
  ```

- Exact change — full file. Operators are exact: `too_short` when `len(text) < drill_min_length_chars`
  (strict); `density_low` when `density < spec.min_density` (strict, so exactly d_min passes);
  `density_high` when `density > spec.max_density` (strict, so exactly d_max passes); `coverage` when
  any target count `< drill_min_coverage`; `word_repeat` when `max_word_count > drill_max_word_repeats`
  (strict, so exactly 3 passes); `bigram_repeat` when `bigram_run >= drill_max_bigram_run` (so run 2
  passes, run 3 rejects — owner answer 7); `real_word_ratio` gate only when `spec.arm is Arm.LLM` and

  is empty. Reasons collected in `RejectReason` definition order.
  ```python
  """The single fairness gate for every generated drill (design doc 9.1, 13.1; D13, D16).

  validate is a pure function: it measures one candidate text against its DrillSpec and a
  ValidatorConfig, collects EVERY failing rule (never stops at the first; the rejection-rate report
  needs the full taxonomy, section 8.1), and returns the recorded fairness metrics alongside the
  verdict. It never mutates text (cleaning is the generator's job, owner answer 6) and never raises
  on generator output (owner answer 9). It reuses the one project bigram definition
  (count_bigrams/word_bigrams; CLAUDE.md, D13) and so can run on Linux CI (no mlx-lm). The density
  bounds come from the spec (min_density/max_density); the length floor, coverage/repeat limits and
  the real-word-ratio threshold come from config, never as literals (section 17.1). Density and
  coverage are skipped when the spec has no targets (control; owner answer 4). The real-word ratio is
  recorded for every arm but gates only the LLM arm (13.1). load_validator_config reads the six keys
  from experiment_config, following assignment.py's loader pattern.
  """

  from collections.abc import Collection
  from dataclasses import dataclass
  from enum import StrEnum

  from sqlmodel import Session

  from typist.corpus.word_index import count_bigrams, word_bigrams
  from typist.generation.base import Arm, DrillSpec
  from typist.models import ExperimentConfig


  class RejectReason(StrEnum):
      """The reason tokens stored in generation_attempts.reject_reasons (owner answer 2). The order
      here is the order reasons appear in a ValidationResult."""

      TOO_SHORT = "too_short"
      BAD_CHARSET = "bad_charset"
      DENSITY_LOW = "density_low"
      DENSITY_HIGH = "density_high"
      COVERAGE = "coverage"
      WORD_REPEAT = "word_repeat"
      BIGRAM_REPEAT = "bigram_repeat"
      REAL_WORD_RATIO = "real_word_ratio"


  class MissingConfigError(LookupError):
      """An experiment_config key the validator needs is absent (run migrations)."""


  @dataclass(frozen=True)
  class ValidatorConfig:
      """The experiment_config values the validator needs (owner answer 5; migration 0006). The
      density bounds are NOT here -- they live on the DrillSpec."""

      min_length_chars: int
      min_coverage: int
      max_word_repeats: int
      max_bigram_run: int
      min_real_word_ratio: float


  @dataclass(frozen=True)
  class DrillMetrics:
      """The measured metrics for one candidate (owner answer 2). target_density, mean_word_len and
      real_word_ratio are recorded on drills; length_chars/coverage/max_word_count/bigram_run drive
      the rules. For a targetless spec target_density is 0.0 and coverage is empty."""

      length_chars: int
      target_density: float
      mean_word_len: float
      real_word_ratio: float
      coverage: dict[str, int]
      max_word_count: int
      bigram_run: int


  @dataclass(frozen=True)
  class ValidationResult:
      """The validator's verdict (owner answer 2). accepted is True iff reasons is empty; reasons is
      in RejectReason definition order; metrics is always populated."""

      accepted: bool
      reasons: tuple[RejectReason, ...]
      metrics: DrillMetrics


  _VALIDATOR_CONFIG_KEYS = (
      "drill_min_length_chars",
      "drill_min_coverage",
      "drill_max_word_repeats",
      "drill_max_bigram_run",
      "drill_min_real_word_ratio",
  )


  def _charset_ok(text: str) -> bool:
      """True iff text is non-empty, is only a-z and single spaces, and has no leading/trailing or
      doubled space (13.1 "Lowercase a to z and single spaces only"; owner answer 6)."""
      if not text:
          return False
      if text[0] == " " or text[-1] == " " or "  " in text:
          return False
      return all("a" <= char <= "z" or char == " " for char in text)


  def _longest_bigram_run(text: str) -> int:
      """The longest run of the same bigram at consecutive letter positions within one word, counting
      the same bigram starting at every other position (owner answer 7). "thth" -> 2, "ththth" -> 3;
      never across a space. 0 when no word has a bigram."""
      longest = 0
      for word in text.split(" "):
          bigrams = word_bigrams(word)
          for start in range(len(bigrams)):
              run = 1
              index = start
              while index + 2 < len(bigrams) and bigrams[index + 2] == bigrams[start]:
                  run += 1
                  index += 2
              longest = max(longest, run)
      return longest


  def _metrics(
      text: str, spec: DrillSpec, known_words: Collection[str]
  ) -> DrillMetrics:
      """Measure one candidate. Density is Σ(target bigram occurrences) / all letter-letter bigrams
      (owner answer 4), 0.0 when there are no targets or no bigrams. words are the NON-empty
      space-split tokens -- empty tokens produced by a leading/trailing/doubled space are not words
      (revision R1), so whitespace-only text has zero words. mean_word_len and real_word_ratio are
      over words and are 0.0 when there are no words (never raise; owner answer 9). Uses
      count_bigrams/word_bigrams only."""
      counts = count_bigrams(text)
      total = sum(counts.values())
      coverage = {bigram: counts.get(bigram, 0) for bigram in spec.target_bigrams}
      target_occurrences = sum(coverage.values())
      density = (
          target_occurrences / total if spec.target_bigrams and total > 0 else 0.0
      )
      words = [token for token in text.split(" ") if token]
      mean_word_len = sum(len(word) for word in words) / len(words) if words else 0.0
      real_word_ratio = (
          sum(1 for word in words if word in known_words) / len(words)
          if words
          else 0.0
      )
      max_word_count = max((words.count(word) for word in set(words)), default=0)
      return DrillMetrics(
          length_chars=len(text),
          target_density=density,
          mean_word_len=mean_word_len,
          real_word_ratio=real_word_ratio,
          coverage=coverage,
          max_word_count=max_word_count,
          bigram_run=_longest_bigram_run(text),
      )


  def validate(
      text: str,
      spec: DrillSpec,
      config: ValidatorConfig,
      known_words: Collection[str],
  ) -> ValidationResult:
      """Measure text and collect every failing rule (never stop at the first; owner answer 2).

      Rules (13.1, D16): too_short when len(text) < config.min_length_chars; bad_charset when text is
      empty or has anything but a-z and single spaces, or a leading/trailing/doubled space; for a
      targeted spec, density_low/density_high when the single density is below spec.min_density or
      above spec.max_density (bounds inclusive), and coverage when any target occurs fewer than
      config.min_coverage times; word_repeat when any token occurs more than config.max_word_repeats
      times; bigram_repeat when the longest bigram run reaches config.max_bigram_run (owner answer 7);
      real_word_ratio only for Arm.LLM when the ratio is below config.min_real_word_ratio. Density and
      coverage are skipped when spec.target_bigrams is empty (owner answer 4/8). Pure: no DB, never
      raises. known_words is any membership collection (the service passes WordIndex.words).
      """
      metrics = _metrics(text, spec, known_words)
      reasons: list[RejectReason] = []
      if metrics.length_chars < config.min_length_chars:
          reasons.append(RejectReason.TOO_SHORT)
      if not _charset_ok(text):
          reasons.append(RejectReason.BAD_CHARSET)
      if spec.target_bigrams:
          if metrics.target_density < spec.min_density:
              reasons.append(RejectReason.DENSITY_LOW)
          if metrics.target_density > spec.max_density:
              reasons.append(RejectReason.DENSITY_HIGH)
          if any(count < config.min_coverage for count in metrics.coverage.values()):
              reasons.append(RejectReason.COVERAGE)
      if metrics.max_word_count > config.max_word_repeats:
          reasons.append(RejectReason.WORD_REPEAT)
      if metrics.bigram_run >= config.max_bigram_run:
          reasons.append(RejectReason.BIGRAM_REPEAT)
      if spec.arm is Arm.LLM and metrics.real_word_ratio < config.min_real_word_ratio:
          reasons.append(RejectReason.REAL_WORD_RATIO)
      return ValidationResult(
          accepted=not reasons, reasons=tuple(reasons), metrics=metrics
      )


  def load_validator_config(session: Session) -> ValidatorConfig:
      """Read the five validator keys from experiment_config; raise MissingConfigError if any is
      absent (run migrations). Four are integers; drill_min_real_word_ratio is a float. (The sixth
      seeded key, drill_length_chars, is read by the GenerationService for DrillSpec.length_chars, not
      by the validator.)"""
      values: dict[str, str] = {}
      for key in _VALIDATOR_CONFIG_KEYS:
          row = session.get(ExperimentConfig, key)
          if row is None:
              raise MissingConfigError(key)
          values[key] = row.value
      return ValidatorConfig(
          min_length_chars=int(values["drill_min_length_chars"]),
          min_coverage=int(values["drill_min_coverage"]),
          max_word_repeats=int(values["drill_max_word_repeats"]),
          max_bigram_run=int(values["drill_max_bigram_run"]),
          min_real_word_ratio=float(values["drill_min_real_word_ratio"]),
      )
  ```

  import pytest
  from sqlalchemy import Engine
  from sqlmodel import Session

      max_word_repeats=3,
      max_bigram_run=3,

          "min_coverage": _DEFAULT_CONFIG.min_coverage,
          "max_word_repeats": _DEFAULT_CONFIG.max_word_repeats,
          "max_bigram_run": _DEFAULT_CONFIG.max_bigram_run,
          "min_real_word_ratio": _DEFAULT_CONFIG.min_real_word_ratio,

      return ValidatorConfig(**values)  # type: ignore[arg-type]


  def _spec(arm: Arm, targets: tuple[str, ...], *, min_density: float = 0.15,

      assert result.reasons == (RejectReason.TOO_SHORT,)
      assert result.metrics.length_chars == 11
      assert result.accepted is False

      assert result.metrics.coverage == {"th": 3}
