# T3.5 Plan — Freeze experiment_config

## 1. Summary

This plan locks all 33 seeded parameters in `experiment_config` ahead of the pre-registered analysis plan in T3.6 and the 10-day pilot.
It introduces Alembic migration `0012_freeze_config.py`, which sets `frozen_at = '2026-10-29 00:00:00'` for all seeded keys and installs SQLite `BEFORE UPDATE` and `BEFORE DELETE` triggers that reject changes with `RAISE(ABORT, 'experiment_config keys are frozen')` (`sqlite3.IntegrityError`).
A dedicated integration test suite `test_migration_0012.py` validates that frozen keys cannot be updated, deleted, or unfrozen, while unfrozen probe keys remain mutable, and proves a clean downgrade path to `0011_calibrate_density`.
Schema and migration suites (`test_schema.py`, `test_migrations.py`, `test_migration_0011.py`, `test_migration_0010.py`, `test_migration_0009.py`) are aligned with the new revision and frozen state.

## 2. Design

### Context & Problem
In Typist-ML, the randomized controlled trial evaluates 4 arms within-person across Days 2 to 11 (D01, §3.2). Background generation workers and session planners rely on configuration values in `experiment_config` (such as `d_min`, `d_max`, `llm_temperature`, `llm_model_id`, `assignment_seed`, `markov_beta`, and validator limits).
Task T3.6 commits the dated analysis plan (`docs/analysis-plan.md`) before practice starts (D20, §16). To prevent outcome-shopping, configuration drift, or accidental parameter adjustments during the trial, `experiment_config` must be frozen at the database engine level (Acceptance Criteria: *"Frozen keys reject changes"*).

### Enforcement Mechanism: SQLite Triggers via Alembic Migration
1. **Deterministic timestamp:** All 33 seeded keys across migrations 0001 through 0011 have their `frozen_at` column set to `'2026-10-29 00:00:00'` (Owner Answer 1 & 4). Deterministic dates avoid clock skew and ensure reproducible test assertions.
2. **Two dedicated triggers:**
   - `trg_experiment_config_frozen_update`: `BEFORE UPDATE ON experiment_config WHEN OLD.frozen_at IS NOT NULL BEGIN SELECT RAISE(ABORT, 'experiment_config keys are frozen'); END`
   - `trg_experiment_config_frozen_delete`: `BEFORE DELETE ON experiment_config WHEN OLD.frozen_at IS NOT NULL BEGIN SELECT RAISE(ABORT, 'experiment_config keys are frozen'); END`
   This mirrors the precedent established in migration 0005 (`trg_bigram_assignment_frozen`, D04). Any attempt to `UPDATE` (including changing `value` or resetting `frozen_at = NULL`) or `DELETE` a frozen key is aborted inside SQLite and surfaces in Python as `sqlite3.IntegrityError` (Owner Answers 2 & 3).
3. **Downgrade ordering:** In `downgrade()`, both triggers must be dropped via `DROP TRIGGER IF EXISTS` *before* executing `UPDATE experiment_config SET frozen_at = NULL`; otherwise the update trigger would abort the downgrade.
4. **Test suite alignment:**
   - `test_schema.py` line 364 asserts `frozen_at == '2026-10-29 00:00:00'` for all seeded keys at HEAD.
   - `test_migrations.py` bumps `HEAD = "0012_freeze_config"` and `down_revision = "0012_freeze_config"` in `PROBE_REBUILD_REVISION`.
   - Migration tests (`test_migration_0011.py`, `test_migration_0010.py`, `test_migration_0009.py`) check the database state produced by `migrated_engine` (which runs `upgrade_to_head()`). Their assertions on `frozen_at` are updated to expect `'2026-10-29 00:00:00'` at HEAD.

### Alternatives Considered and Rejected
- *Python application-level validation only (in SQLModel or FastAPI):* Rejected in one line: bypassed by raw SQL, background workers, or administrative scripts; does not guarantee immutable RCT parameters.
- *Single UPDATE trigger only (no DELETE trigger):* Rejected in one line: allows frozen rows to be dropped via `DELETE FROM experiment_config`, catastrophically destroying experiment configuration.
- *CLI command to trigger the freeze at runtime:* Rejected in one line: Owner Answer 5 clarifies that migration 0012 is the sole mechanism; the freeze occurs at Milestone 3 completion before pre-registering the analysis plan.
- *Dynamic timestamp (`CURRENT_TIMESTAMP`):* Rejected in one line: creates non-deterministic timestamps across test runs and environments, breaking equality assertions.

```python
"""freeze config: set frozen_at on all 33 seeded keys and install immutability triggers (T3.5).

Revision ID: 0012_freeze_config
Revises: 0011_calibrate_density
Create Date: 2026-10-29 00:00:00.000000

Data-and-trigger migration. Sets frozen_at = '2026-10-29 00:00:00' for all 33 seeded keys in
experiment_config (design doc §8.1, §16; ADR D04, D20; T3.5 owner answers 1-4). Installs two
BEFORE triggers on experiment_config (trg_experiment_config_frozen_update and
trg_experiment_config_frozen_delete) that abort any UPDATE or DELETE of a row whose frozen_at is
NOT NULL with RAISE(ABORT, 'experiment_config keys are frozen'), surfacing in Python as
sqlite3.IntegrityError. Downgrade drops the two triggers first, then resets frozen_at = NULL.
"""

from collections.abc import Sequence

import sqlalchemy as sa
from alembic import op

# revision identifiers, used by Alembic.
revision: str = "0012_freeze_config"
down_revision: str | Sequence[str] | None = "0011_calibrate_density"
branch_labels: str | Sequence[str] | None = None
depends_on: str | Sequence[str] | None = None

FROZEN_AT_TIMESTAMP = "2026-10-29 00:00:00"

_config_table = sa.table(
    "experiment_config",
    sa.column("key", sa.String()),
    sa.column("value", sa.Text()),
    sa.column("frozen_at", sa.DateTime()),
)

_CREATE_UPDATE_TRIGGER = (
    "CREATE TRIGGER trg_experiment_config_frozen_update "
    "BEFORE UPDATE ON experiment_config "
    "WHEN OLD.frozen_at IS NOT NULL "
    "BEGIN SELECT RAISE(ABORT, 'experiment_config keys are frozen'); END"
)

_CREATE_DELETE_TRIGGER = (
    "CREATE TRIGGER trg_experiment_config_frozen_delete "
    "BEFORE DELETE ON experiment_config "
    "WHEN OLD.frozen_at IS NOT NULL "
    "BEGIN SELECT RAISE(ABORT, 'experiment_config keys are frozen'); END"
)


def upgrade() -> None:
    """Freeze all seeded keys and install UPDATE and DELETE immutability triggers."""
    op.execute(f"UPDATE experiment_config SET frozen_at = '{FROZEN_AT_TIMESTAMP}'")
    op.execute(_CREATE_UPDATE_TRIGGER)
    op.execute(_CREATE_DELETE_TRIGGER)


def downgrade() -> None:
    """Drop the triggers first, then unfreeze all keys."""
    op.execute("DROP TRIGGER IF EXISTS trg_experiment_config_frozen_update")
    op.execute("DROP TRIGGER IF EXISTS trg_experiment_config_frozen_delete")
    op.execute("UPDATE experiment_config SET frozen_at = NULL")
```

Full code for `services/api/tests/integration/test_migration_0012.py`:
```python
"""Migration 0012 freezes all 33 experiment_config keys and installs immutability triggers (T3.5)."""

import sqlite3
from contextlib import closing
from pathlib import Path

import pytest
from alembic import command
from sqlalchemy import Engine

from typist.migrations import alembic_config

EXPECTED_FROZEN_AT = "2026-10-29 00:00:00"
EXPECTED_SEEDED_KEYS_COUNT = 33
UPDATE_TRIGGER = "trg_experiment_config_frozen_update"
DELETE_TRIGGER = "trg_experiment_config_frozen_delete"


def _triggers(db_path: Path) -> set[str]:
    with closing(sqlite3.connect(db_path)) as connection:
        rows = connection.execute(
            "SELECT name FROM sqlite_master WHERE type = 'trigger'"
        ).fetchall()
    return {row[0] for row in rows}


def test_0012_freezes_all_seeded_keys(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """All 33 seeded keys have frozen_at set to '2026-10-29 00:00:00' and both triggers exist."""
    with closing(sqlite3.connect(isolated_settings)) as connection:
        rows = connection.execute(
            "SELECT key, frozen_at FROM experiment_config"
        ).fetchall()
    assert len(rows) == EXPECTED_SEEDED_KEYS_COUNT
    for key, frozen_at in rows:
        assert frozen_at == EXPECTED_FROZEN_AT, f"key {key} was not frozen"

    triggers = _triggers(isolated_settings)
    assert UPDATE_TRIGGER in triggers
    assert DELETE_TRIGGER in triggers


def test_0012_blocks_update_of_a_frozen_key(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """Updating a frozen key aborts with sqlite3.IntegrityError; value remains unchanged."""
    migrated_engine.dispose()
    with closing(sqlite3.connect(isolated_settings)) as connection:
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "UPDATE experiment_config SET value = '999' WHERE key = 'practice_days'"
            )
        row = connection.execute(
            "SELECT value, frozen_at FROM experiment_config WHERE key = 'practice_days'"
        ).fetchone()
        assert row is not None
        assert row[0] == "10"
        assert row[1] == EXPECTED_FROZEN_AT

        # Also verify d_min cannot be updated
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "UPDATE experiment_config SET value = '0.25' WHERE key = 'd_min'"
            )
        row_dmin = connection.execute(
            "SELECT value FROM experiment_config WHERE key = 'd_min'"
        ).fetchone()
        assert row_dmin is not None
        assert row_dmin[0] == "0.1"


def test_0012_blocks_delete_of_a_frozen_key(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """Deleting a frozen key aborts with sqlite3.IntegrityError; row remains intact."""
    migrated_engine.dispose()
    with closing(sqlite3.connect(isolated_settings)) as connection:
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "DELETE FROM experiment_config WHERE key = 'assignment_seed'"
            )
        row = connection.execute(
            "SELECT value, frozen_at FROM experiment_config WHERE key = 'assignment_seed'"
        ).fetchone()
        assert row is not None
        assert row[0] == "20261021"


def test_0012_blocks_unfreezing_a_frozen_key(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """Attempting to unfreeze a key by setting frozen_at = NULL triggers RAISE(ABORT)."""
    migrated_engine.dispose()
    with closing(sqlite3.connect(isolated_settings)) as connection:
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "UPDATE experiment_config SET frozen_at = NULL WHERE key = 'llm_model_id'"
            )
        row = connection.execute(
            "SELECT frozen_at FROM experiment_config WHERE key = 'llm_model_id'"
        ).fetchone()
        assert row is not None
        assert row[0] == EXPECTED_FROZEN_AT


def test_0012_allows_insert_and_update_of_unfrozen_key(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """Unfrozen rows (frozen_at IS NULL) can be inserted, modified, and deleted freely."""
    migrated_engine.dispose()
    with closing(sqlite3.connect(isolated_settings)) as connection:
        connection.execute(
            "INSERT INTO experiment_config (key, value, frozen_at) VALUES ('probe_key', '\"initial\"', NULL)"
        )
        connection.commit()

        # Update succeeds on unfrozen row
        connection.execute(
            "UPDATE experiment_config SET value = '\"updated\"' WHERE key = 'probe_key'"
        )
        connection.commit()
        val = connection.execute(
            "SELECT value FROM experiment_config WHERE key = 'probe_key'"
        ).fetchone()[0]
        assert val == '"updated"'

        # Freezing the probe key succeeds
        connection.execute(
            f"UPDATE experiment_config SET frozen_at = '{EXPECTED_FROZEN_AT}' WHERE key = 'probe_key'"
        )
        connection.commit()

        # Now that it is frozen, update aborts
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "UPDATE experiment_config SET value = '\"blocked\"' WHERE key = 'probe_key'"
            )

        # And delete aborts
        with pytest.raises(sqlite3.IntegrityError, match="experiment_config keys are frozen"):
            connection.execute(
                "DELETE FROM experiment_config WHERE key = 'probe_key'"
            )


def test_downgrade_0012_drops_triggers_and_resets_frozen_at(
    isolated_settings: Path, migrated_engine: Engine
) -> None:
    """Downgrade to 0011 drops triggers, resets frozen_at to None, and allows updates."""
    migrated_engine.dispose()
    command.downgrade(alembic_config(), "0011_calibrate_density")
    triggers = _triggers(isolated_settings)
    assert UPDATE_TRIGGER not in triggers
    assert DELETE_TRIGGER not in triggers

    with closing(sqlite3.connect(isolated_settings)) as connection:
        rows = connection.execute(
            "SELECT key, frozen_at FROM experiment_config"
        ).fetchall()
        assert len(rows) == EXPECTED_SEEDED_KEYS_COUNT
        assert all(frozen_at is None for _, frozen_at in rows)

        # Updates succeed when unfrozen post-downgrade
        connection.execute(
            "UPDATE experiment_config SET value = '99' WHERE key = 'practice_days'"
        )
        connection.commit()
        val = connection.execute(
            "SELECT value FROM experiment_config WHERE key = 'practice_days'"
        ).fetchone()[0]
        assert val == "99"
```
