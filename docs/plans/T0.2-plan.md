## 1. Summary

When this plan is done, `apps/web/` is a Vite 8 + React 19 + TypeScript (strict,
`noUncheckedIndexedAccess`, `noImplicitOverride`, `noEmit`) app with Tailwind CSS v4, Biome 2 and
Vitest, all pinned to exact versions, with a committed `apps/web/pnpm-lock.yaml`, the section-7
`src/` skeleton, a minimal placeholder page and one Vitest test file for a real pure function
(`apiPath`). `just test` runs that test. `just check` now runs `biome ci .` and a new `build` step
(`vite build`), D21 is amended to match, `just dev` is proven to leave nothing on port 5173 after
Ctrl-C, and the README, `.nvmrc` and `scripts/cloud-setup.sh` pin Node and pnpm.

## 2. Design

- **Standalone pnpm project in `apps/web`** (no root workspace). The lockfile stays at
  `apps/web/pnpm-lock.yaml`, which is where the README, the pre-commit comment and
  `scripts/cloud-setup.sh` already expect it.
- **Files are written by hand, not by `pnpm create vite`.** Every config and source file is given
  in full below. Dependencies are added with `pnpm add -E <pkg>@^<major>`. pnpm picks the highest
  stable version inside that major and writes it without `^`. That meets owner answer 11 (exact
  versions) and needs no judgement at build time. A preflight step checks that each package's
  `latest` dist-tag is in the major this plan assumes, and the builder stops if one is not.
- **Majors:** vite 8, react/react-dom 19, tailwindcss and @tailwindcss/vite 4, @vitejs/plugin-react
  6 (design doc 19.1), typescript 6 (the current stable line; the TS 7 native preview is excluded
  by owner answer 13), @biomejs/biome 2, vitest 4, @types/react and @types/react-dom 19,
  @types/node 22 (to match Node 22). `@types/node` is the only package outside the title's list.
  T0.2 needs it because `tsconfig.node.json` type-checks `vite.config.ts`, and Vite's type
  definitions reference Node types (owner answer 1: extra packages only where T0.2 needs them).
- **TypeScript:** three files, as in Vite's own React template: a solution `tsconfig.json`
  (`files: []`) that references `tsconfig.app.json` (checks `src/`) and `tsconfig.node.json`
  (checks `vite.config.ts`). Both set `noEmit`, and both put `.tsbuildinfo` under
  `node_modules/.tmp/`, which is already gitignored. So `.gitignore` does not change.
- **Vitest config goes inside `vite.config.ts`.** It uses `/// <reference types="vitest/config" />`
  with Vite's own `defineConfig`, which avoids a type mismatch between Vite's and Vitest's plugin
  types. `test.include` is `src/**/*.test.{ts,tsx}`, so a later Playwright file in `e2e/` is never
  picked up. The environment is `node`; per owner answer 5 there is no DOM environment yet.
- **The test target is `apiPath(endpoint)` in `src/api/paths.ts`.** It builds the same-origin path
  `/api/v1<endpoint>` (design doc section 14) that the Vite proxy forwards to the API. It is a real,
  small, pure function, and later tasks will use it for the client. The placeholder page shows
  `API_BASE`.
- **Dev server:** `127.0.0.1:5173`, `strictPort: true`, and a proxy `/api` → `http://127.0.0.1:8000`
  (owner answer 16). No CORS is needed in development.
- **Biome 2:** `apps/web/biome.json` with a 2-space indent, double quotes, semicolons always, line
  width 100, the recommended rules plus the whole a11y group at error, and `noExplicitAny` at
  error. Suppression comments state a reason. Imports are organised. VCS integration is on, with
  `vcs.root` set to `../..` so the repo-root `.gitignore` is read (for example, `dist/` is skipped).
  The config sits in `apps/web`, so no Biome run can reach `services/`, where the golden fixture
  lives.
- **Gate changes (owner answers 8 and 14):** the web part of `just lint` becomes
  `pnpm exec biome ci .`, which runs the same lint, format and import-order checks the pre-commit
  hook's `biome check --write` fixes. `format-check` is left as it is. A new `build` recipe runs
  `pnpm exec vite build`, and `check` becomes `lint format-check types test build`. The D21 row
  is amended in place, as the owner instructed.
- **`just dev` Ctrl-C:** first test the current recipe with a real process-group SIGINT. Change
  the recipe only if Vite survives. The fix is to exec Vite's bin shim directly
  (`exec ./node_modules/.bin/vite`), so the PID the recipe kills is the Vite node process itself,
  and Vite handles SIGTERM.
- Rejected: a root `pnpm-workspace.yaml`, because it would move the lockfile to the repo root and
  contradict the README and cloud-setup.
- Rejected: `vitest.config.ts` as a separate file, because it duplicates the plugin setup and adds
  one more file to type-check.
- Rejected: pnpm `supportedArchitectures`, because pnpm lockfiles already record every platform's
  optional binaries. Step 3 checks this.

`apps/web/src/api/paths.ts`:
```ts
/** Base path of the Typist-ML HTTP API (design doc section 14). In dev, Vite proxies it to 127.0.0.1:8000. */
export const API_BASE = "/api/v1";

/**
 * Returns the same-origin URL path for an API endpoint, for example
 * `apiPath("/health")` → `"/api/v1/health"`.
 *
 * @param endpoint Path below the API base. Must start with "/".
 * @throws RangeError if `endpoint` does not start with "/".
 */
export function apiPath(endpoint: string): string {
  if (!endpoint.startsWith("/")) {
    throw new RangeError(`API endpoint must start with "/": ${JSON.stringify(endpoint)}`);
  }
  return `${API_BASE}${endpoint}`;
}
```
