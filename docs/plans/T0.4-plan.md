## 1. Summary

- `.github/workflows/ci.yml` runs two independent jobs named exactly `web` and `api` on pull
  requests to `main`, pushes to `main` and `workflow_dispatch`. `web` runs the D21 web commands.
  `api` runs the D21 API commands, then bandit and semgrep, and semgrep fails instead of skipping.
- `codeql.yml` is cleaned up, SHA-pinned and extended to `python` and `javascript-typescript`
  with `security-extended`. A weekly, non-required `audit.yml` runs pip-audit and pnpm audit.
  Dependabot updates the pinned actions.
- The repo gains `just check-web` / `just check-api`, an actionlint pre-commit hook, the Biome
  preset fix, `scripts/github-ruleset.json` (no bypass actors), D21/D22 amendments, and a README
  CI section with a badge.
- Done when the squash-merge commit on `main` has a green `ci.yml` run (owner-run RESUME D). The
  ruleset is applied after that (RESUME E).

## 2. Design

- **Two jobs, two contexts (answers 3, 9, 12, 17).**
  - Job keys and `name:` are both `web` and `api`, so the check-run names match the ruleset's
    contexts exactly.
  - No matrix, no `needs`, no `if`, no path filters, `runs-on: ubuntu-latest`,
    `timeout-minutes: 10`.
  - Triggers: `pull_request` and `push`, both with `branches: [main]`, plus `workflow_dispatch`.
    A PR head commit therefore gets exactly one `web` and one `api` check run.
- **Per-app commands, not `just check` (answers 4, 5).**
  - Each job runs D21's commands in D21's order, one step per command, so the log shows which
    one failed.
  - The new recipes `check-web` and `check-api` hold the same command lists. Check W (step 5)
    compares `ci.yml` against them, so drift is caught before commit.
  - `check` itself is unchanged.
- **Concurrency (answer 10 and its note).**
  - The owner's form `ci-${{ github.ref }}` with `cancel-in-progress: true` for PRs and branches
    is kept.
  - On `main`, GitHub replaces a *pending* run in the same group even when `cancel-in-progress`
    is false, and that would drop a `main` run. So on `main` the group gets the run id:
    `ci-${{ github.ref == 'refs/heads/main' && github.run_id || github.ref }}`. The conditional
    `cancel-in-progress` from the note is kept as well. The owner confirms this at the gate
    (Review focus 1).
- **Node and pnpm (answers 13, 15 and the note).**
  - `actions/setup-node` reads `.nvmrc`. Then `corepack enable` runs in `apps/web`, where
    `packageManager` lives, and a check fails the step unless `pnpm@$(pnpm --version)` equals
    `packageManager`.
  - A second `actions/setup-node` call then turns on `cache: pnpm` with
    `cache-dependency-path: apps/web/pnpm-lock.yaml`. It has to come after corepack, because
    setup-node runs `pnpm store path` (in the lockfile's directory) and pnpm must exist by then.
  - Install: `pnpm install --frozen-lockfile`.
  - Rejected: `pnpm/action-setup`, because the owner chose corepack. Also rejected: a hand-rolled
    `actions/cache` for the store, because the owner chose setup-node's cache.
- **uv and Python (answers 13, 15, 22 and the note).**
  - `astral-sh/setup-uv` with `version: "0.12.18"`, `enable-cache: true`, and
    `cache-dependency-glob: services/api/uv.lock`.
  - `UV_PYTHON_PREFERENCE=only-managed`: uv downloads its own 3.12, the version `requires-python`
    and `uv.lock` allow. `.python-version` is gitignored.
  - `UV_PROJECT_ENVIRONMENT=.venv` pins the venv explicitly; uv resolves a relative path against
    the project root, which gives `services/api/.venv`. A `test -x .venv/bin/ruff` guard proves
    the location for pyright and the Alembic hooks.
  - `uv sync --locked` with no extras, so it stays valid when T0.5 adds the `mlx` extra.
- **pyright (answers 14, 15).** The `api` job also runs setup-node from `.nvmrc`, so the PyPI
  wrapper uses that node. `actions/cache` keeps `~/.cache/pyright-python`, keyed on `uv.lock`. If
  the wrapper uses a different directory, the only effect is a cache miss.
- **Security in CI (answers 6, 7 and the note).**
  - The `api` job runs bandit exactly as `security-py` does (`-q -r src -ll`).
  - It then installs just 1.58.0 and semgrep at `just --evaluate semgrep_version`. The justfile
    stays the only pin: CI reads it and adds no fourth copy.
  - semgrep runs from the repo root with D22's flags. There is no reachability probe: a version
    mismatch or a ruleset that can't be downloaded fails the job. This differs from the local
    `security` recipe, so D22 gets a dated amendment.
  - pip-audit and `pnpm audit` run only in `.github/workflows/audit.yml` (weekly plus manual,
    job `audit`, not required). It calls `just security-py` and `just security-web`, so D22's
    skip rules apply unchanged there, which the owner accepted.
  - Rejected: an audit job inside `ci.yml`, because it would add a schedule trigger and skipped
    checks to every PR.
- **Pinning (answer 11).**
  - Every `uses:` is `owner/repo[/path]@<40-hex SHA> # vX.Y.Z`. The SHAs and tags come only from
    the owner's preflight (RESUME A); the builder never guesses one.
  - Publishers are limited to `actions`, `github` and `astral-sh`, and Check W enforces this.
  - `.github/dependabot.yml` updates `github-actions` only, weekly, with `chore(deps)` commit
    messages.
  - `persist-credentials: false` is set on every checkout, because no job pushes.
- **CodeQL (answers 16, 18, 19).**
  - Template comments are removed, so the file is ASCII only.
  - Matrix: `actions`, `javascript-typescript` and `python`, all with `build-mode: none`.
  - `queries: security-extended`. The job-level permissions are kept, including `packages: read`
    and `actions: read`.
  - The weekly schedule stays, and `timeout-minutes: 10` is set (answer 17 read as "per job").
  - Default setup is disabled in RESUME C if the preflight shows it is on.
- **actionlint (answer 24; T0.1 answer 7 wants project-pinned binaries).**
  - actionlint is a Go binary with no npm or uv.lock-native form in this repo. It is installed
    with `uv tool install actionlint-py==<ACTIONLINT_PY>`, the same pattern as semgrep.
  - The hook script `scripts/pre-commit-actionlint.sh` pins the binary version and fails on a
    missing or different actionlint.
  - **Trade-off, stated plainly:** the pin is a string checked at run time, not a hash in a
    lockfile. The rejected alternative was to add `actionlint-py` to the `services/api` dev group
    (hash-locked). That would mix a repo-wide tool into the API lockfile and force another owner
    `uv lock`/`uv sync` round.
  - shellcheck and pyflakes integration is turned off (`-shellcheck= -pyflakes=`), so the result
    doesn't depend on which other tools a machine happens to have.
- **Ruleset (answer 1).**
  - The JSON moves out of the heredoc into `scripts/github-ruleset.json` with
    `"bypass_actors": []`, and `bootstrap-github.sh` reads it.
  - The owner applies the same file with `gh api` as the task's last step (RESUME E). That comes
    only after `web` and `api` have passed on the PR and on `main`.
- **Biome (answer 21).** `biome migrate --write` produces the owner's `"preset": "recommended"`
  change. It is verified by behaviour (the deprecation notice is gone), not by guessing the
  schema location.
- **Sandbox facts.**
  - Every commit is owner-run (protocol OC below).
  - Network checks happen at RESUME points: the preflight, the local gate (API pytest cannot run
    in the sandbox), the push, the PR and CI results, the merge, and the ruleset.
  - Offline checks run in the sandbox: biome, tsc, vitest, vite build, ruff, pyright via fallback
    F, `services/api/.venv/bin/python` with PyYAML (a bandit dependency), and actionlint.

- `<CODEQL_TAG>` / `<CODEQL_SHA>`: from `ACTION github/codeql-action ...`.
- `<ACTIONLINT_PY>`: the version on the `ACTIONLINT_PY` line.
- `<ACTIONLINT>`: the version on the `ACTIONLINT_BIN` line.
- `<TODAY>`: today's date, as `YYYY-MM-DD`.

**Sandbox rules.**
- Never use `dangerouslyDisableSandbox`. Never run `uv lock`, `uv add`, `uv sync`,
  `pnpm install`, `git commit`, `git push` or `gh`.
- RESUME points are owner-run. At each one, stop, hand over the exact block, and wait for the
  pasted output.
- **Fallback F.** If a `uv run` command fails with a uv cache or permission error:
  1. Re-run it with the prefix `env UV_CACHE_DIR="$TMPDIR/uvcache" UV_OFFLINE=1`.
  2. If it works, keep that prefix for every later `uv` command.
  3. If it still fails, stop and report the step, the command and the error.
- **actionlint in the sandbox.** If running `actionlint` fails for a sandbox reason (permission
  denied, not found although RESUME A printed a path), skip that test and note it in the report.
  The owner's commit (OC) runs the actionlint hook on staged workflow files, and a hook failure
  fails the commit.
- Never put a SHA or version into a file unless it came from the RESUME A output.

**Owner commit protocol OC-<N>** (the end of every step that changes files):
1. The builder stages exactly the files named in the step, then runs `git diff --cached --name-only`.
   The output must list exactly those files.
2. The builder writes the step's commit message, which is one line, followed by a newline, with:
   `printf '%s\n' '<message>' > "$TMPDIR/t04-step<N>-msg.txt"`. It then prints the absolute
   path with `printf '%s\n' "$TMPDIR/t04-step<N>-msg.txt"`.
3. Stop and ask the owner to run the following and paste the output:
   ```bash
   cd /Users/allen/Downloads/typist-ml/.claude/worktrees/typist-ml-overview-3379c6 && git commit -F '<absolute msg path>' && git log --oneline -1 && git status --porcelain --untracked-files=all
   ```
   If the owner's shell can't read that path, the owner runs `git commit -m '<message>'` with the
   message from the plan instead.
4. Expected: the log line shows the message, and the status output is empty.
   - If a hook changed files and the commit failed, the owner pastes `git diff`. If the diff is
     formatting only, the builder `git add`s the same files and repeats step 3 of OC.
   - If a hook failed without changing files, the builder compares the file with this plan. A
     builder typo is fixed to match the plan and OC is repeated. Anything else: stop and report.
- Never use `--no-verify`.

"""Check W (T0.4 plan): structure of the workflow and Dependabot files given as arguments."""

import re
import sys
from pathlib import Path
from typing import Any

import yaml

USES = re.compile(r"^\s*(?:- )?uses: (\S+)(.*)$")
PINNED = re.compile(r"^([A-Za-z0-9_.-]+)/[A-Za-z0-9_.-]+(?:/[A-Za-z0-9_.-]+)*@[0-9a-f]{40}$")
TAG_COMMENT = re.compile(r"^ # v[0-9]+\.[0-9]+\.[0-9]+$")
PUBLISHERS = {"actions", "github", "astral-sh"}
DEPENDABOT = {
    "version": 2,
    "updates": [
        {
            "package-ecosystem": "github-actions",
            "directory": "/",
            "schedule": {"interval": "weekly"},
            "commit-message": {"prefix": "chore", "include": "scope"},
        }
    ],
}
CONCURRENCY = {
    "group": "ci-${{ github.ref == 'refs/heads/main' && github.run_id || github.ref }}",
    "cancel-in-progress": "${{ github.ref != 'refs/heads/main' }}",
}
CODEQL_PERMISSIONS = {
    "security-events": "write",
    "packages": "read",
    "actions": "read",
    "contents": "read",
}
problems: list[str] = []


def check(ok: bool, message: str) -> None:
    if not ok:
        problems.append(message)


def load(path: Path) -> dict[Any, Any]:
    data: dict[Any, Any] = yaml.safe_load(path.read_text(encoding="utf-8"))
    if True in data:  # YAML 1.1 reads the key `on` as the boolean True
        data["on"] = data.pop(True)
    return data


def recipe(name: str, prefix: str) -> list[str]:
    lines = Path("justfile").read_text(encoding="utf-8").splitlines()
    commands: list[str] = []
    for line in lines[lines.index(f"{name}:") + 1 :]:
        if not line.strip():
            break
        if line.startswith("    " + prefix):
            commands.append(line.strip())
    return commands


def runs(job: dict[str, Any]) -> list[str]:
    return [str(step["run"]).strip() for step in job["steps"] if "run" in step]


for arg in sys.argv[1:]:
    path = Path(arg)
    text = path.read_text(encoding="utf-8")
    check(text.isascii(), f"{arg}: non-ASCII characters")
    data = load(path)
    if path.name == "dependabot.yml":
        check(data == DEPENDABOT, f"{arg}: content differs from the plan")
        continue
    for number, line in enumerate(text.splitlines(), start=1):
        match = USES.match(line)
        if match is None:
            continue
        ref, rest = match.group(1), match.group(2)
        pinned = PINNED.match(ref)
        check(pinned is not None, f"{arg}:{number}: not pinned to a full commit SHA: {ref}")
        check(TAG_COMMENT.match(rest) is not None, f"{arg}:{number}: needs a ' # vX.Y.Z' comment")
        if pinned is not None:
            check(pinned.group(1) in PUBLISHERS, f"{arg}:{number}: publisher not allowed: {ref}")
    for job_id, job in data["jobs"].items():
        check(isinstance(job.get("timeout-minutes"), int), f"{arg}: job {job_id} lacks timeout-minutes")
        for step in job["steps"]:
            run = str(step.get("run", ""))
            check("${{" not in run, f"{arg}: job {job_id}: expression inside run: {step.get('name')}")
        if path.name != "ci.yml":
            name = str(job.get("name", job_id))
            check(name not in {"web", "api"}, f"{arg}: job {job_id} reuses a required check name")
    if path.name == "ci.yml":
        on = data["on"]
        check(sorted(on) == ["pull_request", "push", "workflow_dispatch"], f"{arg}: triggers {sorted(on)}")
        check(on.get("pull_request") == {"branches": ["main"]}, f"{arg}: pull_request must be branches [main] only")
        check(on.get("push") == {"branches": ["main"]}, f"{arg}: push must be branches [main] only")
        check(data.get("permissions") == {"contents": "read"}, f"{arg}: permissions must be contents: read")
        check(data.get("concurrency") == CONCURRENCY, f"{arg}: concurrency differs from the plan")
        check(sorted(data["jobs"]) == ["api", "web"], f"{arg}: jobs are {sorted(data['jobs'])}")
        for job_id, job in data["jobs"].items():
            check(job.get("name") == job_id, f"{arg}: job {job_id} must be named {job_id}")
            check(job.get("runs-on") == "ubuntu-latest", f"{arg}: job {job_id} runs-on")
            check(job.get("timeout-minutes") == 10, f"{arg}: job {job_id} timeout must be 10")
            for key in ("strategy", "needs", "if", "continue-on-error"):
                check(key not in job, f"{arg}: job {job_id} must not use {key}")
        if sorted(data["jobs"]) == ["api", "web"]:
            web = runs(data["jobs"]["web"])
            web_expected = recipe("check-web", "pnpm exec ")
            check([r for r in web if r.startswith("pnpm exec ")] == web_expected, f"{arg}: web differs from check-web")
            check("pnpm install --frozen-lockfile" in web, f"{arg}: web must use --frozen-lockfile")
            api = runs(data["jobs"]["api"])
            api_expected = recipe("check-api", "uv run --locked ") + ["uv run --locked bandit -q -r src -ll"]
            check([r for r in api if r.startswith("uv run --locked ")] == api_expected, f"{arg}: api differs from check-api + bandit")

            check(api_env.get("UV_PROJECT_ENVIRONMENT") == ".venv", f"{arg}: api needs UV_PROJECT_ENVIRONMENT=.venv")

            check("--extra" not in text and "--all-extras" not in text, f"{arg}: must not install extras")
    if path.name == "codeql.yml":
        job = data["jobs"]["analyze"]
        include = job["strategy"]["matrix"]["include"]
        languages = sorted(item["language"] for item in include)
        check(languages == ["actions", "javascript-typescript", "python"], f"{arg}: languages {languages}")
        check(all(item["build-mode"] == "none" for item in include), f"{arg}: build-mode must be none")

        inits = [s for s in job["steps"] if str(s.get("uses", "")).startswith("github/codeql-action/init@")]
        check(len(inits) == 1, f"{arg}: expected one init step")
        check(all(s.get("with", {}).get("queries") == "security-extended" for s in inits), f"{arg}: queries")
        check(sorted(data["on"]) == ["pull_request", "push", "schedule"], f"{arg}: triggers differ")
    if path.name == "audit.yml":
        check(sorted(data["on"]) == ["schedule", "workflow_dispatch"], f"{arg}: triggers differ")
        check(data.get("permissions") == {"contents": "read"}, f"{arg}: permissions must be contents: read")
        check(sorted(data["jobs"]) == ["audit"], f"{arg}: jobs must be [audit]")
        audit = runs(data["jobs"]["audit"])

for problem in problems:

print("W OK" if not problems else f"W PROBLEMS: {len(problems)}")

## 8. Review focus

1. **Required-check wiring and concurrency.**
   - Job keys and names are `web`/`api`, with no matrix, `needs`, `if` or path filters.
   - `pull_request` and `push` are limited to `main`, so each PR head gets one run.
   - The concurrency group uses `github.run_id` on `main`. This departs from the owner's literal
     `ci-${{ github.ref }}`, because GitHub cancels a *pending* run in the same group even when
     `cancel-in-progress` is false. **The owner confirms this at the blueprint gate.**
2. **pnpm through corepack plus a second `setup-node` call for `cache: pnpm`.**
   - This relies on setup-node running `pnpm store path` in the lockfile's directory
     (`apps/web`), where `packageManager` applies.
   - If the RESUME C log shows a cache "Path Validation Error" or a pnpm other than 12.6.0, that
     falls under step 11's "stop and report" branch, not a builder fix.
3. **`api` job environment.**
   - `UV_PROJECT_ENVIRONMENT=.venv` (relative to the project) and `UV_PYTHON_PREFERENCE=only-managed`.
   - The `test -x .venv/bin/ruff` guard.
   - pyright's node comes from `.nvmrc`, and `~/.cache/pyright-python` is cached.
   - semgrep's version comes from `just --evaluate`, with no reachability probe. So a Semgrep
     registry outage turns `api` red. The owner chose that over a silent pass.
4. **actionlint pinning trade-off.**
   - The pin is a version string in `scripts/pre-commit-actionlint.sh`, installed through
     `uv tool install actionlint-py`. It is not lockfile-hashed.
   - shellcheck and pyflakes are turned off for determinism, so `run:` scripts get no shellcheck
     pass.
   - The hook fails when actionlint is missing. That affects anyone committing workflow changes
     without running the README setup step.
5. **Sequencing on GitHub.**
   - Default setup is turned off before the first push, and the PR is opened as a draft
     (`/ship` must not create a second PR).
   - The ruleset is applied only after a green `main` run, and `can_bypass=never` is checked.
   - The README says `web`/`api` are required checks from the T0.4 merge on. That is only true
     after RESUME E.
