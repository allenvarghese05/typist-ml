## 2. Why it matters

- **Core scientific engine of Typist-ML (§1, §3.5, §15.1):** Typist-ML is built to answer the primary research question: *"does a small on-device language model write better drills than a dictionary heuristic or a Markov chain?"* Task T4.1 implements the mathematical calculations for the primary outcome (targeting effect on error rate via difference-in-differences and Beta posteriors) and the key secondary outcome (targeting effect on median inter-key interval via difference-in-differences and bootstrap confidence intervals).
- **Foundation for Milestone M4 (Dashboard and write-up, §16):**
  - T4.2: Dashboard pages (§15.2: Per-set outcomes view and Timing view) depend directly on the outcomes, intervals, and effect samples produced here.
  - T4.3: Results notebook and README figures rely on these statistical routines.
  - T4.4: README with numbers, method, limitations, and $N$ draws its values from this service.
  - T4.5: Debrief page displays per-set changes and arm comparisons after retest completion.
- **Enforces the pre-registered protocol (D20, `docs/analysis-plan.md`):** The analysis plan was frozen and pre-registered on 2026-10-30 in T3.6. T4.1 translates the pre-registered mathematical formulas, exclusions, priors, and seeds into verified Python calculations.
- **What breaks if it is wrong:**
  - **Inverted or distorted effects:** If the difference-in-differences sign convention ($d(s) - d(\text{control})$ where negative indicates improvement) is inverted or computed over misaligned sets, a deleterious arm could appear beneficial, or vice-versa.
  - **Incorrect uncertainty bounds:** If the prior deviates from the Jeffreys prior $\text{Beta}(1/2, 1/2)$, if posterior percentiles do not match the equal-tailed 2.5th and 97.5th percentiles, or if sampling draws differ from the pre-registered 100,000 draws seeded with `20261030`, reported uncertainty will be invalid.
  - **Violated exclusion rules:** If abandoned sessions are included, if older baseline sessions are pooled instead of the 2 most recent completed sessions per phase, if bigrams with fewer than 20 retest attempts are dropped from retest only instead of both phases, or if pauses are dropped from error counts instead of IKI only (D23), the analysis will violate pre-registration.
  - **Flawed timing metrics:** If median IKI is calculated as an average of session medians or median-of-medians instead of a single median over pooled raw IKI samples of the set across both sessions of the phase, timing comparisons will be mathematically invalid.
  - **Unreproducible results:** If random number generators are not properly seeded or caller-controlled, results will fluctuate across runs.

## 5. Inputs and outputs

### 5.1 Inputs

1. **Database records:**
   - `Participant`: `participant_id`, verifying `status == 'done'`, extracting `is_builder` and `is_blinded`.
   - `BigramAssignment`: Set definitions mapping each bigram to a `set_label` (`A`, `B`, `C`, `D`) and `arm` (`control`, `heuristic`, `markov`, `llm`).
   - `Session` (`TypingSession`): All sessions for the participant. Filters for `phase in ('baseline', 'retest')` and `status == 'completed'`. Selects the 2 most recent completed sessions per phase (ordered by `day_index` / `started_at`), while recording any abandoned or superseded completed sessions for the exclusions report.
   - `BigramStat`: Derived `attempts` and `errors` for each qualifying session and bigram.
   - `KeystrokeEvent` & `SessionBlock`: Clean IKI samples cannot be derived from `BigramStat` (which stores only session-level medians). Raw IKI samples for qualifying bigrams in completed blocks are retrieved by re-pooling raw keystroke events via `attribute_block_samples` + `merge_bigram_samples`.
2. **Pre-registered configuration & constants (`docs/analysis-plan.md`):**
   - Posterior draws: $100,000$ draws per Beta posterior.
   - Random seed: `20261030` passed in by the caller.
   - Jeffreys prior: $\alpha_0 = 0.5, \beta_0 = 0.5$.
   - Equal-tailed credible interval coverage: $95\%$ (2.5th and 97.5th percentiles).
   - Retest attempt inclusion threshold: $\ge 20$ pooled retest attempts per tracked bigram.
   - Bootstrap resamples: $10,000$ resamples within set and phase for median IKI difference-in-differences.

### 5.2 Outputs

1. **Primary Outcome (Error Rate):**
   - For each set $s \in \{\text{control}, \text{heuristic}, \text{markov}, \text{llm}\}$ and phase $t \in \{\text{baseline}, \text{retest}\}$:
     - Retained bigrams count and list.
     - Pooled `attempts` and `errors`.
     - Error rate $p(s, t) = \text{errors} / \text{attempts}$.
     - 95% equal-tailed Jeffreys credible interval: $[p_{025}(s, t), p_{975}(s, t)]$.
   - For each set $s$:
     - Error rate change: $d(s) = p(s, \text{retest}) - p(s, \text{baseline})$.
   - For each targeted arm $s \in \{\text{heuristic}, \text{markov}, \text{llm}\}$:
     - Empirical targeting effect: $E(s) = d(s) - d(\text{control})$.
     - Posterior effect median: $\text{median}(E(s))$ over 100,000 draws.
     - Share of samples below zero: $P(E(s) < 0)$ over 100,000 draws.
2. **Key Secondary Outcome (Median IKI):**
   - For each set $s$ and phase $t$:
     - Clean sample count $n(s, t)$.
     - Pooled median IKI $m(s, t)$ in milliseconds (single median over all pooled clean IKI samples).
     - Interquartile range (IQR: 25th and 75th percentiles).
   - For each set $s$:
     - IKI change: $c(s) = m(s, \text{retest}) - m(s, \text{baseline})$.
   - For each targeted arm $s \in \{\text{heuristic}, \text{markov}, \text{llm}\}$:
     - Empirical IKI targeting effect: $F(s) = c(s) - c(\text{control})$.
     - Bootstrap 95% confidence interval for $F(s)$ (2.5th to 97.5th percentiles over 10,000 resamples).
3. **Exclusions Report:**
   - Excluded sessions: session ID, phase, day_index, reason (`abandoned` or superseded by re-run).
   - Dropped bigrams: bigram string, set label, arm, observed retest attempts ($< 20$).
   - Excluded pause count: number of IKI pairs excluded as pauses ($> 2000$ ms or after blur) per set and phase.
4. **Session-level Exploratory Measures:**
   - Mean baseline WPM and accuracy, mean retest WPM and accuracy across the analyzed sessions.

## 6. Constraints

- **Pre-registration lock (D20, `docs/analysis-plan.md`):** All parameters (seed `20261030`, 100,000 draws, 10,000 bootstrap resamples, Jeffreys prior, $\ge 20$ retest attempts) are pre-registered and must be strictly adhered to without post-hoc modifications.
- **Pure calculations & separation of concerns (CLAUDE.md):** Analysis functions must perform pure calculations on explicit data structures. Database queries read state; no updates or deletes are made during analysis.
- **Randomness discipline (CLAUDE.md):** Randomness must always come from a seeded generator (`random.Random(seed)` or `numpy.random.default_rng(seed)`) passed in by the caller. Default seed is `20261030`. Tests must be deterministic.
- **Python dependencies & environment facts:**
  - `pyproject.toml` pins exact dependencies (`fastapi==0.141.1`, `sqlmodel==0.0.47`, `typer==0.27.2`, etc.).

  - Generating 800,000 Beta random variates (4 sets $\times$ 2 phases $\times$ 100,000 draws) and 10,000 bootstrap resamples must execute efficiently.

- **Honesty rule & reporting (§1, §18, D19):** No statistical hypothesis testing, p-values, or significance stars. Results must be reported as descriptive within-person differences.

## 7. Edge cases

1. **Zero errors in a set and phase ($k = 0, n = 150$):**
   - *Example:* Control set in baseline has 150 attempts and 0 errors.
   - *Behavior:* Empirical error rate is $0.0$. The Jeffreys posterior is $\text{Beta}(0 + 0.5, 150 - 0 + 0.5) = \text{Beta}(0.5, 150.5)$. The equal-tailed 95% interval is strictly positive (approx. $[0.000016, 0.0166]$), avoiding zero-division or degenerate degenerate bounds.
2. **All errors in a set and phase ($k = n = 50$):**
   - *Example:* Set A has 50 attempts and 50 errors.
   - *Behavior:* Empirical error rate is $1.0$. The Jeffreys posterior is $\text{Beta}(50.5, 0.5)$. The interval is strictly in $(0, 1)$ (approx. $[0.951, 0.99998]$).
3. **Bigram exactly at boundary ($19$ vs $20$ retest attempts):**
   - *Example:* In set B, bigram `"th"` has 19 attempts across the two analyzed retest sessions; bigram `"he"` has 20 attempts.
   - *Behavior:* `"th"` must be dropped from set B in **both** baseline and retest for primary and secondary outcomes. `"he"` is retained. `"th"` must be explicitly recorded in the exclusions report with attempts = 19.
4. **All bigrams in a set dropped ($0$ qualifying bigrams remaining):**
   - *Example:* Due to severe attribution skips, all 4 bigrams in set C have $< 20$ retest attempts.
   - *Behavior:* Set attempts = 0, errors = 0. Error rate $p(s, t)$ is undefined (`None`). Targeting effect $E(s)$ cannot be computed; the service must handle this without an unhandled ZeroDivisionError or crash.
5. **Zero clean IKI samples ($n = 0$):**
   - *Example:* Every occurrence of a set's bigrams occurred after a pause ($> 2000$ ms or after window blur) or followed an incorrect first key.
   - *Behavior:* $n = 0$, median IKI is `None`, IQR is `None`. Bootstrap cannot resample an empty array; IKI targeting effect $F(s)$ is `None`.
6. **Even vs odd count of clean IKI samples:**
   - *Example:* Set has clean IKI samples `[120.0, 130.0, 140.0, 150.0]`.
   - *Behavior:* Python's `statistics.median` returns $(130.0 + 140.0) / 2 = 135.0$. For odd count `[120.0, 130.0, 140.0]`, it returns $130.0$. Hand-computed test fixtures must precisely reflect this convention.
7. **Abandoned baseline or retest session:**
   - *Example:* Participant starts baseline session 1, leaves for 40 minutes (session becomes `abandoned`). Later completes session 2 and session 3.
   - *Behavior:* Session 1 keystrokes are excluded from analysis and listed in the exclusions report. Sessions 2 and 3 provide the baseline data.
8. **Superseded completed baseline sessions (>3-day rule):**
   - *Example:* Participant completes sessions 1 and 2, but practice is delayed $>3$ days (§3.2, D23). Participant completes new baseline sessions 3 and 4.
   - *Behavior:* Sessions 1 and 2 are excluded from outcome analysis (listed in exclusions as superseded); sessions 3 and 4 are analyzed as the 2 most recent completed baseline sessions.
9. **Idle-abandoned block within a completed session (D26):**
   - *Example:* In session 2, block 1 encounters a 10s idle timeout and is abandoned. Block 1 is restarted and completed.
   - *Behavior:* Keystrokes from the abandoned block attempt are excluded from outcome analysis; only completed block keystrokes are attributed and analyzed.
10. **Two-set mode contingency:**
    - *Example:* Study runs with `arms_enabled = ["control", "heuristic"]` (D03, §16).
    - *Behavior:* Only sets A and B exist. Primary comparison is strictly heuristic vs control. Markov and LLM comparisons are omitted with an explicit status or indicator, never crashing or failing validation.
11. **Twelve-bigram fallback:**
    - *Example:* Baseline qualifies only 12 weak bigrams (3 per set in 4-arm mode, or 6 per set in 2-set mode).
    - *Behavior:* Analysis logic pools over the assigned bigrams regardless of whether count is 3, 4, 6, or 8 bigrams per set.
12. **Identical arm and control changes ($E(s) = 0$):**
    - *Example:* Set $s$ error rate changes by $-0.02$, and control changes by $-0.02$.
    - *Behavior:* Empirical $E(s) = 0.0$. In posterior draws, the metric checks strict inequality $E(s) < 0$. Draws where $E(s) \ge 0$ do not count toward the share below zero.

## 8. Risks

- **Method for computing Beta quantiles / inverse CDF:**
  - *Risk:* `scipy.stats.beta.ppf` is the standard tool to compute Beta inverse CDF for the 2.5% and 97.5% quantiles. If `scipy` is not in `pyproject.toml`, implementing custom numerical bisection on an incomplete beta function in pure Python is complex and prone to edge-case inaccuracies. Alternatively, estimating quantiles directly from the 100,000 Monte Carlo draws is simple and robust, but might differ slightly from exact analytical quantiles.
- **Execution speed of Monte Carlo and Bootstrap:**
  - *Risk:* Resampling 10,000 times in pure Python using `random.choices` and `statistics.median` over hundreds of items can take 5–15 seconds per comparison, which would make unit tests slow. Using `numpy` vectorized random choice or standard array operations runs in milliseconds.
- **Accidental median-of-medians computation:**
  - *Risk:* `BigramStat` in the SQLite database stores `iki_median_ms` per session. Taking the median or average of these session-level medians violates the design doc and pre-registered plan ("one median over the pooled list — NOT a median of medians"). Raw IKI samples must be reconstructed from `keystroke_events` for all qualifying blocks.
- **Schema mismatch with existing API endpoints:**
  - *Risk:* Existing router `GET /analysis/participants/{participant_id}` and `pipeline_sim.py` expect `ParticipantResults` with specific fields. If `ParticipantResults` or `SetOutcome` is modified without backward compatibility, integration tests and simulations will break.
- **Circular testing in unit tests:**
  - *Risk:* If "hand-computed examples" in acceptance criteria are generated using the implementation code itself, bugs in formula implementation will be missed. Test fixtures must use independently hand-calculated or mathematically verifiable numbers.

## 10. Owner answers (2026-10-30)

1. **Beta intervals & numerical computation:**
   - *Answer:* Add pinned runtime dependencies `numpy==2.2.3` and `scipy==1.15.2` (exact versions matching latest compatible releases) to `services/api/pyproject.toml`. Compute exact equal-tailed 95% Jeffreys credible intervals $[p_{025}, p_{975}]$ via `scipy.stats.beta.ppf([0.025, 0.975], a, b)`. Use `numpy.random.default_rng(seed).beta(a, b, size=100_000)` for fast vectorized generation of the 100,000 posterior draws, and NumPy array operations for the 10,000 bootstrap resamples.
