## 2. Why it matters

- T1.10 is the **last task in M1**; it closes "overhead reported" and "a baseline session
  produces a bigram matrix". If it is wrong, M1 cannot be declared done.
- The **overhead number is reported in the résumé / README** ("the resume bullet uses the
  measured number, not the target", §12.5). A wrong percentile overstates or understates the
  instrument's cost; CLAUDE.md forbids writing result numbers into the README before real
  data exists, so the computation must be trustworthy before any number is published.
- The **bigram matrix is the "working diagnostic tool"** M1 leaves behind if work stops
  (§16). It is the first visual confirmation that attribution (T1.7) and session_stats
  (T1.9) produce sensible per-bigram error/IKI values. A mislabelled heatmap (wrong bigram
  axis orientation, wrong metric) would make a correct pipeline look broken, or hide a real
  bug.
- It is the **first dashboard surface** (§15.2) and likely the **first second screen** in the
  web app, so it is the point where routing (deferred by T0.2/T1.5) and chart tooling
  (Recharts, deferred by T0.2) and the API client (deferred by T1.6) may finally be needed.
  Choices made here shape T2.9 (admin) and T4.2 (full dashboard).

## 4. Current state (quote signatures, do not paraphrase)

### 4.1 Overhead data source — `models/keystroke_events.py`
`KeystrokeEvent(SQLModel, table=True)` stores the two overhead fields as **non-nullable
REAL** (every recorded row has them):
```python

dispatch_lag_ms: float
```
(`handler_ms` = perf.now() end−start; `dispatch_lag_ms` = handler-start − `e.timeStamp`,
§12.5.) Rows are append-only; `(block_id, seq)` is unique. There is **no existing service,
CLI command, endpoint, or test that aggregates these two fields into percentiles.** Grep for

model, the events schema, and docstrings.

### 4.2 Matrix data source — `models/bigram_stats.py`
`BigramStat(SQLModel, table=True)` (created by T1.9), columns:
```python

participant_id: str = Field(foreign_key="participants.id")
session_id: str = Field(foreign_key="sessions.id")
bigram: str
attempts: int
```

## 5. Inputs and outputs

### Overhead report (`typist overhead`)
- **In:** `keystroke_events.handler_ms` and `dispatch_lag_ms` (REAL, non-null) for the
  relevant rows, read through `create_db_engine(settings.db_path)` + a SQLModel `Session`.
  §12.5 scopes percentiles "per session"; grouping key is session (via
  `session_blocks.session_id` → `keystroke_events.block_id`).
- **Out:** p50, p95, p99 for `handler_ms` and for `dispatch_lag_ms`, printed to stdout via
  `typer.echo`. (The exact per-session vs aggregate shape is an open question — see §9.)

### Bigram matrix page (`/dashboard` or similar)
- **In:** persisted `bigram_stats` rows for one session (or phase) → per-bigram `errors`,
  `attempts` (→ error rate `errors/attempts`), and `iki_median_ms` (nullable). Delivered to
  the browser over HTTP JSON (endpoint TBD — see §9); the browser must not recompute.
- **Out:** a rendered 26×26 heatmap (rows = first letter, columns = second letter of the
  bigram) coloured by error rate and/or median IKI (§15.2 names both). Acceptance only
  requires that "heatmap renders".
- **Where each lives:** overhead percentiles — Python (CLI, and optionally a service reused by
  a future `/analysis/overview`, §14). Matrix data — Python `bigram_stats`, served by an
  endpoint; rendering — `apps/web/src/features/dashboard/`.

## 7. Edge cases (with concrete examples)

1. **No completed session / empty `bigram_stats`.** A fresh DB or a session still
   `in_progress` has no bigram rows → the matrix must render an all-empty 26×26 grid, not
   crash. Example: call the page right after `participant add` before any session completes.
2. **Bigram with zero attempts.** Omitted from `bigram_stats` (attribution drops zero-attempt
   bigrams). The page must treat a **missing** cell as "no data" (distinct colour/blank), not
   as error rate 0. Example: "qj" never typed → no row → blank cell, not green.
3. **`iki_median_ms` is NULL** (when `iki_n == 0`: attempts existed but every pair was paused
   or non-adjacent, D23(a)/D24). The IKI heatmap cell must render "no timing" even though the
   error-rate cell has data. Example: bigram "ld" with one paused pair → attempts≥1, iki_n=0.
4. **Error rate denominator.** `errors/attempts` with `attempts ≥ 1` always (rows with 0
   attempts are absent), so no divide-by-zero — but the TS/endpoint must still guard.
5. **Division by zero in overhead percentiles.** A session/block with **0 keystroke rows**
   (block started, never typed) has no overhead samples → percentiles undefined. Example: an
   abandoned block. Must emit "no data" rather than raise.
6. **Single-sample / tiny-sample percentiles.** A session with 1–2 keystrokes: p95/p99 of 1
   value is that value. The percentile method (nearest-rank vs linear interpolation, and
   which library — `statistics.quantiles`, `numpy.percentile`, or hand-rolled) changes the
   printed number; §12.5 does not specify the method (open Q).
7. **Negative `dispatch_lag_ms`.** `dispatch_lag_ms` = handler-start − `e.timeStamp` is
   normally ≥0 but can be small/near-zero; percentiles must handle the full real-valued
   range. (`handler_ms` is ≥0.)
8. **Which sessions count.** `recompute_stats` only processes `status == 'completed'`
   sessions; abandoned/in_progress have stale-or-absent bigram_stats. The matrix must decide
   which sessions are selectable; overhead's §12.5 "per session" says nothing about excluding
   abandoned sessions (open Q 8 in T1.9 kept abandoned-row handling out of scope).
9. **Phase vs session.** §15.2 allows "one session or phase". A phase aggregates multiple
   sessions' bigram rows (sum attempts/errors; pooling medians is **not** a median of medians —
   the raw-sample pooling that session_stats does is per-session only). Aggregating across
   sessions for a phase has **no existing pooled-sample path** (bigram_stats stores a median,
   not raw samples), so a phase-level median would be a median-of-medians unless recomputed
   from raw keystrokes (open Q).
10. **Letter axis orientation.** 26×26: must fix whether rows are the first or second letter
    of the bigram so the heatmap is not transposed. Example: cell (row "t", col "h") = bigram
    "th". A silent transpose is a correctness-looking bug with no exception.
11. **Space in bigrams.** D13: bigrams across a space are not tracked; `length(bigram)=2`
    letters only. The axes are exactly `a..z`; no space row/column.
12. **No route to reach the page.** App currently renders only the TypingSurface demo with no
    router; the matrix page needs a way to be reached (replace App content, add a router, or a
    toggle). Affects whether `App.tsx` changes and whether a test can render the page.

## 8. Risks

- **Endpoint gap:** §14 lists `/analysis/participants/{pid}` and `/analysis/overview` but
  **no single-session bigram-matrix GET endpoint**. Building the page may require inventing an
  endpoint not named in the design (scope + contract risk).
- **Router / Recharts / client introduction:** T1.10 may be forced to be the first user of a
  router, Recharts, and/or an API client — all deferred by T0.2/T1.5/T1.6 "to their first real
  user." Pulling all three in makes this a large PR and may need decision rows/ADRs (D07
  names Recharts and TanStack Query but no router).
- **Percentile method drift:** an unspecified percentile algorithm produces a number that
  later ends up in the résumé/README; if the method changes later the published number
  changes. Needs a single documented method.
- **Median-of-medians trap for phase view:** aggregating bigram IKI across sessions from
  stored medians silently violates the "not a median of medians" rule that T1.7/T1.9 took
  care to honour.
- **Heatmap a11y lint:** Biome `a11y: error` may reject an SVG/`<table>` heatmap without
  labels, failing `just check`.
- **"Heatmap renders" is weakly specified:** no numeric assertion; a test can pass while the
  colours/axes are wrong. Risk of shipping a misleading-but-"rendering" chart.

## Owner answers

2026-10-19 — answered by the orchestrator under the autonomous pipeline rule. Sources: (a) design
doc / D-numbers, (b) CLAUDE.md, (c) earlier briefs/plans/owner answers, (d) existing code
patterns, (e) industry practice. Guiding principle: T1.10 closes M1 with the smallest surface that
satisfies "p50, p95 and p99 printed; heatmap renders"; every deferred tool (router, Recharts,
TanStack Query, openapi-typescript) stays deferred to T4.2, the first real multi-view dashboard.

1. **New `analysis` router with one endpoint: `GET /analysis/sessions/{session_id}/matrix` →
   `BigramMatrix`.** Source: (a) section 7 names an `analysis` router and 15.2 names the matrix as
   the M1 view; section 14's two `/analysis/*` endpoints are T4 shapes, so a sibling read-only
   endpoint is the smallest addition. Schema: `{ session_id, participant_id, phase, wpm, accuracy,
   cells: [{ bigram, attempts, errors, error_rate, iki_median_ms, iki_n }] }` — `error_rate =
   errors / attempts` computed server-side; cells come straight from `bigram_stats` (only bigrams
   with rows). 404 if the session does not exist; 409 if `status != "completed"` (no stats yet;
   section 14 "invalid state" convention). Phase-level matrix is deferred (it needs pooled raw
   samples that `bigram_stats` does not store — T1.7 answer 3).

2. **`typist overhead [--pid PID] [--session SID]` prints one row per session plus an "all" row.**
   Source: (a) 12.5 "Report p50, p95 and p99 per session with typist overhead"; (d) `stats
   recompute --pid` precedent. Columns: `session`, `participant`, `events`, `handler p50 p95 p99`,
   `dispatch p50 p95 p99` (ms, 3 decimals). Sessions with zero events are listed with `-`. The
   "all" row pools every selected session's events. Exit 0 even when empty (prints "no keystroke
   events").

3. **`statistics.quantiles(values, n=100, method="inclusive")`, p50 = q[49], p95 = q[94],
   p99 = q[98]; a single value is its own p50/p95/p99; empty → None.** Source: (e) stdlib,
   linear interpolation on the inclusive definition (matches numpy's default `linear`), no numpy
   dependency; recorded in the module docstring so the résumé number is reproducible.

4. **CLI report + matrix page only.** Source: (a) 15.2's "Overhead" dashboard view is T4.2's
   "All views load from real data"; T1.10's acceptance names printing, not a view.

5. **No router library. A hand-rolled hash view switch in `App.tsx`: default (`#/` or empty) →
   the TypingSurface demo; `#/matrix/<session_id>` → the matrix page.** Source: (c) T0.2/T1.5
   deferred the router to the first task that needs real navigation; two views reachable by
   `window.location.hash` do not justify a dependency or an ADR. The router decision row is
   deferred to T4.2 and this is noted in the plan's out-of-scope section.

6. **Hand-rolled CSS-grid heatmap (26×26 `div`s with inline background colour), no Recharts.**
   Source: (e) Recharts has no heatmap primitive, so adding it would not help; (c) first-user
   deferral precedent. Colour: a single-hue ramp (white → red for error rate; white → blue for
   IKI), computed from the cell's value over the page's max; cells without data render empty
   with a neutral border. Row = first letter, column = second letter, a–z both axes, axis labels
   rendered. The cell has a `title` tooltip with the raw numbers.

7. **Hand-rolled `fetch` on `apiPath` with a hand-written `BigramMatrix` TS type mirroring the
   Pydantic schema; `openapi-typescript` stays deferred.** Source: (c) T1.6 answer 12.

8. **Session only; completed sessions only.** Source: (a) `bigram_stats` only exists for
   completed sessions (T1.9 answer 6), so abandoned sessions are excluded by construction and the
   endpoint returns 409 for them. Phase aggregation deferred (answer 1).

9. **Both, via a toggle; error rate is the default.** Source: (a) 15.2 "heatmap of error rate
   and median IKI". Two buttons ("Error rate" / "Median IKI"); the IKI view leaves cells with
   `iki_n == 0` empty.
