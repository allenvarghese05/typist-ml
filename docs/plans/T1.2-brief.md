## 2. Why it matters

What T1.2 enables later:
- **T1.3 (TextCursor, TypeScript):** its only acceptance criterion is "All fixture outcomes match".
  Without the fixture T1.3 has nothing to pass.
- **T1.7 (attribution.py, Python):** "Fixture matches". The fixture's expected bigram stats are the
  test oracle for the code that produces every number the experiment reports (D05, section 3.5).
- **Cross-language agreement:** section 7 says the fixture exists "so the two languages cannot
  drift apart on what counts as an error". It is the single place where the browser's live
  alignment (TextCursor) and the server's attribution are tied to the same answer.
- **Review of later AI-written code:** section 17.3 asks for telemetry and attribution code to be
  reviewed "line by line against the fixture"; the reviewer agent checks "golden fixture
  unchanged" (`.claude/agents/reviewer.md`); the PR template has "Telemetry or attribution changes
  checked against the golden fixture".
- **Order of work:** section 20.3 puts T1.2 "before any telemetry code". When T1.2 is written, no
  TextCursor, KeystrokeRecorder or attribution code exists to cross-check against
  (`apps/web/src/telemetry/` holds only `.gitkeep`; `services/api/src/typist/services/` has no
  `attribution.py`). Every expected value is derived by hand from the written rules.
- **Possibly T1.9 and T1.4/T1.6**, depending on open questions 1 to 3 (WPM/accuracy, timing
  derivations, insertable rows).

What breaks if it is wrong:
- **A wrong expected value becomes law.** CLAUDE.md: the fixture "is the source of truth for what
  counts as an error ... Never edit expected values to make a test pass; flag it in the PR
  instead." `.claude/agents/builder.md`: "Never edit expected values in
  tests/fixtures/golden_session.json." If the fixture encodes a rule that contradicts section 12.3
  or D14, both implementations are written to match it, and the error propagates to `bigram_stats`,
  weak-bigram ranking (3.4), the frozen sets (D04) and every outcome (D05). Section 18: "Attribution
  bug | All results wrong". After the pilot starts the code may not change (section 16 runbook).
- **An ambiguous fixture lets the two languages disagree silently.** If the fixture leaves a case
  open (for example `target_index` of a Backspace row), TS and Python can each pick a different
  reading and both still "pass".
- **Missing coverage hides bugs.** The acceptance names four cases (errors, backspace, rollover, a
  pause). A case that is present but does not change any expected value (for example a rollover
  that no expected number depends on, or a pause whose IKI is also over 2000 ms) does not
  distinguish a correct implementation from an incorrect one.
- **Float mismatch makes tests flaky or wrong** (edge case 22).
- **Without review evidence the acceptance cannot be shown** ("Reviewed line by line").

### 4.2 Alignment and attribution rules (section 12.3, verbatim)
"The TextCursor holds the target text and an index. Each printable keystroke is compared with
target[index], recorded as correct or error, and the index moves forward one position either way.
Backspace moves the index back. The first keystroke ever recorded at a position is its first
attempt; retyping after a correction is not."

```
for each position j >= 1 where target[j-1] and target[j] are letters:
    a = first_attempt keystroke at j-1
    b = first_attempt keystroke at j
    if a is missing or b is missing:          skip
    if a.outcome != "correct":                skip   # context was wrong
    if a backspace happened between a and b:  skip   # not a clean transition
    bigram = target[j-1] + target[j]
    attempts[bigram] += 1
    if b.outcome == "error": errors[bigram] += 1
    elif b.seq == a.seq + 1 and not b.after_pause:
        iki_samples[bigram].append(b.t_down - a.t_down)
```
- "Session WPM is correct first-attempt characters divided by 5, divided by minutes of active typing (pauses removed)."
- "Session accuracy is correct first attempts divided by all first attempts."
- "Bigrams across a space (for example e then space) are not tracked in v1 (D13)."

### 4.3 Capture and timing rules (sections 12.1, 12.2, 12.4, 11.3, verbatim)
- 12.1: "Listen to keydown and keyup on window while a block is active and the page has focus." / "Ignore events where e.repeat is true, modifier-only keys, and any event with Ctrl, Meta or Alt held. Shift is allowed but not needed in v1." / "Handle only a to z, space and Backspace." / "Use e.key to decide the character and store e.code for the physical key." / "Pair keyup with its keydown by e.code, using a map of open keys. This is what makes dwell correct when keys overlap." / "On window blur: pause the block, mark the next keystroke as following a pause, and resume on focus."
- 12.2 table: Timestamp `e.timeStamp` ("Do not use Date.now()"); Dwell "t_up minus t_down, same physical key"; IKI "t_down(i) minus t_down(i-1) ... Always positive"; Release to press "t_down(i) minus t_up(i-1) ... negative whenever the next key is pressed before the previous one is released (rollover)"; Pause "IKI over 2000 ms, or first key after a blur | Excluded from IKI statistics, still counted for errors".
- 12.4: "A row is created on keydown and sent once its keyup has arrived, or after 2 seconds without one (keyup stays null)."
- 11.3 "Typing surface rules: monospace font, the whole block visible, one character per keystroke, wrong characters shown in red and left in place until corrected with Backspace, no autocorrect or spellcheck, and the block pauses if the window loses focus."
- 12.6 checks: "Gaps in seq within a block." / "Negative dwell, or dwell over 1000 ms (stuck key)." / "Blocks with fewer events than characters in the target text." / "Share of keyups missing."
- 10.3 Figure 9: "Normalise t = event.timeStamp, drop repeat and modifiers" then "Align to target text outcome + first attempt per position" then `keystroke_events`, then "Bigram attribution attempts, errors, IKI" then "bigram_stats per session".

## 7. Edge cases

Examples use target `the cat` (index 0 `t`, 1 `h`, 2 `e`, 3 space, 4 `c`, 5 `a`, 6 `t`). Tracked
positions are j = 1 (`th`), 2 (`he`), 5 (`ca`), 6 (`at`); j = 3 (`e` space) and j = 4 (space `c`)
are not tracked (D13). Seq numbers count rows in the block from 0. These illustrate the rules; they
are not proposed fixture content.

1. **Error at j-1 removes the pair at j.** Keys: `t`, `x`, Backspace, `h`, `e`. Rows: seq 0 `t`
   correct (first), seq 1 `x` error at index 1 (first), seq 2 Backspace, seq 3 `h` correct at
   index 1 (not first), seq 4 `e` correct at index 2 (first). j = 1: attempt and error for `th`.
   j = 2: a = seq 1 (error), so skip; `he` gets no attempt even though `h` and `e` end up correct.
2. **Backspace between a clean a and b.** Keys: `t`, `h`, Backspace, `h`, `e`. j = 1: a = seq 0,
   b = seq 1, the Backspace (seq 2) is after b, so `th` gets an attempt and an IKI sample. j = 2:
   a = seq 1 (correct), b = seq 4, Backspace seq 2 lies between, so skip. This shows that erasing a
   correct character is allowed and still affects attribution.
3. **What "between" means.** 12.3 says "a backspace happened between a and b" without defining it.
   One reading is any Backspace row with `a.seq < seq < b.seq` in the same block. Under that reading
   (and with no seq gaps) `b.seq == a.seq + 1` always holds once the Backspace check passes, because
   the only rows that can come between a first attempt at j-1 and the first attempt at j are
   Backspaces (reasoned from 12.3; verify). The seq test then matters only if a row is missing (a
   gap in seq, a 12.6 check).
4. **Backspace row fields.** 8.1: `target_index` is "Cursor position when the key was pressed". For
   Backspace at index 2 that is 2 (before moving back) under one reading, or 1 (the position
   erased) under another; no owner answer covers it. `expected_char` and `first_attempt` are NULL
   (T1.1 answer 5). `key` is `"Backspace"`, `code` is `"Backspace"` (KeyboardEvent values, verify).
5. **Backspace at index 0.** Nothing to erase. Whether a row is recorded, whether `index` stays 0,
   and whether such a row counts as "a backspace between a and b" are not stated.
6. **Several Backspaces and over-erasing.** Keys: `t`, `h`, `x` (error at 2), Backspace x3, `t`,
   `h`, `e`. After three Backspaces the index is 0; the retyped `t`, `h` are not first attempts.
   j = 1: a = seq 0, b = seq 1, no Backspace between, so `th` is clean. j = 2: a = seq 1 correct,
   b = seq 2 (`x`, first at 2), no Backspace between them, so `he` gets an attempt and an error.
7. **Omission cascades (purely positional alignment).** 12.3 compares each key with
   `target[index]`; there is no realignment. Keys `t`, `e`, space, ... (the `h` was skipped): `e` at
   index 1 is an error (`th` attempt and error), space at index 2 is an error and j = 2 is skipped
   (a was an error), `c` at index 3 (space) is an error, etc., until the typist backspaces. One
   omission produces a run of errors.
8. **Transposition.** Keys `t`, `e`, `h`: `e` at 1 error (`th` error), `h` at 2 error but j = 2 is
   skipped (a was an error). One slip counts as one bigram error, not two.
9. **Space positions.** Typing `x` at index 3 (space expected) is an error: it counts in session
   accuracy ("all first attempts") but in no bigram. The next pair j = 5 (`ca`) depends only on
   positions 4 and 5, so it is unaffected. Typing a space where a letter is expected is an error at
   that letter's position and can be a bigram error (j = 1: typing space instead of `h`).
10. **Uncorrected errors and the end of the block.** 11.3: wrong characters are "left in place until
    corrected with Backspace". Whether the typist may keep going past an error, whether a block can
    end with uncorrected errors, what `isDone()` means (index equals target length?) and what
    happens to keys pressed after the last position are not stated.
11. **Unfinished block (untyped tail).** If the page closes at index 5, j = 6 has no b: "if a is
    missing or b is missing: skip". 12.6 flags "Blocks with fewer events than characters in the
    target text".
12. **Rollover (keys overlap).** `t` down 100, `h` down 160, `t` up 195, `h` up 250: dwell `t` 95,
    dwell `h` 90, IKI `h` 60, release-to-press `h` = 160 - 195 = -35. Nothing in 12.3 uses
    release-to-press or dwell, so rollover changes no bigram stat (IKI is press-to-press, D15). A
    fixture rollover case therefore tests the timing columns (if present), not attribution.
13. **Nested overlap.** `t` down 100, `h` down 160, `h` up 200, `t` up 230: keyups arrive in the
    opposite order to keydowns; dwell `h` 40, dwell `t` 130. 12.4 sends `h`'s row when its keyup
    arrives (200), before `t`'s keyup (230). Release-to-press for `h` would be 160 - 230 = -70, but
    `t_up` of the previous key is not known when `h`'s row is sent. T1.1 answer 6 says
    release-to-press is "never backfilled — it's computed from stored timestamps at read time, not
    stored eagerly", while the model docstring says it is NULL "when the previous key's t_up was
    unknown at insert". Which value the fixture expects (−70 or NULL) depends on who computes the
    column and when; that is not settled.
14. **Pause by blur with short gap (the D24 case).** `t` at 1000, window blurs and refocuses, `h` at
    2800 with `after_pause` true. Gap 1800 ms (under 2000). `th`: attempt counted (still counted
    for errors), no IKI sample. Without the flag the pair would enter `iki_samples`.
15. **Pause by long gap only.** `t` at 1000, `h` at 3500, no blur, `after_pause` false. Gap 2500 ms:
    no IKI sample per D24's consequence. The 12.3 pseudocode alone (`not b.after_pause`) would keep
    it; D24 says `b.after_pause` "stands for both parts". A case where both conditions hold at once
    (blur plus gap over 2000) cannot tell the two rules apart.
16. **Boundary 2000 ms.** A gap of exactly 2000.0 ms is not "over 2000", so it is a sample under the
    literal wording. Whether the fixture should pin this boundary is not stated.
17. **First key after a blur is a Backspace or an error.** D24: the flag goes on "the first
    keystroke after the window regains focus". If that key is Backspace, the flag sits on a
    Backspace row and the next letter is unflagged (the pair is then skipped anyway by the
    Backspace rule). If it is an error, D23(a) says it still counts as an attempt and an error.
18. **Missing keyup.** A row sent after 2 s without keyup: `t_up_ms` NULL, `dwell_ms` NULL (answer
    5); the next row's `release_to_press_ms` NULL. Attribution is unaffected (it uses `t_down`).
19. **Seq 0.** `iki_ms` and `release_to_press_ms` NULL (answer 5). The first key's `t_down` is
    relative to block start and can be large (reading time before typing).
20. **Repeated letters and same physical key.** `ll` in `all`: two keydowns with `code` `KeyL`.
    Dwell pairing is by `code` (12.1); if the first `l`'s keyup were lost, the second keydown would
    find an open entry with the same code (T1.4 concern; relevant if the fixture carries raw
    events).
21. **Same bigram in several contexts.** A bigram occurring several times (some clean, some skipped,
    some errors, some paused) is the only way to check aggregation of attempts, errors and the
    median.
22. **Floating-point timestamps.** `event.timeStamp` values are fractional ms. In IEEE-754 doubles,
    `1234.5 - 1100.2` is `134.29999999999995`, not `134.3` (verify). TS and Python compute the same
    double from the same inputs, but a hand-written expected value `134.3` is a different double.
    Medians of sample lists add one more operation.
23. **Median of an even count.** With samples `[60, 80]`, the median is 70 under the usual
    "mean of the two middle values" rule, 60 or 80 under lower/upper rules. Python's
    `statistics.median` returns the mean of the middle two (verify); TS has no built-in median.
24. **Bigram with attempts but no IKI samples** (all errors, or all paused): `iki_median_ms` has no
    value and `iki_n` is 0. 8.1 does not say whether `iki_median_ms` is NULL then. Bigrams never
    attempted have no `bigram_stats` row under "UNIQUE (session_id, bigram)" only if rows are
    created per attempted bigram; not stated.
25. **"Session" vs "block".** The file is named `golden_session.json` and `bigram_stats` is per
    session, but `seq`, `t_down_ms` and `target_text` are per block. A multi-block fixture would
    exercise aggregation across blocks; a pair is never formed across a block boundary because
    each block has its own target.
26. **Filtered events.** `e.repeat`, modifier-only keys, Ctrl/Meta/Alt chords, keys outside a to z,
    space and Backspace, and keys while blurred never become rows (12.1). T1.4's acceptance covers
    them with "synthetic KeyboardEvents". If the fixture contains a raw event stream, whether it
    includes such events is open.
27. **Shift / uppercase.** "Shift is allowed but not needed in v1"; with Shift, `e.key` is `T`, not
    `t`. Whether `T` against target `t` is an error, a filtered key, or out of scope is not stated.
28. **Derived columns redundant with timestamps.** `iki_ms` equals `t_down_ms` minus the previous
    row's `t_down_ms`; `dwell_ms` equals `t_up_ms - t_down_ms`. If the fixture stores both the raw
    and the derived values, they can disagree by hand error; if it stores only one, a consumer must
    derive the other.
29. **JSON details.** JSON has no comments, no NaN/Infinity, and one number type: `60` and `60.0` are
    the same JSON number; Python's `json` gives `int` for `60` and `float` for `60.0`, TS gives
    `number` for both (verify). `null` maps to `None` / `null`. Key order and layout are free
    because no formatter touches the file.
30. **Field-name convention.** The DB uses `t_down_ms`, `target_index`, `first_attempt`; Figure 5 uses
    `tDown`, `targetIndex`, `firstAttempt`, `expected`, `iki`. Whichever the fixture uses, one
    language maps names.

## 8. Risks

1. **A wrong rule frozen as truth.** The fixture is hand-derived before any implementation exists,
   then becomes uneditable. A slip in one expected value (for example counting `he` in edge case 1)
   would be implemented faithfully in both languages.
2. **The author decides open semantics silently.** Backspace `target_index`, Backspace at index 0,
   the 2000 ms boundary, release-to-press under nested overlap and the even-count median are not
   settled by the design. Whatever the fixture says becomes the rule without an owner decision or
   ADR (17.3: "Any change to a decision gets a short ADR").
3. **A format that serves one consumer only.** TextCursor (T1.3) consumes a character/Backspace
   sequence and returns an outcome per key; attribution (T1.7) consumes stored rows plus the target
   text. A format shaped for one may force the other to re-derive fields, which re-opens drift.
4. **Required cases present but not discriminating.** A rollover no expected value depends on; a
   pause that is both blurred and over 2000 ms; an error that is never followed by a pair it
   should suppress. Such a fixture passes buggy code.
5. **Float comparison** (edge case 22): flaky or wrongly failing tests in one language, or
   tolerance chosen differently in TS and Python.
6. **Inconsistency with the merged schema.** Rows that a DB insert would reject (NULL `handler_ms`,
   non-null `first_attempt` on Backspace) or that contradict T1.1 answer 5/6 nulls.
7. **Review evidence missing or informal.** "Reviewed line by line" cannot be shown at the review
   phase; or the reviewer agent's review is taken for the owner's hand-check.
8. **Size.** Too small to cover the required and important cases; too large to hand-check.
9. **No gate validates the file** (4.6): a JSON syntax error or an editor reformat is caught only in
   T1.3/T1.7.
10. **Scope creep.** Writing TextCursor, attribution or a JSON-schema validator inside T1.2 would
    implement later tasks and, for attribution, could place logic outside `attribution.py`.
