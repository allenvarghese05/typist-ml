## 2. Why it matters

What T0.1 enables later:
- The justfile is the single entry point every later task and phase refers to:
  - T0.2 acceptance is phrased as `just test` ("just test runs one passing web test").
  - The M0 done-when is phrased as `just dev` ("runs web, API and worker").
  - T2.9 acceptance: "Builder can run the pilot without the terminal except just dev".
  - Section 14: "the frontend generates its types from it with just gen-types".
  - CLAUDE.md: "Run `just check` (lint, types, tests for both apps) before pushing."
  - `.github/pull_request_template.md` checklist: "`just check` passes locally".
  - `.claude/commands/ship.md` step 1: "Run `just check` (or the per-app checks if the justfile does not exist)."
  - `.claude/agents/builder.md`: "run `just check` (or the lint, type and test commands for the apps you changed, if the justfile does not exist yet)".
- pre-commit (section 5.3: "pre-commit runs ruff and Biome before each commit") is the local gate in front of CI (T0.4).
- `.gitignore` for `data/` enforces CLAUDE.md "Never commit anything under `data/` (database, corpus artifacts)" and section 4.2's privacy claim that typing data stays on one machine.

What breaks if it is wrong:
- If `data/` or `*.db` leaks into git, participant keystroke data (section 4.2 consent promise: "one SQLite file on your laptop") would be pushed to GitHub (`origin` is `https://github.com/allenvarghese05/typist-ml.git`). This is a privacy failure, not only a hygiene one.
- If recipe names differ from those the doc, CLAUDE.md, PR template and pipeline agents use (`dev`, `test`, `lint`, `types`, `check`, `migrate`, `worker`, `gen-types`), later acceptance criteria and agent instructions become unrunnable as written.
- If recipes fail hard when an app directory is missing, every task between T0.1 and T0.3 inherits a broken `just check` gate (the builder and ship phases call it).
- If pre-commit hooks run tool versions different from the ones pinned in the lockfiles, local formatting and CI results can disagree (section 18 risk: "Library changes mid-project / Behaviour drift / Lockfiles").

## 7. Edge cases

1. **Apps do not exist yet.** Right after T0.1, `apps/web/` and `services/api/` are absent. Example: a `lint` recipe that runs `cd services/api && uv run ruff check` fails with "No such file or directory", so `just check` (required by PR template and builder/ship agents) fails on the T0.1 PR itself and on T0.2's PR (api still missing).
2. **Partial scaffolding.** After T0.2 but before T0.3, only the web app exists. T0.2 acceptance "just test runs one passing web test" must pass while `services/api` is still missing.
3. **Worker does not exist until T2.5.** `worker.py` and `typist worker` arrive in M2, but the M0 done-when says "just dev runs web, API and worker".
4. **`just dev` on Linux.** In a cloud session the worker would eventually need the model; mlx is not installed there. Example: `uv sync` without the mlx extra, then worker startup imports `mlx_lm` → ImportError.
5. **`just --list` output format.** It prints recipes alphabetically by default with optional `# doc comment` text; private recipes (`_name` or `[private]`) are hidden. A recipe named e.g. `types` hidden as private, or aliased only, would not satisfy the criterion. Recipes with parameters display them (e.g. `test *args`), which still "shows" the name.
6. **`.gitignore` `data/` matches at any depth.** The pattern without a leading `/` ignores every directory named `data`, e.g. `apps/web/src/data/` or `services/api/tests/fixtures/data/`, silently.
7. **`*.db` matches at any depth.** A deliberately committed test database fixture (e.g. `services/api/tests/fixtures/sample.db`) would be ignored. The golden fixture is JSON so it is not affected.
8. **`dist/`, `coverage/` at any depth** likewise ignore any directory of those names anywhere.
9. **Empty `data/` directory.** Git cannot track an empty directory, and `data/` is ignored, so a fresh clone has no `data/`; anything writing `data/typist.db` must cope with it missing.
10. **Already-tracked files are not affected by `.gitignore`.** If anything under `data/` were ever committed before the ignore, it stays tracked. Currently nothing under `data/` is tracked (no such path in the inventory).
11. **pre-commit in a git worktree.** Hooks live in the common git dir (`/Users/allen/Downloads/typist-ml/.git/hooks`), shared by all worktrees. Installing in one worktree affects all of them; hooks that `cd apps/web` resolve relative to each worktree's root.
12. **pre-commit is per-clone.** `.pre-commit-config.yaml` does nothing until `pre-commit install` runs; cloud sessions (cloud-setup.sh) do not install pre-commit.
13. **pre-commit hooks for tools not yet installed.** Before T0.2/T0.3 there is no `apps/web/node_modules` (Biome) or `services/api/.venv` (ruff). A hook that invokes the project-local binary fails on the first commit after T0.1; a hook that uses pre-commit's own managed environment works but may use a different version than the lockfile.
14. **Hook file scoping.** Ruff should only see Python files and Biome only web files; e.g. committing only `README.md` or the PDF should not trigger failures. Biome also formats JSON — `services/api/tests/fixtures/golden_session.json` could be reformatted by a Biome hook if it is in scope (CLAUDE.md: never edit expected values; reformatting is not a value change but produces diffs in the source-of-truth file).
15. **Formatter hooks that modify files.** `ruff format` / `biome check --write` rewrite files and make the commit fail on first run; check-only mode does not rewrite. Behaviour is unspecified.
16. **just default recipe.** Running bare `just` runs the first recipe (or `default`). If the first recipe is `dev`, bare `just` starts long-running servers.
17. **`just dev` running three long-lived processes.** If one process crashes (e.g. worker model crash, which section 6.2 explicitly anticipates), the others may keep running or all may be killed depending on how they are combined; Ctrl-C must stop all three.
18. **Shell differences.** just's default shell is `sh`; macOS `sh` is bash-in-posix-mode (older bash 3.2 for `/bin/bash`), Linux `sh` is often dash. Bash-only syntax in recipes behaves differently.
19. **Branch name.** This worktree's branch is `claude/typist-ml-overview-3379c6`, not a task-named branch (CLAUDE.md requires a branch named after the task).

## 8. Risks

1. **Recipe-name drift.** Three sources name recipes differently (section 7: dev, test, lint, types, migrate, worker; section 14: gen-types; CLAUDE.md/PR template/agents: check). Missing any one leaves a later instruction unrunnable.
2. **Hard-failing recipes before scaffolding.** `just check` is a gate in the builder and ship phases; if it fails because apps are missing, T0.1 through T0.3 cannot pass their own gate.
3. **Required CI checks already exist without CI.** If `bootstrap-github.sh` ran, main requires status checks `web` and `api`, but there is no `.github/workflows/ci.yml` (T0.4). The T0.1 PR cannot merge until checks with those exact names report, which only happens after T0.4. CI job names chosen in T0.4 must match `web` and `api` exactly.
4. **Version skew between pre-commit and lockfiles.** Hooks pinned in `.pre-commit-config.yaml` (e.g. a ruff or Biome revision) versus the versions in `uv.lock` / `pnpm-lock.yaml` created in T0.2/T0.3 can format differently than CI.
5. **pre-commit installation path unspecified.** Not in the 20.3 install list or cloud-setup.sh; if it is not installed, the hook silently does not run.
6. **Privacy leak via `.gitignore` gaps.** Exports (`typist export --out file`, CSV or Parquet, section 14.1) written outside `data/`, or notebook outputs containing keystroke data in `notebooks/`, are not covered by the current ignore rules.
7. **Over-ignoring.** Unanchored `data/` and `*.db` could hide legitimate fixture files later (edge cases 6, 7).
8. **Scope creep into T0.2/T0.3/T0.4.** Making recipes actually work requires app scaffolding and CI, which belong to other tasks; mixing them violates "One task per PR".
9. **mlx on Linux.** A recipe that runs `uv sync --extra <mlx group>` or starts the worker unconditionally breaks cloud sessions and CI.

## Owner answers

Answered 2026-09-25. Numbering follows section 9 above.

1. **Recipe set:** include all of them now: `dev`, `test`, `lint`, `types`, `check`, `migrate`, `worker`, `gen-types`, even the ones that are just placeholders until later tasks fill them in. Better to have the name exist and say "not ready yet" than to add it piecemeal later.
2. **`check` semantics:** yes, `check` = lint + types + test for both apps, plus format-checking (not just linting). Record this as a new decision (D21) since the design doc never defines it.
3. **Behaviour before apps exist:** recipes for a missing app should skip cleanly: print something like `"apps/web not yet scaffolded, skipping"` and exit 0, not fail. `just check` must pass on T0.1's own PR with everything skipped.
4. **`dev` before the worker exists:** during M0/M1, `dev` starts whatever exists (web, API) and prints `"worker not yet implemented (M2)"` instead of failing. The M0 "done when" is satisfied by dev starting whatever currently exists; it doesn't require a real worker yet.
5. **`dev` on Linux/cloud:** `just dev` only needs to work on macOS. On Linux/cloud it should print a message that it requires macOS and exit. No fake-runtime worker startup needed, since nothing in `just check` or CI depends on dev running. Testing the worker logic with a fake runtime happens in pytest, separately.
6. **Full section-7 layout:** yes, create the empty top-level directories now (`apps/`, `services/`, `docs/decisions/`, `notebooks/`) with `.gitkeep` files so the structure is visible from commit one. Leave filling them in to their own tasks.
7. **pre-commit hook source:** local hooks that call the project's own pinned binaries via `uv run` / `pnpm exec`, not pre-commit's separately-managed hook versions. One source of truth for tool versions, matching the lockfiles.
8. **pre-commit scope:** ruff and Biome only, exactly as the design doc says. No pyright or tests in the commit hook (too slow for every commit); those stay in CI.
9. **Fix vs check:** hooks should auto-fix (`ruff format`, `biome check --write`) for convenience, except the one exclusion below.
10. **Golden fixture formatting:** yes, exclude `services/api/tests/fixtures/golden_session.json` from all formatting hooks. It's a source-of-truth file and should never be touched by a tool.
11. **pre-commit installation:** install it as a uv tool (`uv tool install pre-commit`), and add that line to `scripts/cloud-setup.sh` too. That's a small edit to an existing file, not a new task, so it's fine to do as part of T0.1.
12. **`.gitignore` additions:** anchor `data/` and `*.db` to the repo root (`/data/`, `/*.db`) so nested fixture folders elsewhere in the repo aren't accidentally ignored, and add `.python-version` plus common editor folders (`.vscode/`, `.idea/`).
13. **Generated API types:** gitignore `apps/web/src/api/schema.d.ts`. It's generated by `just gen-types` from the API's own OpenAPI schema, not something to hand-maintain or commit.
14. **"Create repository" / ruleset conflict:** the repo and remote already exist, so treat that part as done. 16. **Default recipe:** bare `just` lists recipes (same as `just --list`), not launch `dev`. A safer default so nothing starts by accident.
17. **Version recording:** record the installed versions of `just`, `pre-commit`, `uv`, `pnpm`, Node and Python in the README's setup section.
