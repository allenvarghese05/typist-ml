- **What was wrong.** In step 4, pyright strict (with sqlmodel 0.0.47) reported 12 errors:
  - `__tablename__ = "..."` gave 6× `reportAssignmentType`.
  - `assert Model.__tablename__ == "..."` in `test_table_names_follow_section_8_1` gave 6×
    `reportGeneralTypeIssues`.
- **Why.** `SQLModel` declares `__tablename__` twice:
  - first as a variable, `__tablename__: ClassVar[str | Callable[..., str]]` (main.py:846);
  - then as a method, `@declared_attr  # type: ignore` `def __tablename__(cls) -> str`
    (main.py:906).

  Pyright takes the last declaration, so the inherited declared type is `declared_attr[Unknown]`.
  Reading it on a class gives `InstrumentedAttribute[...]`, from `declared_attr.__get__(None, owner)`
  in sqlalchemy 2.0.54 `orm/decl_api.py:443`, and `==` on that is a `ColumnElement[bool]`.
- **Change 1: the table name is declared `__tablename__: ClassVar[Any] = "<name>"`** in all six
  table classes. There is no suppression comment. Checked against the pyright checker installed
  in `services/api/.venv` (`pyright/dist/dist/pyright-internal.js`, override validation):
  - An annotated override is checked by the override rule: `assignType(baseType, overrideType)`,
    invariant for a variable. `Any` passes against `declared_attr[Unknown]`.
  - Pyright also requires ClassVar-ness to match the base. The base symbol is ClassVar because of
    its `ClassVar[...]` annotation, so the override must be `ClassVar` too.
  - Runtime is unchanged. Pydantic treats a `ClassVar` annotation as a class attribute, not a
    field. SQLAlchemy reads `__tablename__` by name (a declarative dunder), so the value and the
    table names stay exactly the same, as before.
  - Rejected forms, all checked against the same sources:
    - `ClassVar[str]`, the form the coordinator suggested: `str` is not assignable to
      `declared_attr[Unknown]`, so pyright reports `reportIncompatibleVariableOverride`.
    - A bare `Any` (not ClassVar): an instance variable overriding a ClassVar, which is also
      `reportIncompatibleVariableOverride`.
    - `@declared_attr.directive def __tablename__`: `_declared_directive[str]` is not a
      `declared_attr`.
    - `@declared_attr def __tablename__(cls) -> str`: `declared_attr` only accepts functions that
      return `Mapped`/`ORMDescriptor`/`SQLCoreOperations` (`decl_api.py:107`).
    - `cast("declared_attr[str]", "...")`: this lies about the runtime type.
- **Change 2: the test reads the mapped table's name, which is a plain `str`.** It now checks
  `sqlalchemy.inspect(Model).tables[0].name`. **This deviates from the owner's literal wording
  (`Model.__table__.name`)**, because pyright cannot see `__table__` on a SQLModel class:
  - Neither `SQLModel` nor `DeclarativeMeta` declares it. Only `DeclarativeBase` does
    (`decl_api.py:793`), and SQLModel does not use it.
  - Pydantic's metaclass `__getattr__` sits in a `not TYPE_CHECKING` block
    (`_model_construction.py:282`).
  - `Model.__table__` would therefore be a `reportAttributeAccessIssue` error in `tests/`.

  `inspect(Model)` returns the class's `Mapper` (the metaclass is `Inspectable[Mapper[Any]]`).
  `Mapper.tables` is `Sequence[TableClause]` (`mapper.py:942`), whose `.name` is `str`
  (`selectable.py:1072`). For a single-table class, `tables[0]` is the same `Table` object as
  `__table__`. The owner confirms this deviation at review (Review focus 6).
- **Stop rule.** If pyright still reports anything on `__tablename__` or in
  `test_table_names_follow_section_8_1` after this revision, stop and report the diagnostics
  verbatim. Do not add a suppression comment and do not try another form.

## 2. Design

- **One hand-written revision, id `0001_initial_schema`** (owner answer 2). The builder types it
  from this plan. It is not autogenerated, because the id and the content must be exact.
  - It uses plain SQLAlchemy types (`sa.String`, `sa.Float`, `sa.Boolean`, `sa.DateTime`,
    `sa.JSON`, `sa.Integer`) and imports no app code, so later model edits cannot change what an
    old revision does. After Revision 3, the JSON columns are `sa.Text`.
  - It does not import `sqlmodel`. The template's `import sqlmodel` is dropped: it would be
    unused, and no post-write hook runs on a hand-written file.
  - Rejected: autogenerate. It gives a random id, renders `sqlmodel.sql.sqltypes.*` types, and
    still needs hand edits for the seed rows and the partial indexes.
- **Parity is proven, not assumed** (owner answer 1c).
  - `alembic.autogenerate.compare_metadata` must return `[]` against `SQLModel.metadata`, both
    after a plain upgrade and after a round trip.
  - Alembic does not compare CHECK constraints or partial-index `WHERE` clauses (verified in
    `ddl/impl.py`). Separate tests therefore compare (i) every constraint and index name,
    (ii) every CHECK text, and (iii) both `WHERE` clauses, on both the model side and in
    `sqlite_master`.
- **Naming convention** (owner answer 19). `typist/models/base.py` sets
  `SQLModel.metadata.naming_convention` (`ix`, `uq`, `ck`, `fk`, `pk`).
  `typist/models/__init__.py` imports `base` on its first import line, so the convention is set
  before any table class is defined. The package `__init__` always runs before any submodule, and
  isort sorts `from typist.models import base` ahead of `from typist.models.<x> import ...`.
  - CHECKs are given short names (`name="status"`), which the convention turns into
    `ck_<table>_status`.
  - The two partial unique indexes and the sessions index get explicit full names.
  - The revision writes every name out with `op.f()`.
- **Table classes** (owner answer 3):
  - The modules are `participants.py`, `experiment_config.py`, `text_passages.py`, `sessions.py`
    (holding `Session` and `SessionBlock`) and `keystroke_events.py`.
  - Classes have columns and foreign keys only: no `Relationship`, no `ondelete`, no cascades
    (owner answer 10).
  - The class `Session` shadows `sqlmodel.Session` by name. Code that needs both imports the model
    as `from typist.models import Session as TypingSession`, and the sessions module docstring
    says so.
  - Each class declares `__tablename__: ClassVar[Any] = "<name>"` (Revision 1).
- **Value sets** are Python tuples in each model module. `base.sql_in(column, values)` renders the
  CHECK text for them. The revision holds the same text as literals, and a test compares the two
  character by character.
- **Timestamps** (owner answer 14). The storage is what the owner accepted: naive UTC text in
  SQLite (`YYYY-MM-DD HH:MM:SS.ffffff`, space separator, no offset).
  - On the Python side, sqlmodel 0.0.47 maps every `datetime` field to `UTCDateTime`. That type
    rejects naive datetimes on write and returns aware UTC on read, which enforces "never a naive
    local `datetime.now()`" for free.
  - `typist.db.utc_now()` returns `datetime.now(UTC)`, and the `db.py` docstring documents the
    rule.
  - `participants.created_at` has `server_default=CURRENT_TIMESTAMP`, which is UTC with whole
    seconds.
  - SQLAlchemy skips `None` on INSERT, so the ORM leaves the column out and the database fills it.
- **Ids** (owner answer 13). `base.new_id()` returns `str(uuid.uuid4())`: 36 characters, stored as
  text. `keystroke_events.id` is `INTEGER PRIMARY KEY` (the SQLite rowid; no `AUTOINCREMENT`).
- **Seed rows** (owner answer 16, assumption B). The revision `bulk_insert`s exactly
  `practice_days=10`, `block_chars=600`, `d_min=0.15`, `d_max=0.40` and
  `arms_enabled=["control","heuristic","markov","llm"]`, all with `frozen_at` NULL. There is no
  `assignment_seed` and no `model_id`.
- **Downgrade** drops tables in child-to-parent order: `keystroke_events`, `session_blocks`,
  `sessions`, `text_passages`, `experiment_config`, `participants`. With `foreign_keys=ON`,
  `DROP TABLE` first deletes all of the table's rows, so dropping a parent before its children
  would fail on a populated database. Indexes go with their tables. No CLI command is added (owner
  answer 18).
- **The one allowed update** (owner answer 6) is `typist.services.keystrokes.record_key_up`.
  - It sets `t_up_ms`, and `dwell_ms = t_up_ms - t_down_ms`, on one row, and only while `t_up_ms`
    is NULL.
  - A second call raises `KeyUpAlreadyRecordedError`.
  - There are no triggers.
  - Rejected: a conditional `UPDATE ... WHERE t_up_ms IS NULL`. It is atomic, but it needs a
    typed `rowcount` path and adds nothing with SQLite's single writer.
- **Participant delete** (owner answer 10) is `typist.services.participants.delete_participant`.
  - It deletes in this order: the participant's keystrokes, blocks, sessions, their own
    `text_passages` (`participant_id` set), then the participant.
  - Shared passages are never touched.
  - It is one transaction, it returns per-table counts, and it has no CLI.
  - It uses `session.exec(delete(...))`, not the deprecated `Session.execute`.
- **Batch rebuild vs `foreign_keys=ON`** (owner answer 20a, assumption A). The tests run a probe
  revision through the real `env.py`, in a temporary copy of `alembic/`, and record the actual
  behaviour. `env.py` logic is not changed. Only its docstring records the finding.
  - The alembic 1.20.0 source has no PRAGMA handling. Its batch rebuild does `DROP TABLE` on the
    original, and SQLite runs an implicit `DELETE` for that, which fails when child rows reference
    the table.
  - The expected result is therefore: a rebuild of a leaf table, or of a parent table without
    child rows, works; a rebuild of a parent table with child rows fails with
    `FOREIGN KEY constraint failed`.
  - A separate test shows that `PRAGMA foreign_keys` cannot be changed inside a transaction.
  - Step 8 gives the text for both possible outcomes and a mechanical rule for which one to keep.
- **alembic.ini log format** (owner answer 20b). `logging.config.fileConfig` reads the formatter
  section raw, so the fix is a single `%`. An end-to-end test checks the printed lines.
- **Raw SQL in tests** uses complete string literals only: no f-strings and no `+` concatenation
  passed to `execute`. CI runs semgrep `p/security-audit` over `tests/` too.
- **Rejected alternatives:**
  - `create_all` in tests: section 5.2 rejects it, and it would hide drift between models and
    migration.
  - `ON DELETE CASCADE`: owner answer 10 rejects it.
  - Triggers for append-only: owner answer 6 rejects them.
  - A `typist db downgrade` command: owner answer 18 rejects it.
  - A custom `MetaData` subclass or base class: SQLModel's registry is shared, so setting the
    convention on `SQLModel.metadata` is the simplest correct place.

### Assumptions (stated by the main session; the owner did not answer them)

- **A. Answer 20a, FK checks during batch rebuilds.** The owner's premise is that
  `render_as_batch` already disables and re-enables FK checks. The alembic 1.20.0 source
  contradicts it: `alembic/` contains no `pragma` at all. On top of that, `PRAGMA foreign_keys` is
  a no-op inside a transaction.
  - Following "verify with a test rather than redesigning anything", this plan does not change
    `env.py` logic.
  - Step 8 writes deterministic tests that assert the observed behaviour. The finding is recorded
    in the test docstrings and the `env.py` docstring, and it is flagged for the reviewer's
    `IMPROVEMENTS.md` and the owner (Review focus 3).
  - If the observed behaviour differs from the prediction, step 8 says exactly which variant of
    the test and docstring to keep.
- **B.** `assignment_seed` is **not** seeded. Answer 16's list is exhaustive, and T2.2 owns the
  seed.
- **C.** The `created_at` round-trip tests accept both stored formats. One is `CURRENT_TIMESTAMP`'s
  whole-second `YYYY-MM-DD HH:MM:SS`; the other is a Python-written `YYYY-MM-DD HH:MM:SS.ffffff`.
  The regex is `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}(\.\d{6})?$`.
- **D. `.env.example`.** The sandbox shows `services/api/.env.example` as deleted (` D`). It is not
  deleted. The builder never stages it, and always uses `git add <explicit paths>`, never
  `git add -A` or `git add .`.

  """Shared pieces of the table modules: constraint naming, row ids and CHECK text (T1.1).

  Importing this module sets SQLModel.metadata's naming convention (T1.1 owner answer 19), so every
  constraint gets a stable name that later SQLite batch migrations can address.
  typist/models/__init__.py imports this module before any table module.
  """

  import uuid
  from collections.abc import Sequence
  from typing import Final

  from sqlmodel import SQLModel

  NAMING_CONVENTION: Final[dict[str, str]] = {
      "ix": "ix_%(column_0_label)s",
      "uq": "uq_%(table_name)s_%(column_0_N_name)s",
      "ck": "ck_%(table_name)s_%(constraint_name)s",
      "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
      "pk": "pk_%(table_name)s",
  }

  SQLModel.metadata.naming_convention = NAMING_CONVENTION


  def new_id() -> str:
      """Return a new row id: a 36-character hyphenated UUID4 string (T1.1 owner answer 13).

      Ids are opaque and must differ between runs, so they come from uuid.uuid4() (the OS random
      source), not from a seeded generator. CLAUDE.md's seeded-randomness rule covers randomness
      that affects results (assignment, sampling, drill generation); row ids never do.
      """
      return str(uuid.uuid4())


  def sql_in(column: str, values: Sequence[str]) -> str:
      """Return the CHECK text "<column> IN ('a', 'b', ...)" for a fixed set of allowed values.

      Values are literals from the model modules, never user input. A value containing a single
      quote raises ValueError.
      """
      if any("'" in value for value in values):
          raise ValueError("CHECK values must not contain a single quote")
      quoted = ", ".join(f"'{value}'" for value in values)
      return f"{column} IN ({quoted})"
  ```

  """The one write path that updates keystroke_events rows (T1.1 owner answer 6)."""

  from sqlmodel import Session, col, select

  from typist.models import KeystrokeEvent


  class KeystrokeEventNotFoundError(LookupError):
      """No keystroke_events row has the given (block_id, seq)."""


  class KeyUpAlreadyRecordedError(ValueError):
      """t_up_ms is already set; keystroke rows are append-only apart from one key-up fill."""


  def record_key_up(session: Session, block_id: str, seq: int, t_up_ms: float) -> KeystrokeEvent:
      """Fill in the key-up time of one stored keystroke, the only update keystroke_events allows.

      Sets t_up_ms and dwell_ms = t_up_ms - t_down_ms on the row (block_id, seq), commits, and
      returns the refreshed row. Nothing else changes: release_to_press_ms on later rows is never
      backfilled. A negative or long dwell is stored as is (section 12.6 checks flag it).
      Raises KeystrokeEventNotFoundError if no row matches, and KeyUpAlreadyRecordedError if
      t_up_ms is already set (the row is left unchanged).
      """
      event = session.exec(
          select(KeystrokeEvent).where(
              col(KeystrokeEvent.block_id) == block_id, col(KeystrokeEvent.seq) == seq
          )
      ).one_or_none()
      if event is None:
          raise KeystrokeEventNotFoundError(f"no keystroke event (block_id={block_id!r}, seq={seq})")
      if event.t_up_ms is not None:
          raise KeyUpAlreadyRecordedError(
              f"key-up already recorded (block_id={block_id!r}, seq={seq})"
          )
      event.t_up_ms = t_up_ms
      event.dwell_ms = t_up_ms - event.t_down_ms
      session.add(event)
      session.commit()
      session.refresh(event)
      return event
  ```

  """Explicit deletion of one participant's data (design doc 4.2; T1.1 owner answer 10)."""

  from dataclasses import dataclass

  from sqlmodel import Session, col, delete, select

  from typist.models import KeystrokeEvent, Participant, SessionBlock, TextPassage
  from typist.models import Session as TypingSession


  class ParticipantNotFoundError(LookupError):
      """No participants row has the given id."""


  @dataclass(frozen=True)
  class ParticipantDeletion:
      """Rows removed by delete_participant, per table."""

      keystroke_events: int
      session_blocks: int
      sessions: int
      text_passages: int
      participants: int


  def delete_participant(session: Session, participant_id: str) -> ParticipantDeletion:
      """Delete every row that belongs to one participant, children before parents, and commit.

      Order: keystroke_events of the participant's blocks, session_blocks, sessions, the
      participant's own text_passages (participant_id set; shared passages with a NULL
      participant_id are never touched), then the participants row. There is no ON DELETE
      CASCADE, so this is the only delete path. Raises ParticipantNotFoundError, deleting nothing,
      if the participant does not exist. Any database error rolls the whole delete back.
      """
      if session.get(Participant, participant_id) is None:
          raise ParticipantNotFoundError(participant_id)
      session_ids = list(
          session.exec(
              select(TypingSession.id).where(col(TypingSession.participant_id) == participant_id)
          ).all()
      )
      block_ids = list(
          session.exec(
              select(SessionBlock.id).where(col(SessionBlock.session_id).in_(session_ids))
          ).all()
      )
      try:
          events = session.exec(
              delete(KeystrokeEvent).where(col(KeystrokeEvent.block_id).in_(block_ids))
          ).rowcount
          blocks = session.exec(delete(SessionBlock).where(col(SessionBlock.id).in_(block_ids))).rowcount
          sessions = session.exec(
              delete(TypingSession).where(col(TypingSession.id).in_(session_ids))
          ).rowcount
          passages = session.exec(
              delete(TextPassage).where(col(TextPassage.participant_id) == participant_id)
          ).rowcount
          participants = session.exec(
              delete(Participant).where(col(Participant.id) == participant_id)
          ).rowcount
          session.commit()
      except Exception:
          session.rollback()
          raise
      return ParticipantDeletion(
          keystroke_events=events,
          session_blocks=blocks,
          sessions=sessions,
          text_passages=passages,
          participants=participants,
      )

  # D24: keystroke_events gets an after_pause column

  - Date: 2026-09-29
  - Status: accepted
  - Task: T1.1

  ## Context

  Section 12.2 defines a pause as "IKI over 2000 ms, or first key after a blur", and says pauses

  ```python
  """Shared pieces of the table modules: constraint naming, row ids, CHECK text and JSON (T1.1).

  Importing this module sets SQLModel.metadata's naming convention (T1.1 owner answer 19), so every
  constraint gets a stable name that later SQLite batch migrations can address.
  typist/models/__init__.py imports this module before any table module.
  """

  import json
  import uuid
  from collections.abc import Sequence
  from typing import Any, Final, override

  from sqlalchemy.engine import Dialect
  from sqlalchemy.types import Text, TypeDecorator
  from sqlmodel import SQLModel

  NAMING_CONVENTION: Final[dict[str, str]] = {
      "ix": "ix_%(column_0_label)s",
      "uq": "uq_%(table_name)s_%(column_0_N_name)s",
      "ck": "ck_%(table_name)s_%(constraint_name)s",
      "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
      "pk": "pk_%(table_name)s",
  }

  SQLModel.metadata.naming_convention = NAMING_CONVENTION


  class JSONText(TypeDecorator[Any]):
      """A JSON value stored as TEXT (T1.1 Revision 3).

      SQLAlchemy's JSON type declares the column JSON, which has NUMERIC affinity in SQLite, so JSON
      text such as "10" or "0.4" is stored as a number and then fails JSON decoding on read. This
      type declares TEXT, writes json.dumps(value) and reads json.loads(text). Python None is SQL
      NULL in both directions; a JSON null value cannot be stored.
      """

      impl = Text
      cache_ok = True

      @override
      def process_bind_param(self, value: Any, dialect: Dialect) -> str | None:
          """Encode a Python value as JSON text; None stays SQL NULL."""
          if value is None:
              return None
          return json.dumps(value)

      @override
      def process_result_value(self, value: Any, dialect: Dialect) -> Any:
          """Decode stored JSON text; SQL NULL becomes None."""
          if value is None:
              return None
          return json.loads(value)


  def new_id() -> str:
      """Return a new row id: a 36-character hyphenated UUID4 string (T1.1 owner answer 13).

      Ids are opaque and must differ between runs, so they come from uuid.uuid4() (the OS random
      source), not from a seeded generator. CLAUDE.md's seeded-randomness rule covers randomness
      that affects results (assignment, sampling, drill generation); row ids never do.
      """
      return str(uuid.uuid4())


  def sql_in(column: str, values: Sequence[str]) -> str:
      """Return the CHECK text "<column> IN ('a', 'b', ...)" for a fixed set of allowed values.

      Values are literals from the model modules, never user input. A value containing a single
      quote raises ValueError.
      """
      if any("'" in value for value in values):
          raise ValueError("CHECK values must not contain a single quote")
      quoted = ", ".join(f"'{value}'" for value in values)
      return f"{column} IN ({quoted})"
  ```
